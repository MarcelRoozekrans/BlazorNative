### Self-test run 1: the pipe has no name — stop condition, owner's call

Run 43461090948 on `scratch/530-selftest`, headSha `e94832ea2b8feb6b0d539dd843cee28211e7ab66`,
conclusion failure. `Handle.zip` SHA256
`279AAF8ECCB6F79147F4DCC6BA091FB895C4CB8B199A0DD186A4C76BC519D2CD`, Handle 5.0;
`handle64.exe` SHA256 `24BAFCC570CC9BBB6B6E6652A57A519E0464E3996891AABA6F55299CCE20B04F`.

- **The stall shape was planted and seen.** Parent `pwsh` 6888 ran the holder `pwsh` 7496 as a
  native command piped to `Out-Host`. 7496 started `PING.EXE` 3416 and exited at 16:19:12. The
  parent kept reading `ping`'s output until the job killed 3416.
- **Trigger A fired exactly once,** for 6888 at 16:19:41, 29 s after its child exited. `tree.csv`
  holds the chain `3416 PING.EXE <- 7496 pwsh.exe, dead <- 6888 pwsh.exe`, with command lines
  and start times: tracking across the dead parent works.
- **`holders.csv` was empty, and trigger B logged 3416 as a survivor, not a holder.** The
  redirect pipe has no name in `handle.exe`'s output. The parent's only named pipes were its
  own `dotnet-diagnostic-6888` and `PSHost.….6888.DefaultAppDomain.pwsh` servers. Its other
  pipe handles, and the sleeper's, print as a bare device, from `stall-1/handles.txt`:

identify a holder. This is the plan's stop condition for Task 1 Step 6: the definition of
"identified" goes back to the owner. The handle values match between the two processes because
inherited handles keep their values, which is not proof of a shared object.
