## 1. What the phase did

Every layout length in the public surface was `string?` or `float?`. So `Width="12px"` compiled,
shipped, and was **logged-and-ignored by both shells** at runtime — CSS muscle memory meeting a
grammar that has no units, with nothing in between to say so.

Two value types now carry that grammar, and it is implemented **once**:

| Type | Values | Properties |
|---|---|---|
| `BnLength` | points, percent | `MinWidth`, `MaxWidth`, `MinHeight`, `MaxHeight`, `Top`, `Right`, `Bottom`, `Left`, `Padding`, `Gap` |
| `BnAutoLength` | the above, plus `auto` | `Width`, `Height`, `Basis`, `Margin` |

`BnAutoLength` **composes** `BnLength` rather than duplicating it, so there is one formatter and one
place for the wire format to be right. `Padding` moved `float?` → `BnLength?`, closing the
milestone DoD's *"the `float?`/`string?` split is gone"*.

`BnModal.ContentWidth` / `ContentHeight` / `Padding` were typed too. They were **not in the plan** —
they surfaced during execution (§4).

## 2. The mechanism is an absence, and it was measured before it was designed

There is deliberately **no conversion from `string`**. Nothing inspects the text. Razor compiles a
non-`string` parameter's literal as a C# *expression*, so a malformed length is a syntax error
before it is anything else.

This was established by **compiling a throwaway probe during design**, not by reasoning — and the
probe corrected the design while it was at it:

| Markup | Result |
|---|---|
| `Width="200"` | ✅ `int` → `float` → `BnLength` → `BnLength?` |
| `Width="12.5"` | ✅ — **but only because an implicit `double` operator exists** |
| `Width="@BnLength.Percent(50)"` · `Height="@BnAutoLength.Auto"` | ✅ |
| `Width="12px"` | ❌ CS1003 |
| `Width="50%"` | ❌ CS1525 |
| `Width="auto"` · `Width="abc"` | ❌ CS0103 |
| `Width="100 px"` | ❌ CS1003 |

**The `double` operator is required, not a convenience.** Razor emits `12.5` as a `double` and
`double → float` is narrowing. Without it, every decimal literal in markup fails CS1503. Reasoning
would not have found that; compiling did.

Migration cost was likewise counted, not guessed: **44 numeric literals compile untouched**, 76
`@`-bound sites needed retyping, and exactly **one** literal percentage existed in the whole
repository.

## 3. The wire did not move

No `.kt`, no `.swift`, no `.mm`, no `src/wire-vocabulary.json`, and no frame-table file appears in
the branch diff. Both device lanes were dispatched against the branch and came back green on 2026-08-21:
`android-instrumented` [32422529858](https://github.com/MarcelRoozekrans/BlazorNative/actions/runs/32422529858)
and `ios` [32422532073](https://github.com/MarcelRoozekrans/BlazorNative/actions/runs/32422532073).

Stated precisely, because the distinction cost this phase a correction: what the **diff** proves is
that no shell or frame-table file changed. What the **device lanes** prove is that the shells still
render the sample correctly. Neither alone is "frame tables are byte-identical at runtime", and an
earlier draft of the ledger claimed exactly that. It was softened, unprompted, by the implementer
who noticed the overclaim — this repo's worst recorded bug class is a comment asserting a property
nothing enforces.

## 4. The two mechanisms that behave differently, and the trap in one of them

Phase 13.0 left three paths from a parameter to the wire. Typing them revealed that they are **not**
equally exposed, and the difference is not obvious from reading them:

| Mechanism | How | Exposure |
|---|---|---|
| **A** — `EmitItemAttributes` | `AddAttribute(seq, "width", …)` on an **element** | formats explicitly at the call site |
| **B** — `ItemAttributes` | `Dictionary<string, object?>` splatted onto an **element** | **the trap** |
| **C** — `ForwardItemParameters` | `AddComponentParameter(seq, nameof(Width), …)` on a **component** | exempt, and must stay exempt |

Mechanism B's values land on an element and are stringified by the renderer
(`NativeRenderer.cs`: `frame.AttributeValue?.ToString()` — **no format provider**). A boxed
`BnLength` there would go through culture-sensitive `ToString()`, so a machine with a comma decimal
separator would put `1,5` on the wire and both shells would reject it as *"not a number, a
percentage or `auto`"*. **Invisible on any English development machine.**

Every value entering that dictionary is formatted first, and
`ToStyleValue_IsInvariant_UnderACommaDecimalCulture` (nl-NL / de-DE / fr-FR) is mutation-proven.

Mechanism C is exempt for a reason worth writing down: it forwards a *component parameter*, so the
value stays typed all the way to the base that emits it and no culture is ever consulted. Adding
`.ToStyleValue()` there — the obvious "completion" of the refactor — would pass a `string` to a
`BnAutoLength?` parameter and break the binding. Both forward methods now carry a comment saying so.

## 5. Nullable everywhere, and the pin that was nearly vacuous

Parameters are `BnLength?` / `BnAutoLength?`, never bare. The reason is #178/#181 applied *before*
the fact instead of after:

- `default(BnLength)` is a real **zero-point length** — a never-assigned `Width` would collapse a node.
- `default(BnAutoLength)` reads as **`auto`**, because the inner null is how `auto` is encoded. On
  `Margin`, `auto` absorbs free space and **re-centres the node**.

Both are a struct's zero-value silently meaning something the author never chose.

**The first attempt to pin this did not pin it.** A test asserting `default(BnAutoLength?) is null`
is a C# language axiom and cannot fail; the actual invariant — *every length parameter is declared
nullable* — was guarded by nothing, and changing a parameter to a bare `BnAutoLength` would have
left the suite green. The final whole-branch review caught it.
`EveryLengthParameter_IsDeclaredNullable` now sweeps the assembly by reflection (18 parameters
across four declaring types) and is mutation-proven: a bare `BnLength` on `MinWidth` reds it by
name.

`DefaultStructTrapSweepTests` also gained `BlazorNative.Components` — the standing #178 guard swept
three assemblies and **not** the one this phase added two public structs to.

## 6. Standing pins added or repaired

| Pin | What it refuses |
|---|---|
| `ToStyleValue_IsInvariant_UnderACommaDecimalCulture` | A non-invariant format reaching the wire (3 cultures) |
| `NoConversionFromString_Exists` | A `string` conversion on either type — the single member that would revert the whole phase |
| `EveryLengthParameter_IsDeclaredNullable` | A bare (non-nullable) length parameter |
| `DefaultStructTrapSweepTests` (+1 assembly) | The #178 trap in `BlazorNative.Components` |
| `BnListSurfaceTests` | `BnList.Width` untyped, or `Height`/`ItemHeight` retyped away from `float` |
| `LayoutSurfaceSequenceBandTests.SampleValue` (**repaired**) | See §7 — it had stopped covering the new types |

.NET test count **1032 → 1051**. JVM (161), Android (224) and iOS (269) are untouched — no Kotlin
and no Swift changed.

## 7. What the process caught that the plan did not

Recorded because the plan was wrong in ways worth remembering, not to pad the record.

- **A pin that would have passed while checking nothing.** `LayoutSurfaceSequenceBandTests`
  supplies a sample value per parameter type. It had no arm for the two new types, so 12 of 22
  parameters would have been left unset — and an unset element attribute is never appended to the
  frame array. The band pin would have **silently stopped checking over half the surface while
  reporting PASS.** Caught one task before it mattered.
- **A boxed `float` is a landmine, not just a boxed `string`.** `[nameof(BnView.Padding)] = 16f` in
  a `ParameterView` dictionary compiles and throws `InvalidCastException` at first render, because
  the implicit operators are compile-time only. Nine files were affected. One carried a comment
  reading `// typed (7.1)` asserting it was fine.
- **Two files no build could see.** `samples/ConsumerSmoke/SmokeRoot.cs` is not a solution member;
  its break would have surfaced inside `consumer-smoke.ps1` — the release pipeline's own `validate`
  job, and the exact gate that made `v0.9.0` an orphan tag.
- **`<inheritdoc cref>` does not red when its target's type changes.** `BnModal.Padding` documented
  `BnLength?` while being `float?` for several commits, silently.
- **The plan asserted test runs at points where the projects could not compile.** `Runtime.Tests`
  has a `ProjectReference` to `SampleApp`, so no test could run until the samples migrated. Found
  in a pre-flight scan before any task ran.

## 8. What 13.1 deliberately did not do

- **Type the negative-legality axis.** `Width="-8"` still compiles and is still rejected by the
  shells. Negative-legality is per-property — legal on `margin` and the insets, illegal elsewhere —
  and encoding it would have doubled a public type surface that freezes at 1.0. `NaN` and
  infinities are the same class. Documented in the migration note §7.
- **Ship a friendly diagnostic.** The compile errors are correct but cryptic: `12px` reports
  *"syntax error, ',' expected"*. An analyzer could improve the message; the migration note carries
  the CS-code → cause table instead.
- **Add an executable compile-failure test.** The milestone DoD asked for one *"not by a comment
  claiming they do"*. What shipped is `NoConversionFromString_Exists`, a mutation-proven reflection
  guard on the mechanism. **This is a substitution and is recorded as one rather than ticked
  silently:** a Roslyn test in `Analyzers.Tests` would compile C#, not Razor markup, so it would not
  actually test `Width="12px"` — it would restate the reflection pin more expensively. The compile
  behaviour itself was demonstrated by probe at design time (§2).
- **Retype `BnList.Height`/`ItemHeight`.** They are `BnListWindow.Compute`'s divisor and must be
  point values. `BnList` stays allowlisted, with its reason rewritten from *deferred to 13.1* to
  **settled**.
- **Touch the shells.** No `.kt`, `.swift`, `.mm`, or `wire-vocabulary.json`.

## 9. Consumer impact

Source-breaking, not binary-relevant in practice: the parameter *types* change, so a consumer
recompiles and adjusts any `string`-typed variable bound to a length. Plain numeric literals — the
overwhelming majority of real markup — need no edit at all.

The one trap worth repeating from the migration note: a layout value boxed into a
`ParameterView`/`Dictionary<string, object?>` as a `string` **or** as a bare `float` compiles and
then throws at first render. Box the constructed type: `["Width"] = (BnAutoLength)200f`.
