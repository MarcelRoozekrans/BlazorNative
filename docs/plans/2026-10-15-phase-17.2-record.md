## 2. Red before the fix

`android-instrumented.yml` run 38682991221, on `7da39429`, the seams and the five pins with no
product change, at attempt 1. 238 tests, 4 failed. Read with an XML parser from the
`instrumented-test-results` artifact.

| pin | result on unchanged code | message |
|---|---|---|
| `biometrics_begin_returns_before_the_check_runs` | **red** | `hostCallBegin did not return while the work was gated: the work runs inside the begin, on the caller's thread. That is #440.` |
| `secure_storage_begin_returns_before_the_keystore_work_runs` | **red** | the same message |
| `secure_storage_keeps_request_order` | green, as expected | order is today's behaviour, since the work ran inline |
| `a_throw_on_the_executor_completes_error_never_a_hang` | **red** | `java.lang.IllegalStateException: job-fault`, thrown out of `hostCallBegin` into its caller. Inline work has no guard, so a throw escapes the begin instead of becoming an `ERROR` completion |
| `the_after_auth_work_runs_on_the_secure_storage_executor` | red, **but contaminated** | `… ran on contract-test-caller …`. No pin-5 code runs on that thread. A gated job from an earlier pin, run on its caller thread, completed after its test ended, into pin 5's hook, under the same request id: every test instance restarted ids at `1_000_000_000` |

**The contamination, fixed.** Request ids now come from one process-wide counter, and each test's
cleanup joins its caller threads before it resets the hooks. Pin 5's honest red is mutation M5 in
§3. That mutation removes the after-auth hop on the fixed tree, which is exactly the path
unchanged code took.
