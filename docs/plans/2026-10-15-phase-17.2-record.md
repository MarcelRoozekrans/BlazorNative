## 4. Verification and the final review

A fresh reviewer on the whole branch found no Critical issue, one Important and two Minor. All
three were fixed, per the owner's rule that review findings are fixed in the loop.

- **Important: the auth-bound set's after-auth hop had no pin.** M5 removed only the
  `getWithAuth` hop. The set cannot reach its prompt on the CI emulator, because provisioning its
  key needs an enrolled biometric. Both paths now go through one helper, `afterAuth`, so pin 5
  covers the hop they share.
  - **M6**, the executor hop removed from `afterAuth`: run 38686482863, on `1fbf0ba2`, at
    attempt 1. It reds `the_after_auth_work_runs_on_the_secure_storage_executor` alone, with
    `… ran on main …`, 1 of 238.
- **Minor: the ordering comment overclaimed.** An auth-bound request frees its executor while its
  prompt is up, so later requests on the same key run before its encrypt step. That predates
  17.2. The comment and the spec now say requests **start** in order. The serialise-on-prompt
  question is filed as #506.
- **Minor:** the new seams are `internal` and `@VisibleForTesting`.

`TemplateDriftTests`, `AuthSemantics` and `GeneratedSymbolShadowTests` pass, 32/0: the template
copy is byte-identical. `compileDebugAndroidTestKotlin` passes locally.
