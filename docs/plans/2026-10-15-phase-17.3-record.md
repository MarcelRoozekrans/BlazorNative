## 3. Mutations

**The .NET fix.**
- `HostSession.TryMount`: a mount replaces any root as one render-thread unit, through the
  `InvokeAsync` and `RunAfterDispatch` shape of the navigation swap. A mount of the default
  component re-resolves it from the current route. Every shell mount bumps
  `NativeRenderer.RootGeneration`.
- Each dispatch scope records the generation it began under. `NativeNavigationManager` drops
  `NavigateToAsync` and `NavigateBackAsync` called from a replaced root's code, and logs a Warn.

The 4 facts are green.

**A fifth fact, from executing the plan.** The planning review warned that every later `start()`
would deliver the old root's removal frame to the new runtime. Those patches describe the **old**
shell's views, which are gone, and 15 JVM test files read `frames.first()` as the mount frame. The
cause is fixed, not the tests: a replacing mount disposes the old root through
`NativeRenderer.UnmountReplacedRoot`, which updates the renderer's tree but delivers no frame for
that batch. A navigation swap keeps its removal frame, because there the shell is the same one.
- `AReplacingMount_SendsTheNewShellNoRemovalFrameForTheOldRoot` was red first:
  `… frames after it: [RemoveNodePatch,CommitFramePatch | CreateNodePatch,…]`.
- **M5**, the drop disabled, reds it alone.
- No shell checks that frame ids are consecutive: `grep` over the Kotlin and Swift frame
  consumers.
