## 3. Mutation reds

Base for every red: the PR head `1fe09fc6`, which holds all of this phase's code and tests. One scratch
ref per commit, `scratch/18.7-<id>`, cut from that head with `git status` clean first. Each ref is
pushed, its lane runs are dispatched, and it is deleted, local and remote, once its runs are read; the
draft PRs the JVM refs needed, #692 to #696, are closed. The feature branch was never mutated. Each
`ci.yml` ref also carries `continue-on-error: true` on the `.NET tests` step, the only change to
`ci.yml`, so that a .NET fact reding under the mutation cannot stop the job before the JVM step; the
Kotlin mutations were made in the repo copy and the template mirror alike. The scratch PRs were based
on the feature branch, not on `main`, so `ios.yml` and `android-instrumented.yml` did not start
unasked. Every message is quoted from the run's own log or JUnit XML; every run is attempt 1 with
`headSha` equal to the mutation commit.

two that one lane judges. `18.7-r1r2` carries R1 for the iOS lane and R2 for the JVM lane, `r3`, `r4`,
