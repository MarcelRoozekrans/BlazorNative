### Method

- **Population.** For each of the ten squashes, every test file in `git show --stat` was diffed. For each XCTest method, `@Test` and `[Fact]`/`[Theory]`, the body at `<squash>^` was compared with the body at `<squash>`, comments and whitespace stripped. A test is in the population when the squash added it, or changed an assertion in it: its condition, its message, or the helper assertion it calls. A moved line, a changed comment, or a changed setup line alone does not count.
- **Sites.** `docs/pin-standard.md`, "Grading a pin: sites and reds", part 1, and nothing broader (#562): every assertion the test's own comment or message calls an anchor, every line a multi-line label names, and every assertion that carries a clause of the test's name. A helper's assertion is a site once per calling pin. Lines are HEAD's, re-read in the file; where a record cites an older line, the cited-red column gives it as "then".
- **Pre-M18 tests.** Only the sites the M18 change added or altered are graded, per the design's "Calls made for the builder". The rest stay under their pre-M18 cell.
- **A red's commit** is the tree the mutation was applied to, as [the 17.11 record](2026-10-22-phase-17.11-record.md) §4 defines it: the named commit for a local run, and the parent of the scratch commit for a lane, JVM or JNA run. A scratch commit's `headSha` differs from that parent by the mutation itself, so a diff from it is never empty; every record in M18 names the parent as its base. The parent was checked where the scratch commit still resolves: `a6bb9eb3`, `3b4816fc`, `28f4567f`, `4398cd0a`, `13e9c322`, `6e91f64a`, `2e9d6506`, `f63fcbed`, `14f9c82b`, `6af31742` and `d7194a48` each have the base the record names, and 18.6's R3, two scratch commits `9c64fbc1` and `52c166f3`, sits on `87b48f3c`. Every base commit cited below resolves.
- **The subject files** are the product file the red's mutation edited, plus the file or files the pin is named for in its register row, plus the template mirror of each Kotlin shell file. The second term is the conservative reading of the brief's "the file the pin is named for / the product file whose mutation the red used": it makes three rows stale that the mutated file alone would leave fresh. They are under "Disagreements".
- **Staleness.** `git diff --stat <red commit> HEAD -- <test file> <subject files>`, run for every row. Empty is fresh, any output is stale, and a site with no red, or a red with no commit, is `unresolvable`. Where a site has several reds, the row cites the most recent one with a recorded commit, and names the others.
- **Script.** The diffs were run by a script under the session scratchpad that reads the row list and prints each command's output; the outputs are pasted below as it printed them.
