## 2. The red before the fix

Run on the Task 1 commit plus only the Task 2 test edits in `FaultNoticeTests.cs`: the
`InlineContinuationProbe`, the `DispatchTwo` helper and five facts. No product code had changed.

Command: `dotnet test tests/BlazorNative.Runtime.Tests -c Debug --filter "FullyQualifiedName~FaultNoticeTests.AnInlineContinuation|FullyQualifiedName~FaultNoticeTests.ACallBegunByAnInline|FullyQualifiedName~FaultNoticeTests.AFaultWithNoDispatchFlow|FullyQualifiedName~FaultNoticeTests.AFinishedDispatch"`.

| fact | result on unchanged code | message |
|---|---|---|
| `AnInlineContinuationsFault_IsItsOwnDispatchs_NotTheWindows` | **red** at the rc | `rc was 2: B's own synchronous part did not fault. A's fault was charged to B's window, which is #464.` |
| `AnInlineContinuationsFault_LeavesTheWindowsOwnFault_Rc2` | **red** at the notice | `no FaultNotice for A's fault.` B's rc 2 passes today, because B returns A's fault as its own; the red is that A's fault never reaches A |
| `ACallBegunByAnInlineContinuation_DoesNotMarkTheWindow` | **red** at the rc | `rc was 0: the call A's continuation began marked B, so B's own synchronous fault became rc 0.` The geolocation-begin anchor passed |
| `AFaultWithNoDispatchFlow_InsideAWindow_IsTheWindows` | green, as expected | the null-flow rule is today's behaviour |
| `AFinishedDispatchsFault_InsideAWindow_IsNotTheWindows` | **red** at the rc | `rc was 2: A's code raised the fault after A finished. It is A's, ... never charged to B's window.` |

In every red the `RanInsideB` anchor passed, so A's continuation really ran inside B's window.

**The no-flow scenario, corrected before the run above.** The first version registered its
continuation under `ExecutionContext.SuppressFlow()`. It failed at its own anchor: a continuation
that captured no context runs inline in the context that completes it, which is B's. So it flowed
B's scope, not none. The fact now runs its continuation in the execution context captured at the
probe's mount, when no dispatch was open. The anchor reads the renderer's own
`FlowingScopeIsSetForTests`.
