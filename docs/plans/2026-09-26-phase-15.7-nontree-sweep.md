**Returned 93 files. All 93 were read in full**, fact by fact. The classification is per FACT (Rule 6).

### How facts were classified

- **Pin.** The expected side is a hand-kept list, table, count or constant (or a second
  implementation) that duplicates a truth whose authoritative copy lives somewhere else, such as a
  product declaration, another assembly or a generated table. The fact compares the two and reds on
  divergence. Population sweeps count too, where a rule is held against a reflected population
  (the "Sweep" class Rule 1 names, e.g. `DefaultStructTrapSweepTests`). Anchor and control facts that
  exist to hold a pin's input or suppression list in place are counted as pin facts, as the
  standard's 111 count does.
- **Not a pin.** Behaviour tests (call X, expect Y). Also goldens whose expected value *is* the
  definition of correct output, even when a device suite transcribes the same numbers.
- **Rule 3 reading used.** An **exact-equality** comparison of two non-empty collections exercises its
  own detector on every run, so it conforms structurally. An **absence** detector
  (`offenders`/`missing` must be empty) needs a fixed point or fixture. This follows the standard:
  all nine 15.1 controls were for absence assertions.
- **Rule 7.** Recorded only where a cheap grep of `docs/` found a mutation table. Otherwise the
  entry says "unknown".

## Addendum, found by the 15.8 re-audit review, not by this sweep

sweep classed its file as not one.** The one-line entry above reads *"`DeclaresNoOwnParameters…`
uses `ItemParameters` as input only (structural)"*. But the fact loops `ItemParameters` and asserts

that the type declares no `[Parameter]` of its own. The 15.8 re-audit review found it; this sweep
and the first draft of the 15.8 re-audit both missed it.

It now has its own row in the register in `docs/pin-standard.md`, with all five rule cells. That
makes **16 files holding pins and 41 pin facts**, where this record says 15 and 40. The counts above
are left as the sweep measured them.
