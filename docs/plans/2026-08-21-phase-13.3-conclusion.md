## 3. A correction the phase made to the issue it was implementing

**#286 lists Cloud Storage under "works today via REST". That is only half true**, and publishing it
unqualified would have been exactly the kind of claim this phase exists to remove.

The bridge exposes bodies as **UTF-8 text in both directions** — binary payloads are unsupported
(`BridgeHttpHandler`, `IMobileBridge.BridgeHttpResponse`). So Storage's JSON control plane
(metadata, signed URLs, delete) works, and **moving the object bytes does not**. The page splits the
row and says why, and points at the camera's return-a-path pattern as the workable route.

Checked rather than assumed, because "does Firebase work" is precisely the question a reader will
act on.

## 4. A flaky test of my own making, and the two wrong fixes before the right one

`RenderThreadWarningTests` (added in 13.2) failed intermittently in **solution** runs while passing
alone. Three attempts:

1. **Forward the sink and add a `[Collection]`** — necessary, but a collection only serialises
   classes *within* it, and this class was alone in one. Did not fix it.
2. **Filter captured reports by owner thread id** — sound reasoning, wrong premise: **pooled test
   threads reuse ids**, so a concurrent class's renderer can legitimately share an owner id. Still
   flaked, 2 runs in 3.
3. **Serialise the assembly** (`xunit.runner.json`, `parallelizeTestCollections: false`). Green
   5 runs of 5. `Renderer.Tests` completes in ~0.7 s, so this costs nothing measurable and removes
   the entire interference class rather than narrowing it.

Recorded because the first two are the attractive fixes and both are wrong, and because the general
lesson is worth more than the specific one: **a global capture cannot be made safe by filtering when
the discriminator is itself recycled.**
