# Phase 18.13 — Re-audit and close Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-audit all 13 M18 DoD items on HEAD after 18.12. Item 3 is graded against the text as amended by the owner on 2026-11-16. If the verdict is a pass, M18 is ready for `complete-milestone`.

**Architecture:** The work comes in three parts:
- the owner's amendment to item 3 and the phase bookkeeping;
- a freshness re-check of 18.11's 339 graded sites, with re-reds only where a site went stale, plus an independent sample;
- the re-audit report, graded on the PR's own lanes.

There is no change to product or test code.

**Tech Stack:** the work uses:
- C#/xUnit on net10.0 and net11.0;
- Kotlin JUnit/JNA;
- Android instrumented tests;
- XCTest on the iOS simulator;
- GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-16-phase-18.13-design.md`

## Global Constraints

- **Grading rule.**
  - Use `docs/pin-standard.md`, the section "Grading a pin: sites and reds". Nothing broader is graded; that is #562.
  - Item 3 is graded against the amended text, and its best possible grade is **MET NARROWLY**.
- **Item 3 amendment, verbatim.** It is added as a sub-bullet under the first bullet:
  > *Owner decision 2026-11-16:* a flake whose cause stays unproven after a phase spent hunting it (#407: 18.12, with #718 left open for a recurrence) meets this bullet with a fix that makes the failure name itself, plus a lane capture that would record the cause if it recurs. A residual the owner accepted after measuring it (#580, 18.12) counts as decided.
- **Population.** The 108 pins and 339 sites in `docs/plans/2026-11-14-phase-18.11-record.md` §2, "The table". 18.12 added no pin; its record §8 says so.
- **Staleness.**
  - The check is `git diff --stat <red-commit> HEAD -- <test-file> <subject-file>`, with the red commit taken from the 18.11 record for each site. Any output means stale.
  - A red whose commit cannot be resolved counts as stale.
  - Never diff a directory.
- **Known non-doc changes since 18.11.** At design time, `git diff --stat 09332c5e origin/main -- ':!docs' ':!*.md'` showed 15 files:
  - the workflows;
  - `scripts/android-emulator-settle.sh` and `scripts/android-gradle-captured.sh`;
  - `src/BlazorNative.Runtime/Exports.cs`, where only `VersionNumber` changed from `0.22.0` to `0.22.1`;
  - the props files, the template files and the release-please files.

  Any site whose test or subject is one of these files is stale under the rule and gets re-run.
- **Record.** `docs/plans/2026-11-16-phase-18.13-record.md` holds the freshness table, every re-red row and the lanes. Every red row gives the following, in the 18.11 record's red-row format:
  - pin, site `file:line`, and the label or name clause;
  - the exact mutation diff;
  - the commit;
  - the command, or the run id with its `headSha` and attempt;
  - the quoted failure message at the site's own line.
- **Report.** `docs/plans/2026-11-16-milestone-18-reaudit.md`, in the 18.11 audit's shape. Each item's scorecard row is set against its 18.11 grade.
- **Mutations.**
  - Run them only in a detached worktree. `git status --short` must be empty before and after.
  - Commit, then mutate; never mutate on a dirty tree.
  - Copy the mutation text from HEAD, not from an old record.
- **Device runs.**
  - Use the ref `scratch/18.13-<lane>-<n>`, dispatched with `gh workflow run <file> --ref <branch>`.
  - One run per ref at a time. Wait with `gh run watch --exit-status` in the foreground, and never background a loop with `&`.
  - Delete each scratch ref after the record cites it, then verify it is gone.
- **Linux host.**
  - The .NET suite needs `pwsh` as a dotnet tool.
  - Swift and the instrumented suite cannot run here.
  - JVM pins need a draft PR, because JNA cannot load the win-x64 dll (#491).
- **Process hygiene.** Kill processes by PID only. Never use `pkill -f`.
- **Branch.** Work on `docs/18.13-reaudit`, pushed with `git push -u origin docs/18.13-reaudit`.
- **Commits:**
  - prefix `docs(18.13):`;
  - no nested parentheses in the body;
  - no closing keywords;
  - no Claude signature, no `Co-Authored-By: Claude` trailer, no session URL.
- **Plan boxes.** Each implementer ticks only its own task's boxes, line by line. Never run `sed` over the plan.
- **Baselines.** .NET 2828 (1414 facts on two TFMs), JVM 210, Android 273, iOS 307.

## Review Focus

- **A site called fresh because its directory diff was empty.** For example, a pin whose subject is `Exports.cs`, a workflow or `android-emulator-settle.sh`. Covered by Task 2 Step 3.
- **#580 graded as fixed.** The issue reads `CLOSED COMPLETED`, but 18.12 accepted it and did not fix it. The report must say "accepted" and keep #453 narrowed. Covered by Task 5 Step 2.
- **The capture taken as working when its artifact is missing or empty on the graded `android-instrumented` run.** Covered by Task 4 Step 3.
- **A lane graded on a re-run attempt, or on a run whose `headSha` is not the PR head.** Covered by Task 4 Step 2.
- **The amendment changes more than its own sub-bullet.** That covers item 3's other bullets, 18.11's NOT MET history, or another item. Covered by Task 1 Step 3.
