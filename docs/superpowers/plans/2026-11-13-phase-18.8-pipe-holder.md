# Phase 18.8 The generator's pipe holder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Tick each box in this file as you finish its step, and commit the ticks with the step's work. Tick only your own task's boxes, line by line; never a broad `sed` over the file** (the 18.6 lesson). The complete-phase gate fails on unticked boxes.

**Goal:** Name the process that holds the reference generator's output pipe on Windows, fix it at its source, and close #530 on that evidence, or bring a silent result to the owner.

**Architecture:**
- A scratch-only harness runs on `windows-latest`, triggered by a push to `scratch/530-**`. It is never merged.
  - A watcher (`watch-holder.ps1`) polls the process tree beside each `dotnet test` iteration. When a generator `pwsh` stalls, it records the tree, every handle from Sysinternals `handle.exe`, the processes that share the stalled pipe, and their environments.
  - A self-test plants a known holder first and proves the watcher names it by pipe name.
  - A loop (`loop-530.ps1`) runs `ci.yml`'s .NET test invocation 20 times per arm: 10 warm, 10 cold.
- Two arms, two refs: **fixed** is the merged tree; **stripped** is the same plus one commit that removes 17.5's node-reuse fix.
- What the watcher names decides the fix (design D3, D4). The plan's Task 4 branches on it. Anything outside D4's three sketches goes to the owner before it is planned.

**Tech Stack:** PowerShell 7 on the `windows-latest` runner, GitHub Actions, Sysinternals `handle.exe`, `Get-CimInstance Win32_Process`, xUnit (`tests/BlazorNative.Runtime.Tests`), `gh` on the local host for runs and artifacts.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-18.8-design.md`. Read it in full before your task. Its D1–D5 are the rules this plan implements. The owner approved it on 2026-11-11.

- **No silent close.** If neither arm stalls, Task 3 stops and the owner rules (D3 last row). No phase PR is opened before that ruling.

## Review Focus

1. **The script exits but its pipe stays held** (`RunBounded`'s "exited" message). Then there is no stalled `pwsh` left to watch, and a watcher keyed only on a living `pwsh` stays silent through a real stall. Task 1's trigger B covers it: a descendant that outlives its generator `pwsh` by 30 s and shares a pipe with the testhost.
2. **A pipe-name match that never matches,** because the redirect pipe is anonymous or `handle.exe` prints no name for it. The watcher would then report survivors, not holders. Task 1's self-test fails on exactly that, and the experiment does not start until it passes.
3. **A warm iteration that is really cold,** because the previous iteration's stall reset shut the build servers down. Task 2 logs each iteration's actual mode, warm or cold, from the reset it did or did not run, so the record never credits a stall to the wrong mode.
4. **A stall that the loop's own instrumentation caused,** for example `handle.exe` holding a handle, or the watcher's `pwsh` inheriting the test step's pipe. The watcher starts with `Start-Process -NoNewWindow` and redirects its output to files, so it inherits no pipe of the test, and `handle.exe` runs only after a trigger fires. The fixed arm's clean result is also the control for this.
5. **A green test step that hid a stall,** because the generator's output is captured by the fixture. The loop reads the stall from the watcher and from the bound's messages in the test log, never from the exit code alone.

### Task 1: The watcher and its planted-holder self-test

**Model:** opus. Windows handle semantics and process trees, debugged through CI only.

**Files (on `scratch/530-selftest` only):**
- Create: `scripts/scratch-530/watch-holder.ps1`.
- Create: `scripts/scratch-530/plant-holder.ps1`.
- Create: `.github/workflows/scratch-530.yml`, job `selftest` only.
- Create on `feat/18.8-pipe-holder`: `docs/plans/2026-11-13-phase-18.8-record.md`, with §0 "Harness", §1 "Experiment", §2 "Holder", §3 "Reds", §4 "Site map", §5 "Stale reds".

**Interfaces:**
- Produces: `watch-holder.ps1 -OutDir <dir> -HandleExe <path> [-StallSeconds 30] [-PollSeconds 2] [-RootPid <pid>] [-ScriptPattern 'generate-reference\.ps1']`. It runs until its stop file `<OutDir>/stop` exists. `-RootPid` limits the watch to descendants of that process; the loop passes the `dotnet test` PID, the self-test passes its planted parent. Each firing writes `<OutDir>/stall-<n>/` holding `trigger.txt` (A or B, the watched PID, the time), `tree.csv` (PID, parent PID, start time, command line), `handles.txt` (raw `handle.exe -a -nobanner`), `holders.csv` (pipe name, holder PID, holder command line, holder parent PID) and `env-<pid>.txt` per holder. It appends one line per firing to `<OutDir>/stalls.csv`.
- Produces: `plant-holder.ps1 -Mode Parent|Holder`. The parent `pwsh` starts a native child, holds its output pipe, and that child starts an inheriting sleeper (`cmd /c "ping -n 600 127.0.0.1"` or similar) and exits, so the parent's read never sees end of file. The script's command line contains `plant-holder.ps1`, which the self-test passes as `-ScriptPattern`.

- [x] **Step 1: Create the record** with the six headings and §0 listing the harness files, the scratch refs and the `handle.exe` source. Commit on `feat/18.8-pipe-holder` as `docs(18.8): start the phase record`.
- [ ] **Step 2: Write `watch-holder.ps1`.** Two triggers, polled every `-PollSeconds`:
  - **A:** a `pwsh` under `-RootPid` whose command line matches `-ScriptPattern`, still running, that has had no living child process for `-StallSeconds`. The generator's slowest step took 3.1 s in 17.5, so 30 s is far past any pause between its native commands.
  - **B:** a process first seen as a descendant of such a `pwsh`, still alive `-StallSeconds` after that `pwsh` exited. On B the watcher runs one `handle.exe` scan and fires only if the survivor holds a pipe that the `pwsh`'s parent (the testhost) also holds. A survivor that shares no pipe is logged to `survivors.csv` and is not a firing; reused MSBuild nodes on the stripped arm are expected there.
  - On a firing: take the tree from `Get-CimInstance Win32_Process`, run `handle.exe -a -nobanner -accepteula` once, parse the `File` handles whose name starts with `\Device\NamedPipe\`, and for the watched `pwsh` (A) or the testhost (B) list every other PID that holds one of the same pipe names. Those are the holders. .NET cannot read another process's environment (`Process.StartInfo.Environment` is the caller's own), so read each holder's from its PEB: an `Add-Type` P/Invoke of `NtQueryInformationProcess` (`ProcessBasicInformation`) and `ReadProcessMemory`, following `PebBaseAddress` → `ProcessParameters` → `Environment`, 64-bit only. If a read fails, write `environment unreadable: <Win32 error>` instead; a failed read never stops the firing. The `MSBUILDDISABLENODEREUSE` value is the one that matters.
  - The watcher only observes. It never kills or signals a process, so the bound still fires and the run shows its message is still right.
  - The watcher writes nothing to stdout; it starts under `Start-Process -NoNewWindow -RedirectStandardOutput/-RedirectStandardError` to files, so it inherits no pipe of the step it watches.
  - Each watched `pwsh` fires at most once per trigger.

- [ ] **Step 1: Write `loop-530.ps1`.** Per iteration:
  - Mode: iterations 1 to `-WarmCount` are warm, the rest cold. A cold iteration first runs `dotnet build-server shutdown`, then kills by PID every `MSBuild.exe`, `dotnet.exe` whose command line contains `MSBuild.dll` or `nodemode`, `VBCSCompiler` and `rzc` process that is not an ancestor of the loop. `mode` records what actually happened, so a warm iteration after a stall reset is logged as `cold`.
