# Phase 15.0 — The Pin Standard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the pin population exactly enumerable, write down what a pin must do to be trusted, and measure every pin against that standard.

**Architecture:** One shared `RepoRoot()` replaces **24** copy-pasted walks. That consolidation is not cleanup — it is the mechanism: reflection and source-scanning over the shared helper's callers enumerates the pin population exactly, where no naming convention can.

**Tech Stack:** C# / xUnit, MSBuild (`Directory.Build.props`), Markdown.

**Spec:** [`docs/superpowers/specs/2026-09-22-phase-15.0-design.md`](../specs/2026-09-22-phase-15.0-design.md)

## Global Constraints

- **No production source changes.** This phase touches `tests/**` and `docs/**` only. If a task appears to need a change under `src/`, stop and escalate.
- **The suite count must not change** — it is **1111** today. Consolidating a helper adds no tests; Tasks 2 and 4 may add some, and each must say so explicitly. **Do not touch the count gates** — Task 5 owns them.
- **Conventional commits, scope `15.0`.** The body must contain **no nested parentheses** — release-please silently drops the entire commit when a `(` appears inside a parenthesised group, and the workflow still reports success. Never write a `claude.ai/code/session_*` URL.
- **Zero new build warnings.** A pre-existing `CS8669` on generated `BnDeepLinkVectors.g.cs` is not yours.
- **A pin that passes under its own mutation is worthless**, and this phase is *about* that. Every assertion added must be mutation-proven **against its own branches**, not only its subject — the M14 lesson that cost five review rounds.
- **Run every command in the FOREGROUND.** Backgrounding a `dotnet test` and waiting for a notification hangs a subagent indefinitely.

## Environment notes

- .NET SDK **10.0.400**. If `dotnet test` wedges: `Stop-Process -Name testhost,MSBuild -Force`, then `dotnet build-server shutdown`.
- Three test projects: `BlazorNative.Runtime.Tests` (19 copies), `BlazorNative.Renderer.Tests` (2), `BlazorNative.Analyzers.Tests` (2).
- **There is no `Directory.Build.props` above `tests/`** — `src/` has its own, and `tests/` is a sibling, so adding one at `tests/` is purely additive and applies to all three projects.

**Interfaces:**
- Produces: `internal static class BnRepo` with `public static string Root()`. Task 2 enumerates its callers; Task 4's census assumes every pin reaches the tree through it.

- [ ] **Step 1: Enumerate by the WALK, not the method name — there are 24, not 23**

This is the load-bearing precondition. **Verify the walks are identical yourself rather than trusting any count** — consolidating differing implementations into one would silently change what some pins look at.

Run:
```bash
grep -rl 'File.Exists(Path.Combine(dir.FullName, "BlazorNative.sln"))' tests/ --include="*.cs"
```

Expected: **24 files**. A pre-flight scan found `BnImageDemoTests.cs:313-323` declaring `ShellSource(string)`, which performs the **identical** walk but is not called `RepoRoot` — so grepping the method name skips it. This is the milestone's own lesson one level down: pins are not enumerable by class-name suffix, and the helper is not enumerable by method name either. **Counting by what the code does is the only count that has been right.** Then confirm the walks are identical by diffing their bodies. **If more than one, stop and report the differences** — the consolidation plan changes shape, and which body wins becomes a decision rather than a mechanical merge.

- [ ] **Step 2: Write the shared helper**

`tests/Shared/BnRepo.cs`:

```csharp
namespace BlazorNative.Tests.Shared;

/// <summary>
/// THE single way a test reaches the repository tree.
///
/// WHY THIS EXISTS, and why it is not merely cleanup: before phase 15.0 this
/// walk was copy-pasted into 24 separate test files -- 23 named `RepoRoot`, and
/// one inlined into `BnImageDemoTests.ShellSource`, which is why counting by
/// method name undercounted it. They had not drifted: all 24 used the same
/// `BlazorNative.sln` sentinel and the same walk. But 24 copies of one truth is
/// the precondition for the twin-divergence class that
/// milestone 14 spent five phases closing. #339 was copies-agreeing right up
/// until one was not.
///
/// It also does a second job the copies could not. The pin population is NOT
/// enumerable by name -- `Drift`, `Pin`, `Sweep` and `Roster` are all in use, so
/// a convention test keyed on a suffix would miss a quarter of it. Callers of
/// THIS method are the population, exactly. PinPopulationTests depends on that,
/// so a test that reaches the tree another way is invisible to enforcement --
/// which is what that test exists to catch.
/// </summary>
internal static class BnRepo
{
    /// <summary>Walks up from the test binary to the directory holding
    /// BlazorNative.sln. Fails loudly when it cannot find it: a pin that cannot
    /// locate its subject must red, never pass over nothing.</summary>
    public static string Root()
    {
        var dir = new DirectoryInfo(AppContext.BaseDirectory);
        while (dir is not null && !File.Exists(Path.Combine(dir.FullName, "BlazorNative.sln")))
            dir = dir.Parent;

        if (dir is null)
            throw new InvalidOperationException(
                "could not find BlazorNative.sln above the test binary — a pin that cannot find "
                + "its subject must fail loudly, never vacuously");

        return dir.FullName;
    }
}
```

**Note the deliberate change from the copies:** they used `Assert.True(dir is not null, …)`. This throws instead, so the helper carries no xUnit dependency and can be linked into any test project. The failure is still loud; only the mechanism differs. **Say so in your report** — it is a behaviour change, narrow but real.

- [ ] **Step 3: Link it into all three projects**

`tests/Directory.Build.props`:

```xml
<Project>
  <!-- Links the shared test helper into EVERY project under tests/, so a future
       test project cannot forget it. That matters beyond convenience:
       PinPopulationTests enumerates the pin population by finding callers of
       BnRepo.Root, and a project that reached the tree its own way would have
       pins invisible to enforcement. -->
  <ItemGroup>
    <Compile Include="$(MSBuildThisFileDirectory)Shared\BnRepo.cs" Link="Shared\BnRepo.cs" />
  </ItemGroup>
</Project>
```

**Verify no `Directory.Build.props` already applies to these projects** before adding this — MSBuild walks up from each `.csproj`, and an existing file at the repo root would need `<Import>` rather than replacement. The design says none exists; confirm it.

- [ ] **Step 4: Build before migrating anything**

Run: `dotnet build BlazorNative.sln -c Debug`

Expected: succeeds. Every test file still has its own `RepoRoot()`, and `BnRepo` is merely present and unused. **A failure here is a linking problem, not a migration problem**, and separating the two is why this step exists.

- [ ] **Step 5: Migrate all 24 files**

In each file: delete the local `RepoRoot()` declaration, and replace every `RepoRoot()` call with `BnRepo.Root()`. Add `using BlazorNative.Tests.Shared;` where needed.

**Two files declare it `internal static` rather than `private static`** — check whether anything outside those files calls them before deleting. If something does, that caller migrates too.

- [ ] **Step 6: Prove the migration changed nothing**

Run: `dotnet test BlazorNative.sln`

Expected: **1111 passed, 0 failed, 0 skipped** — exactly as before.

**A green suite is necessary but NOT sufficient here, and this is the subtle part.** A pin that silently stopped finding the repo root would still pass *if it were vacuous* — which is precisely the property this milestone doubts. So also run:


### Task 2: The pin that pins the pins

Task 1 made the population enumerable *in principle*. This makes it enforceable: a test that reaches the repo tree without going through `BnRepo.Root()` is invisible to every mechanism this milestone will build, so it must red.

**Files:**
- Create: `tests/BlazorNative.Runtime.Tests/PinPopulationTests.cs`

**Interfaces:**
- Consumes: `BnRepo.Root()` from Task 1.
- Produces: nothing later tasks depend on structurally, but Task 4's census cites its output as the population roster.

- [ ] **Step 1: Write the failing mutation first**

Before writing the test, create the thing it must catch. Add to any test file in `Runtime.Tests`:

```csharp
    [Fact]
    public void BypassesTheSharedHelper()
    {
        var dir = new DirectoryInfo(AppContext.BaseDirectory);
        while (dir is not null && !File.Exists(Path.Combine(dir.FullName, "BlazorNative.sln")))
            dir = dir.Parent;
        Assert.NotNull(dir);
    }
```

- [ ] **Step 2: Write the pin**

```csharp
using System.Text.RegularExpressions;
using BlazorNative.Tests.Shared;
using Xunit;

namespace BlazorNative.Runtime.Tests;

// ─────────────────────────────────────────────────────────────────────────────
// THE PIN POPULATION (phase 15.0).
//
// A pin is not defined by its NAME. `Drift`, `Pin`, `Sweep` and `Roster` are all
// in use as suffixes, so a convention test keyed on one would miss a quarter of
// the population -- this milestone's own bug class, inside the mechanism meant
// to close it.
//
// A pin is defined by what it DOES: it reads the repository tree at runtime and
// asserts on the contents. Every such test must reach the tree through
// BnRepo.Root, because that is what makes the population enumerable. A test that
// walks to the solution file itself is invisible to enforcement, and this test
// is what notices.
// ─────────────────────────────────────────────────────────────────────────────

public sealed class PinPopulationTests
{
    /// <summary>Every way a test could reach the tree without the shared helper.
    /// This list is the one manual seam and cannot be removed: it is a fact about
    /// the .NET API surface, not about this repo.</summary>
    private static readonly string[] BypassMarkers =
    [
        "BlazorNative.sln",       // the sentinel — walking to it by hand
        "AppContext.BaseDirectory",
    ];

    [Fact]
    public void NoTest_ReachesTheRepoTree_WithoutTheSharedHelper()
    {
        string root = BnRepo.Root();
        string testsDir = Path.Combine(root, "tests");
        Assert.True(Directory.Exists(testsDir), $"tests/ not found under {root}");

        var offenders = new List<string>();
        int scanned = 0;

        foreach (string path in Directory.EnumerateFiles(testsDir, "*.cs", SearchOption.AllDirectories))
        {
            // The shared helper is allowed to do exactly this — it is the one
            // implementation everything else routes through.
            if (Path.GetFileName(path) == "BnRepo.cs") continue;

            scanned++;
            string code = File.ReadAllText(path);
            foreach (string marker in BypassMarkers)
                if (code.Contains(marker, StringComparison.Ordinal))
                    offenders.Add($"{Path.GetRelativePath(root, path).Replace('\\', '/')} uses '{marker}'");
        }

        // ANTI-VACUITY: the standard this milestone is writing, applied to the
        // test writing it. If the walk finds no files, the loop above asserts
        // nothing and this test passes while checking nothing.
        //
        // THE FLOOR IS NOT ARBITRARY, and a low one is nearly useless. There are
        // ~151 .cs files under tests/ today. A floor of 20 would pass while the
        // walk saw 13% of its subject -- a guard weak enough to be theatre, which
        // is precisely what this milestone exists to remove. 100 is comfortably
        // below today's count so ordinary deletion does not red it, and far
        // enough above zero that a broken walk cannot slip through.
        Assert.True(scanned >= 100,
            $"scanned only {scanned} test files, and there are roughly 151 — the walk has stopped "
            + "seeing its subject, so the assertion below is checking almost nothing");

        Assert.True(offenders.Count == 0,
            "these tests reach the repo tree without BnRepo.Root, so they are invisible to pin "
            + "enforcement — route them through the shared helper:\n  " + string.Join("\n  ", offenders));
    }
}
```

- [ ] **Step 3: Run — the mutation must RED**

Run: `dotnet test tests/BlazorNative.Runtime.Tests/BlazorNative.Runtime.Tests.csproj --filter "FullyQualifiedName~PinPopulationTests"`

Expected: **FAIL**, naming the file holding your step 1 mutation.

- [ ] **Step 4: Remove the mutation and confirm green**

Delete the `BypassesTheSharedHelper` fact. Re-run: **PASS**.

**If it does not pass, you have found real offenders** — files that legitimately reach the tree another way. Do **not** widen the allow-list to silence them. Migrate them, or report them if migration is not obviously right.

- [ ] **Step 5: Mutation-prove the anti-vacuity assertion itself**

One at a time, reverted between:

1. Change `testsDir` to a directory that does not exist → must red on the `Directory.Exists` assertion, **not** crash.
2. Change the file filter from `*.cs` to `*.nonsense` → must red on the **`scanned >= 20`** assertion, and the offender assertion must pass vacuously beneath it. **That contrast is the point** — it demonstrates the anti-vacuity guard doing the job the offender check cannot do for itself.

- [ ] **Step 6: Full suite and commit**

Run: `dotnet test BlazorNative.sln` — expect **1112** (one new fact). Report the real number.

```bash

git commit -m "test(15.0): make a test that bypasses the shared helper red"
```

### Task 3: Write the standard

**Files:**
- Create: `docs/pin-standard.md`

- [ ] **Step 1: Write it**

In the repo, not a milestone doc — milestone docs get archived and this must outlive M15.

It must state, with the reasoning rather than only the rule:

1. **What a pin is** — a test that reads the repo tree at runtime and asserts on its contents. Not a name.
2. **It must fail when it scans nothing.** Vacuity is about the *assertion shape*, not the input: *for every X, assert Y* passes trivially when there are no X, whether X came from a regex, a directory walk, or a collection. `RouteMenuDriftTests` scans no files and has the shape.
3. **It must fail when its subject moves** — a renamed file, a restructured manifest, a regex whose anchor disappears.
4. **It must state what it does not cover**, as a written limit. A pin that implies completeness it lacks is worse than one that admits a gap.
5. **It must reach the tree through `BnRepo.Root()`**, or it is invisible to enforcement.
6. **Its mutations must exercise its own branches**, not only its subject. Cite M14: six mutations missed a real hole because every one placed its token alone on its own line and never entered the suppression branch where the bug lived.

- [ ] **Step 2: Link it where a pin author will look**

From `CONTRIBUTING.md` if one exists, and from `docs/` index if there is one. A standard nobody finds is not a standard — the same argument Task 3 of phase 14.4 made about the observability recipe.

- [ ] **Step 3: Verify and commit**

Run `npm run build` in `website/` **if** the file is published there — `onBrokenAnchors: 'throw'` means a bad cross-reference reds a required check.

```bash
git add docs/pin-standard.md
```

### Task 4: The census

**Files:**
- Create: `docs/plans/2026-09-22-phase-15.0-census.md`

- [ ] **Step 1: Enumerate the population mechanically**

Use Task 2's definition, not a name pattern:

```bash
grep -rl "BnRepo.Root()" tests/ --include="*.cs" | sort
```

That list **is** the population. Record its size — the milestone's opening guess was 16 and the first correction said 19 by name; this is the first count that is neither a guess nor a suffix match.

- [ ] **Step 2: Assess each one against the standard**

For every file, record a verdict in a table: **conforms**, **fixed**, or **exempt with a written reason**.

The property to judge hardest is anti-vacuity, and **the question is not "does it call `Assert.NotEmpty`"** — it is *can this test pass while checking nothing?* Trace each assertion's shape:

- a `foreach` over a collection that could be empty
- a regex `Matches` loop that could match zero times
- a set comparison where both sets could be empty
- a `Contains` over text that could have failed to load

**An unassessed pin is a gap. "Exempt" is a fine outcome — silence is not.**

- [ ] **Step 3: Record what you could not determine**

If a pin's vacuity depends on runtime state you cannot evaluate by reading, say so and mark it **needs-mutation** rather than guessing either way. That is a finding for 15.1, not a failure here — and it is more useful than a confident wrong verdict.

```bash
git add docs/plans/2026-09-22-phase-15.0-census.md
git commit -m "docs(15.0): census every pin against the standard"
```
