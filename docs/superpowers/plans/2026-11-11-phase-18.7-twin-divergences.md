# Phase 18.7 Twin divergences Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Tick each box in this file as you finish its step, and commit the ticks with the step's work. Tick only your own task's boxes, line by line; never a broad `sed` over the file** (the 18.6 lesson). The complete-phase gate fails on unticked boxes.

**Goal:** The stderr pump forwards every line ungated on both shells (#401), and an auth-bound secure-storage `set` with no enrolled biometric returns `Unavailable` on both shells (#396). Each is held by a behavioural twin pin.

**Architecture:**
- **#401:**
  - One vector file, `src/stderr-pump-vectors.json`, which WireGen generates into Swift and Kotlin tables.
  - A JVM test and an XCTest run every vector through the pump's production forward path and observe each log's emit seam.
  - iOS gets a `BnLog.relay`, the twin of Kotlin's `BnShellLog.relay`, so the pump stops re-gating.
- **#396:**
  - A static `BnBiometrics.evaluateBiometry()`, which owns the existing `canEvaluatePolicyOverrideForTest` seam, is asked inside `secureSet`'s `requireAuth` branch. With no enrolment or no hardware, `secureSet` returns `unavailable` before the access control is built.
  - An Android instrumented test anchors the twin on the lane's unenrolled AVD.

**Tech Stack:** Swift / XCTest on the iOS simulator lane (`ios.yml`), Kotlin / JUnit Jupiter on the JVM (`ci.yml`, Windows), AndroidX instrumented tests on the API 34 lane (`android-instrumented.yml`), C# WireGen (`tools/BlazorNative.WireGen`), xUnit drift tests.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-18.7-design.md`. Read it in full before your task. Its D1–D6 are the rules this plan implements. The owner approved it on 2026-11-11.

## Global Constraints

- **No ABI change, no wire vocabulary change.** The 80-byte bridge struct and the 10 exports stay as they are.
- **Template mirrors:** every edited file that has a copy under `templates/BlazorNative.Templates/content/` gets the identical edit in the same commit. The mirror guard requires byte-identical copies.
- **Generated files** (`*.g.swift`, `*.g.kt`, `*.g.cs`) are never hand-edited. Regenerate with `dotnet run --project tools/BlazorNative.WireGen`.
- **Test counts:**
  - Task 1 Step 1 re-measures the baselines on `main`. #690 landed after 18.6, so do not trust 1412 / 209 / 271 / 296 without re-measuring.
  - A task that adds tests moves the count at every site in `ci.yml`, `README.md` and the workflow headers in the same commit.
- **Commits:**
  - Conventional, with scope `18.7`.
  - No `Co-Authored-By` trailer, no "Generated with" line, no session link.
  - No closing keywords (`closes`, `fixes` or `resolves` followed by `#N`) in any commit. Only the PR body closes #401 and #396.
  - No nested parentheses in a body line.
- **Pins** are graded against `docs/pin-standard.md`, "Grading a pin: sites and reds".
  - Every new site needs a fresh red from one subject mutation, prefixed `18.7-`, and the red quotes its own message.
  - Edit every file, comments included, before mutating.
  - Staleness is judged against each red's own commit.
- **Local host is Linux:**
  - The JVM suite needs the win-x64 dll, so it runs only in `ci.yml` on a PR.
  - iOS runs only in `ios.yml`. Android instrumented runs only in `android-instrumented.yml`, which runs only for PRs against `main`.
  - Run one lane run at a time per ref, never `&` in the Bash tool, and compare each run's `headSha` with the head.
  - Commit before any mutation run and check `git status` is clean.

## Review Focus

1. **A test that swaps `BnStderrPump.sink` and leaves it swapped.** The vector tests would then observe the swapped sink, not production. Tasks 2 and 3 call the production `forward` directly and never go through `sink`.
2. **Lines pumped on iOS before `BnRuntime` applies the shell level** (`BnRuntime.swift:252-253`) used to be gated at the default Warn. After D1 they are forwarded. Task 3's vector at shell level Error covers the gate's absence at any level, including the default.
3. **The existing iOS auth-set tests on the unenrolled simulator.** Without the override they now get `unavailable`. Task 4 Step 3 sets the override in each one, and the full iOS suite runs in Task 6.
4. **A refused auth `set` and the key's old value.** Both shells delete before they provision: `secureSet` calls `secureDelete` first, and `provisionKey` calls `deleteEntry` at `AndroidShellBridge.kt:1263`. The iOS check sits after the delete, which keeps that order. The docs make no claim about a refused set's old value, and no test asserts one.
5. **`UNAVAILABLE` on Android for the wrong reason, such as no lock screen.** Task 5's test asserts both preconditions first, each with its own message.
