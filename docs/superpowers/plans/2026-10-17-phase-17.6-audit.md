# Phase 17.6 — Audit and close Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Audit all eleven M17 DoD items on evidence measured now on `origin/main`, and close M17 if every item is MET, or MET NARROWLY with its reason.

**Architecture:** This phase writes no code. The controller measures:
- the tests on HEAD, which are the local .NET runs, the CI run and both device lanes;
- the pin inventory, with re-reds of any pin whose code moved after its red.

One implementer writes the report. A fresh reviewer then re-measures a sample of it.

**Tech Stack:** `gh`, `git`, `dotnet test` with `pwsh` on PATH, and GitHub Actions. Two lanes need care:
- **JVM:** the pure-Kotlin JVM tests run locally. The JNA tests run on CI only (#491).
- **CI:** `ci.yml` has no `workflow_dispatch` and runs on PRs only.

**Spec:** `docs/superpowers/specs/2026-10-17-phase-17.6-design.md`

## Global Constraints

- **Measure at the point of writing.** Nothing is copied from a phase record, ROADMAP, STATE.md, memory or the 16.8 re-audit as evidence. Every number in the report has the command that reproduces it beside it. A phase record is cited only as **where a mutation is recorded**.
- **The M17 range** is `23ffc4ab..origin/main`, where `23ffc4ab` is #499. Release-please and dependency-update commits are excluded **by name**.
- **Device lanes:**
  - They count only on `main`'s exact HEAD, compared by `headSha`, at attempt 1.
  - Dispatch one at a time per workflow and ref, and never background a loop with `&`.
  - Diagnose a failure from its JUnit XML or log before anything else.
  - One rerun is allowed, only for a proven infrastructure failure. Record both attempts.
- **CI:**
  - `ci.yml` cannot be dispatched. The CI evidence is therefore this phase's own PR run.
  - That PR's diff is docs-only, so its tree's code equals HEAD's. The report shows this with `git diff --stat origin/main <pr-head> -- ':!docs'`, which must be empty.
- **Grading:**
  - Each item is graded on its DoD sentence, quoted.
  - **Item 9 wording:**
    - The #454 sentence asks that `ReferenceFixtureBase` "fails naming the stalled command".
    - If the failure names the script, package and output but not the native command that stalled, the item is **MET NARROWLY**, citing #530.
  - **Item 10:** 17.1's BREAKING 0.20.0 is recorded as a behaviour change, not an ABI change.
  - **Item 11:**
    - A pin with no recorded red on current code is **NOT MET**.
    - A partial that its record names, with a reason, is MET NARROWLY. An unnamed partial is NOT MET.
    - A pin first recorded as vacuous needs a later recorded red.
  - **Carried debt** (#500, #506, #511, #522, #530, and #491, which is adjacent) never blocks the close. It narrows an item only when it contradicts that item's wording.
- **No tag.** `CONVENTIONS.md` records `Milestone completion tags a release: no`.
- **No product code changes.**
  - A mutation is restored, and `git status --short` must be empty before the next one.
  - A defect is filed with file:line, not fixed.
- **Commits:**
  - the subject is `docs(17.6): subject`;
  - bodies have no nested parentheses;
  - no session URL;
  - end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - no closing keywords, since every carried issue stays open;
  - run the subject and body through `node scripts/commit-parse-check/check.js` before committing.

## Review Focus

- **A record's claim copied as evidence.** In particular, the line counts, pin counts and lane counts in the MILESTONE `## Phases` summaries, for example "Android 243 → 245". The reviewer re-measures them, or the report marks them as quoted from the record.
- **A green lane that predates HEAD.** Every lane cell carries its `headSha`.
- **A pin whose subject moved after its red.** Task 3's per-pin `git diff --stat` table is in the report.
- **A pin with no register row.** Task 3 maps every test method that M17 added to a record row and a `docs/pin-standard.md` row.
- **Item 9's wording.** The failure text quoted in the report comes from running `GeneratorRunTests`' stall test on HEAD, not from the 17.5 record.
