# Phase 16.4 — The lost first tap (#438) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Task 2 also follows superpowers:systematic-debugging, which puts root cause before the fix.

**Goal:** Find, fix and pin why the first tap after a cold boot sometimes never reaches the iOS biometrics op. #438 is to be closed after merge.

**Architecture:**
- **Evidence:** throwaway branches with diagnostics, plus a pre-M16 baseline.
- **Root cause:** each hypothesis is confirmed or refuted from logs.
- **Fix:** it targets the root cause and comes with a deterministic pin.
- **Verification:** the pin, plus 10 sequential lane runs.

**Tech Stack:** Swift and XCTest through the iOS lane, .NET with xUnit, GitHub Actions workflow dispatch.

**Spec:** `docs/superpowers/specs/2026-09-28-phase-16.4-design.md`

## Global Constraints

- **No workarounds.** No timeout bump, retry, skip or loosened assertion in `BnBiometricsTests` or anywhere else (this is the owner's rule).
- **Scratch branches.**
  - Only branches named `scratch/16.4-*` may be pushed for diagnostics.
  - Delete each one, both remote and local, when you are done with it.
  - Never merge diagnostic logging.
- **iOS lane runs are sequential per ref.** `ios.yml` cancels any in-progress run on the same ref. Before recording a run, compare its `headSha`.
- **Pins** follow `docs/pin-standard.md` Rules 2–5 and 7. Record the mutations, and revert each one by reversing the edit.
- **Commits:**
  - Commit before long runs.
  - Never use `--no-verify`.
  - Subjects are `type(16.4): subject`.
  - Bodies contain no nested parentheses, no URLs and no closing keywords; write "#438 to be closed".
  - End each commit with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No tag.**
