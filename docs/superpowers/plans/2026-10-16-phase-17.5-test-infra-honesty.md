# Phase 17.5 — Test-infrastructure honesty Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No local run can hang silently, test a stale native library, or fail with a bare message (#454, #424, #458).

**Architecture:**
- **#454.** The reference script turns MSBuild node reuse off. The fixture's process run moves into one bounded, testable method that kills the tree and fails with a named message.
- **#424.** Gradle declares the win-x64 publish as an input of every task that loads it.
- **#458.** The 10 androidTest `pollUntil` copies become one helper that names a destroyed Activity, and a Swift assertion gets a message.

**Tech Stack:** C# xUnit, PowerShell 7, Gradle Kotlin DSL, Kotlin androidTest, Swift XCTest.

**Spec:** `docs/superpowers/specs/2026-10-16-phase-17.5-design.md`

## Global Constraints

- **Red first** for every new fact and test. Mutations are recorded with their anchors in `docs/plans/2026-10-16-phase-17.5-record.md`, sections `1. Baseline`, `2. Red`, `3. Mutations`, `4. Final review`, `5. Lanes`.
- **Mutations:**
  - commit before mutating, back up into a `mkdir -p` directory, restore with `cp`, verify with `cmp`;
  - never `git checkout` on a dirty tree;
  - scratch refs are cut only from a clean, committed tree.
- **Local runs:**
  - .NET: `dotnet test --blame-hang --blame-hang-timeout 10m`, redirected to a file;
  - pure-Kotlin JVM tests run locally;
  - JNA-loading JVM tests, Android and iOS run only on the lanes.
- **Lanes:** compare `headSha` and use attempt 1.
- **Commits:**
  - `fix(17.5): …` for behaviour changes, `test(17.5)`/`docs(17.5)` otherwise;
  - each through `node scripts/commit-parse-check/check.js`;
  - no nested parentheses in bodies;
  - the PR title is lowercase-first;
  - the PR body says `Closes #454`, `Closes #424` and `Closes #458`, and nothing else closes.
- **Baseline counts** on `6d86e9ce`: .NET 1362, JVM 206, Android 243.
- **The bound is 5 minutes per reference generation.**
- **The DESTROYED message is exactly** "the activity was DESTROYED while the test still expected it on screen".

## Review Focus

- **A test that legitimately takes longer than 5 minutes** to generate one reference, such as a cold machine or a Windows restore. The soak records the slowest generation, and Task 2 checks the bound against it.
- **A process-tree kill that leaves a re-parented MSBuild node behind.** The bound's fact asserts no tree member survives. The failure message says how to clear a stray node.
- **A pure-Kotlin JVM run on Linux where the win-x64 DLL does not exist.** Declaring a missing file as an input must not fail the task. Task 3 runs `BnShellLogTest` locally after the change.
- **A `pollUntil` caller whose copy used a different sleep or deadline name.** It must keep its timing. Task 4 maps each copy's values before deleting it.
- **The helper polled on a scenario whose Activity finished by design**, such as `back_at_root_finishes_the_activity`. The helper must fail only where the caller still expected it on screen. Task 4 runs the full Android lane.

**Interfaces:**
- Produces `internal static GeneratorRun RunBounded(string script, IReadOnlyList<string> args, TimeSpan bound)`, in a new `internal static class BoundedScript` in the test project.
  - `GeneratorRun` is a record `(int ExitCode, string Log)`.
  - On expiry it kills the process with `entireProcessTree: true` and throws `XunitException` with this message: "`<script>` `<args>` did not finish within `<bound>`; the process tree was killed.   - Both streams are read with `BeginOutputReadLine`/`BeginErrorReadLine` into one locked buffer. `WaitForExit(bound)` is the only wait. After a true return, call parameterless `WaitForExit()` only if the streams' EOF is already reached; otherwise do not wait on EOF.
- `ReferenceFixtureBase` calls `RunBounded(script, [-NoProfile -File … -Package p -OutputPath o], TimeSpan.FromMinutes(5))`. Its asserts are unchanged.
