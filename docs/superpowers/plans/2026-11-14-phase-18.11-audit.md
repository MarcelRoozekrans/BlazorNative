# Phase 18.11 — Audit and close Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every pin M18 added a fresh, quoted red at each graded site, fix #568's last three cells, and audit M18 against its DoD on that head.

**Architecture:** Stage 1 is a re-run record. One task derives the population and its staleness from git. Four tasks re-run the stale reds, one per route: .NET, JVM, Android and iOS. A cells task then updates the register. Stage 2 is the audit report, graded on the PR's own lanes. There is no product or test code change.

**Tech Stack:** C#/xUnit on net10.0 and net11.0, Kotlin JUnit/JNA, Android instrumented tests, XCTest on the iOS simulator, and GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-14-phase-18.11-design.md`

## Global Constraints

- **Grading rule.** Use `docs/pin-standard.md`, "Grading a pin: sites and reds", parts 1 to 4. Nothing broader is graded; that is #562.
- **Population.** Pins added or materially changed by the M18 squashes `5a7ab54a`, `d246778f`, `2eb3f22d`, `0b430432`, `2cc6801d`, `d7fdf937`, `ff39e209`, `d9bf0711`, `a1bacd6b` and `da6f8c1d`. In a pre-M18 test, grade only the sites the M18 change added or altered.
- **Staleness.** `git diff --stat <red-commit> HEAD -- <test-file> <subject-file>`. Any output means stale. A red whose commit cannot be resolved is stale.
- **Base.** The branch is cut at `da6f8c1d`. If `origin/main` moves, merge it in and re-run the staleness diff for the files it touched.
- **Record.** `docs/plans/<date>-phase-18.11-record.md`. Every red row gives:
  - pin, site `file:line`, and the label or name clause;
  - the exact mutation diff;
  - the commit;
  - the command, or the run id with `headSha` and attempt;
  - the quoted failure message at the site's own line.
- **Mutations.** Run them only in a detached worktree. `git status --short` must be empty before and after. Commit, then mutate; never on a dirty tree. Copy the mutation text from HEAD, not from an old record.
- **Device runs.**
  - Use `scratch/18.11-<lane>-<n>`, dispatched with `gh workflow run <file> --ref <branch>`.
  - One run per ref at a time. Wait with `gh run watch --exit-status` in the foreground. Never background a loop with `&`.
  - A mutation that crashes the process runs alone.
  - Delete each scratch ref after the record cites its run, and verify it is gone.
- **Linux host.** The .NET suite needs `pwsh` as a dotnet tool. Swift cannot compile here, so every iOS red runs on CI.
- **Process hygiene.** Kill processes by PID only. Never `pkill -f`.
- **Branch.** `feat/18.11-audit` is checked out in another worktree. Work detached and push with `git push origin HEAD:feat/18.11-audit`.
- **Commits:**
  - prefix `docs(18.11):`;
  - no nested parentheses in the body;
  - no closing keywords except the final PR body's deliberate one;
  - no Claude signature, no `Co-Authored-By: Claude` trailer, no session URL.
- **Plan boxes.** Each implementer ticks only its own task's boxes, line by line. No `sed` over the plan.

## Review Focus

- A re-run red that fails through an earlier line, a crash, or a masking mutation in the same batch, and is counted for a later site.
- A pin that is in the git-derived population but missing from the phase records, or the reverse, skipped silently.
- A red called fresh whose diff was run against the squash commit instead of the red's own commit.
- A register cell edited to cite a re-run while it still states the stale red's old line or message as current.
- The flake bullet graded MET on a run that hit a #551, #564, #453, #444 or #407 signature, or on a re-run attempt.
