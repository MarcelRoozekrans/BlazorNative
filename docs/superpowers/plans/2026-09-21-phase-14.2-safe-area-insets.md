# Phase 14.2 — Safe-Area Insets on Both Shells Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give app authors a `BnSafeArea` component that keeps content clear of notches, status bars, camera cutouts and home indicators on **both** shells, and put it in every code snippet a user would copy.

**Architecture:** Per-edge padding is added to the style vocabulary first (it does not exist — `padding` is applied as `YGEdgeAll`). Each shell then reports its safe-area insets over the existing `blazornative_host_event` export using a generated `safeAreaChanged` name; a reserved arm in `Exports.DispatchHostEventCore` stores them and re-renders; `BnSafeArea` pads by them, with React-Native-style per-edge modes and Flutter-style nesting that never double-pads.

**Tech Stack:** C# / .NET 10, Swift + Objective-C++ (Apple shell), Kotlin (Android shell), Yoga, xUnit, JUnit, XCTest.

**Spec:** [`docs/superpowers/specs/2026-09-21-phase-14.2-design.md`](../specs/2026-09-21-phase-14.2-design.md)

## Global Constraints

- **Both shells, always.** #338 is fixed on iOS *and* Android. Android has zero inset handling today; a change that lands on one shell only recreates the divergence this milestone exists to close.
- **No ABI change.** Insets ride the existing `blazornative_host_event` export. `nm -gU` must still find exactly **10** `blazornative_*` exports.
- **Never hand-edit a `.g.*` file.** Add names to `src/wire-vocabulary.json`, run `dotnet run --project tools/BlazorNative.WireGen`, commit the regenerated output. `WireVocabularyCodegenTests` byte-compares.
- **A style name the table accepts that no shell applies is silently dropped at runtime.** That is the manifest's own warning. `ShellStyleTableDriftTests` and `AndroidSetStyleDispatch_HasAnArmForEveryYogaStyle` catch it — mutation-prove both when the names land.
- **The Android shell has a byte-identical template mirror.** `TemplateDriftTests` compares `MainActivity.kt` and `BlazorNativeRuntime.kt` between `src/BlazorNative.Jni/` and `templates/`, and runs in the required lane. Edit both copies in the same commit.
- **Respect M13's sequence bands** — item 1–17, container 50–54, component-specific 100+, `ChildContent` 200. A collision does not throw; it produces a **wrong diff, silently**.
- **Nulls must travel.** Component parameter forwarding fires unconditionally, nulls included. An `if (x is not null)` "optimisation" leaves the target holding a stale value — see `BnFlexPreset`'s header.
- **The four existing frame tables must not move.** `bnLayoutDemoFrames`, `bnScrollDemoFrames`, `bnScrollDemoImageFrames`, `bnImageDemoBeforeFrames`. If one changes, a demo page was wrapped that should not have been.
- **Zero-warning bar** on shipping projects; **RS0016/17/37 are errors** — public additions need `PublicAPI.Unshipped.txt` entries.
- **Every new pin must be mutation-proven.** Break it, watch it red, restore, report the message.
- **Environment:** gradle needs `export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-25.0.0.36-hotspot"`. - [x] **Step 1: Report insets from the existing layout hook**

`viewDidLayoutSubviews` already runs on every layout pass — rotation included — and already reads `view.bounds.size`. Add the inset report there, sending only when the value **changes**, so a layout pass that did not move the safe area does not dispatch:

```swift
    /// Phase 14.2 (#338): the safe-area report. `viewDidLayoutSubviews` is the right
    /// hook for the same reason it is the right hook for size — it runs on every
    /// layout pass, including rotation and a keyboard appearing, and `safeAreaInsets`
    /// is only meaningful once layout has happened.
    ///
    /// Sent ONLY when the value changes: an unchanged report would re-render the tree
    /// on every layout pass, and the dispatch is fire-and-forget so nothing downstream
    /// would notice the waste.
    private var lastReportedInsets: UIEdgeInsets?

    private func reportSafeAreaIfChanged() {
        let insets = view.safeAreaInsets
        if let last = lastReportedInsets, last == insets { return }
        lastReportedInsets = insets

        let payload = """
            {"top":"\(insets.top)","right":"\(insets.right)","bottom":"\(insets.bottom)","left":"\(insets.left)"}
            """
        BnRuntime.current?.dispatchHostEvent(.safeAreaChanged, payload: payload)
    }
```

Call it from `viewDidLayoutSubviews` after the existing size handling. Use the **fire-and-forget** overload — 14.1 split these precisely so a UIKit callback never blocks the lane.

- [x] **Step 1: Listen for insets on the root view**

Use `ViewCompat.setOnApplyWindowInsetsListener` on `widget_root`, reading `systemBars()` and `displayCutout()` together — a cutout is not part of `systemBars()`, and #338 is fundamentally a cutout bug:

```kotlin
        // Phase 14.2 (#338): the safe-area report, the twin of iOS's
        // viewDidLayoutSubviews hook. systemBars() alone is NOT enough — a display
        // cutout is reported separately, and the cutout is precisely what made the
        // iPhone's Take Photo button untappable.
        ViewCompat.setOnApplyWindowInsetsListener(widgetRoot) { _, windowInsets ->
            val bars = windowInsets.getInsets(
                WindowInsetsCompat.Type.systemBars() or WindowInsetsCompat.Type.displayCutout())
            reportSafeAreaIfChanged(bars)
            windowInsets
        }
```

Return the insets unconsumed so other views still see them.

- [x] **Step 2: Convert to the same units .NET expects, and send only on change**

The payload must carry the same units Yoga consumes. Android's insets arrive in **pixels**; the Yoga tree works in **dp**. Convert with the display density before sending, and mirror Task 3's change-detection so an unchanged inset does not re-render:

```kotlin
    private var lastReportedInsets: androidx.core.graphics.Insets? = null

    private fun reportSafeAreaIfChanged(insets: androidx.core.graphics.Insets) {
        if (lastReportedInsets == insets) return

        val d = resources.displayMetrics.density
        val payload = """{"top":"${insets.top / d}","right":"${insets.right / d}","bottom":"${insets.bottom / d}","left":"${insets.left / d}"}"""
        if (booted) runtime.dispatchHostEvent(BnHostEvent.SafeAreaChanged, payload)
    }
```

    public void MaximumMode_UsesTheAuthorsPadding_WhenItExceedsTheInset()
    {
        // REACT NATIVE'S RULE: "my padding, or the inset, whichever is larger".
        // Author asks for 24, inset is 8 -> 24. This is the case people otherwise

    [Fact]
    public void WhenTheInsetsChange_TheComponentRelaysOut()
    {
        // Rotation, a keyboard, a call banner. Without this the component is correct
        // exactly once per run.
        var (renderer, frames) = CreateCapturingSession();
        BnSafeAreaInsets.SetForTests(BnSafeAreaInsets.Zero);
        renderer.Mount<BnSafeArea>(ParameterView.Empty);

## Notes for the executor

**Both shells or neither.** A change that lands on iOS alone recreates the divergence this milestone exists to close, and MAUI's own design doc — *"we only support Safe Area on iOS… we haven't done that yet"* for Android — is what that looks like after a few years.

**Three failures are expected and are the point.** Task 1 Step 2 (codegen), Task 1 Step 3 (accepted-but-unapplied style), Task 2 Step 2 (reserved name with no arm). Each is an existing guard catching this phase's work before it ships. Record the messages; they are mutation proofs obtained for free.

**The two rules that make Task 5 hard were learned from other frameworks, not derived.** Nesting must not double-pad (Flutter), and `maximum` compares against the author's own padding (React Native). A from-first-principles implementation gets both wrong.

**The Android density conversion is the quietest risk in the plan.** Insets arrive in pixels; Yoga works in dp. Wrong there, and the app looks right on one device and wrong on another, with every test still green.
