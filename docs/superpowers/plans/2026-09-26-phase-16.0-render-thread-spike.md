# Phase 16.0 — The render-thread spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer, by measurement against criteria G1–G7 fixed in the spec, whether a .NET-owned render thread can replace `InlineDispatcher` and still keep every contract the inline dispatcher exists to hold.

**Architecture:** The spike code lives on `spike/16.0-render-thread`, cut from `main`, and is **never merged**. The first spike commit adds the probes and the timing harness on unchanged code, which gives the baseline. The second commit swaps the dispatcher. The controller then runs the JVM suite and both device lanes against the spike head. The only merged output is a conclusion doc on `feat/16.0-render-thread-spike`.

**Tech Stack:** .NET 10, xUnit, `Microsoft.AspNetCore.Components` `Renderer`/`Dispatcher`, NativeAOT, Gradle with JDK 21, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-26-phase-16.0-design.md`

- [ ] **Step 1: The dispatcher.** Replace `InlineDispatcher` with a render-thread dispatcher of this shape. It is spike code, so keep it minimal:

```csharp
internal sealed class RenderThreadDispatcher : Dispatcher
{
    private readonly BlockingCollection<(SendOrPostCallback Cb, object? State)> _queue = new();
    private readonly Thread _thread;

    public RenderThreadDispatcher()
    {
        _thread = new Thread(Run) { IsBackground = true, Name = "BlazorNative-Render" };
        _thread.Start();
    }

    public int ThreadId => _thread.ManagedThreadId;

    private void Run()
    {
        SynchronizationContext.SetSynchronizationContext(new RenderThreadContext(this));
        foreach (var (cb, state) in _queue.GetConsumingEnumerable())
            cb(state);
    }

    internal void Post(SendOrPostCallback cb, object? state) => _queue.Add((cb, state));

    public override bool CheckAccess() => Environment.CurrentManagedThreadId == _thread.ManagedThreadId;

    public override Task InvokeAsync(Action workItem)
    {
        if (CheckAccess()) { workItem(); return Task.CompletedTask; }
        var tcs = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);
        Post(_ => { try { workItem(); tcs.SetResult(); } catch (Exception ex) { tcs.SetException(ex); } }, null);
        return tcs.Task;
    }

    public override Task InvokeAsync(Func<Task> workItem)
    {
        if (CheckAccess()) return workItem() ?? Task.CompletedTask;
        var tcs = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);
        Post(async _ => { try { await workItem(); tcs.SetResult(); } catch (Exception ex) { tcs.SetException(ex); } }, null);
        return tcs.Task;
    }

    // The two InvokeAsync<TResult> overloads follow the same pattern with TaskCompletionSource<TResult>.

    private sealed class RenderThreadContext(RenderThreadDispatcher owner) : SynchronizationContext
    {
        public override void Post(SendOrPostCallback d, object? state) => owner.Post(d, state);
        public override void Send(SendOrPostCallback d, object? state)
        {
            if (owner.CheckAccess()) { d(state); return; }
            using var done = new ManualResetEventSlim();
            owner.Post(s => { try { d(s); } finally { done.Set(); } }, state);
            done.Wait();
        }
        public override SynchronizationContext CreateCopy() => this;
    }
}
```
