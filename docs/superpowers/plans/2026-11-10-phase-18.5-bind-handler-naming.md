# Phase 18.5 Slow-handler naming for compiler lambdas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Tick each box in this file as you finish its step, and commit the ticks with the step's work.** The complete-phase gate fails on unticked boxes.

**Goal:** A slow-handler warning never names a compiler-generated method. For a compiler lambda it names the declaring page plus the call site's position on it, `BnInput at sequence 12` (#522).

**Architecture:**
- **The name changes; the key does not.** `HandlerCallSite.Resolve` keeps keying by the generated method. When that method is compiler-generated app code, it names the page instead and hands the `MethodInfo` back.
- **The position is looked up only on the warning path.** `NativeRenderer` walks from the call site's tree owner up through the component-parent map and reads each component's current frames. The outermost attribute frame whose value runs that method wins.
- **The frame scan lives in `BlazorInterop.cs`,** the one file allowed to name `RenderTree` types. `NativeRenderer` passes it `GetCurrentRenderTreeFrames(id)` without naming the type.
- **Every failure falls back to the page alone.** That covers a disposed component, a lookup that throws, and no frame matching.

**Tech Stack:** C# / .NET 10 Blazor renderer, xUnit with Razor-compiled fixture pages, the NativeAOT win-x64 dll driven from JUnit (`testDebugUnitTest`, Windows CI only).

**Spec:** `docs/superpowers/specs/2026-11-04-phase-18.5-design.md`. Read it in full before your task. Its D1–D6 are the rules this plan implements. The owner approved it on 2026-11-04.

## Global Constraints

- **No ABI change and no public API change.** The 80-byte bridge struct and the 10 exports stay as they are. `HandlerCallSite`, `DispatchSubject` and the new lookup are `internal` or `private`. The template mirror and `src/wire-vocabulary.json` are untouched.
- **`NativeRenderer.cs` never names a `Microsoft.AspNetCore.Components.RenderTree` type.** Frame reading goes through `BlazorInterop.cs` (its header, `:1-21`).
- **No cost on the render path.** The attach site at `NativeRenderer.cs:1576` copies one more `int`, the component id, and does nothing else. All reflection and frame walking happens inside the over-budget branch at `:2464`.
- **Naming a diagnostic never faults a dispatch.** Every new code path that can throw runs inside a catch-all that falls back.
- **The warning never carries the payload.**
- **Exact formats** (D4):
  - Name: `in {Page}, {Control} at sequence {N}`, so a warning reads `slow handler: handler 41 'change' in MyApp.Pages.Settings, BnInput at sequence 12 held …`.
  - `{Page}` is a `Type.FullName`. `{Control}` is a component's short `Type.Name`, or `element {name}` for an element, such as `element button`.
  - Fallback: `in {Page}` alone. A compiler name, anything with `<`, never appears.
  - Key: unchanged, `{Declaring}::{Method}#{EventName}` on the generated method.
- **Commits:**
  - Conventional, with scope `18.5`.
  - No `Co-Authored-By` trailer, no "Generated with" line, no session link.
  - No closing keywords (`closes`, `fixes`, `resolves` followed by `#N`) in any commit. Only the PR body closes, and it closes #522 on purpose.
  - No nested parentheses in a body line.
- **Pins** are graded against `docs/pin-standard.md`, "Grading a pin: sites and reds". Every labelled anchor and every claim in a test's name needs a fresh red from one subject mutation, and the red quotes its own message. Anchor messages start with `anchor:`.
- **Local host is Linux:**
  - The .NET suite runs locally with `pwsh` installed.
  - The JVM suite needs the win-x64 dll, so it runs only in `ci.yml` on a PR.
  - Run one lane run at a time per ref, never `&` in the Bash tool, and check each run's `headSha`.
  - Commit before any mutation run, and check `git status` is clean. A mutation helper's `git checkout` wipes uncommitted work.

## Review Focus

1. **The call site is gone by the time the warning is named.** A slow `:after` hides its own input with an `@if`, so the `BnInput` is disposed during the dispatch. Expected: rc 0 and `in {Page} held`. Task 1, `ASlowHandlerThatHidesItsInput_NamesThePageAlone`.
2. **A lambda forwarded through an app component.** Three trees hold it: `BnButton`'s element, the card's `BnButton` frame and the page's card frame. Expected: the page's card frame, not an inner one. Task 2, `ALambdaPassedThroughAnAppComponent_NamesTheOutermostCallSite`.
3. **Attributes that are not callbacks sit before the match**, such as a string `Placeholder`, a `bool` or a `RenderFragment`. The reader returns no match for them without throwing, and the owner is still the nearest component or element frame, not the frame just before. Task 2's bind facts, which have `Placeholder` first, and mutation M9.
4. **A value-type `EventCallback<T>` under NativeAOT.** `BnCheckbox`'s `EventCallback<bool>` is a separate ILC instantiation from `BnButton`'s `EventCallback<MouseEventArgs>`, and reflection on its `Delegate` field can be trimmed. Task 3, the probe's capturing lambda on a `BnCheckbox`.
5. **A lambda declared outside a component** (D2), here a static helper that builds the delegate. Expected: the helper's type plus the position the walk finds, with no `<` and no throw. Task 2, `ALambdaDeclaredInAHelper_NamesTheHelperAndThePosition`.

**Interfaces:**
- Consumes: Task 1's `Resolve()` returning `Lambda`, and the sequences in record §1.
- Produces:
  - In `BlazorInterop`: `internal readonly record struct FramePosition(string Control, int Sequence)` whose `ToString()` is `$"{Control} at sequence {Sequence}"`.
  - In `BlazorInterop`: `static Delegate? CallbackDelegate(object? value)`. It returns `HandlerDelegate(value)` when that is not null. Otherwise, for a boxed `EventCallback<T>` of any `T`, it reads the non-public instance field `Delegate` by reflection on `value.GetType()`. Mark it `[DynamicDependency(DynamicallyAccessedMemberTypes.NonPublicFields, typeof(EventCallback<>))]`. Any other value returns null. If the trim analyzer reports IL2075 on the `GetField` call, suppress exactly that ID, in the style of the IL2057 suppression at `:87-95`. The justification names the `[DynamicDependency]` that keeps the field and the JVM probe pin from Task 3. Record this in record §5; the final review checks it.
  - In `BlazorInterop`: `static FramePosition? FindCallSite(in ArrayRange<RenderTreeFrame> frames, System.Reflection.MethodInfo method)`. It makes one linear pass over the frames. It remembers the latest `Element` or `Component` frame as the owner. At the first `Attribute` frame where `CallbackDelegate(frame.AttributeValue)?.Method == method`, it returns that owner's position. For a component frame, the control is `ComponentType.Name` cut at the first backtick. For an element frame, it is `"element " + ElementName`. It returns null when nothing matches.
  - `HandlerCallSite` gains a leading `int ComponentId` field. `RecordCallSite` passes its `componentId`.
  - In `NativeRenderer`: `private FramePosition? CallSitePosition(int componentId, System.Reflection.MethodInfo method)`, which runs on the render thread:
    - Start at `componentId`. For each component, read `BlazorInterop.FindCallSite(GetCurrentRenderTreeFrames(id), method)`; a match REPLACES the previous one, so the outermost wins.
    - Then step up with `_tree.TryGetComponentParent(id, out var parent)` to `parent.ParentComponentId`, and stop when there is no parent.
    - The whole walk sits in a catch-all that returns null, never a partial result. An inner match with an ancestor that throws is not trusted.
  - `DispatchSubject`: when `Lambda` is not null, `owner` becomes `$"{Owner}, {position}"` when `CallSitePosition(s.ComponentId, Lambda)` returns one, and `Owner` alone otherwise.
