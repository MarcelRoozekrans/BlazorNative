# Phase 17.8 — Re-audit and close Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-audit all eleven M17 DoD items on evidence measured now on `origin/main`, then close M17 with no tag if every item is MET or MET NARROWLY.

**Architecture:**
- **No code.** This plan writes a report only.
- **Measurement.** A subagent measures the tests on HEAD. A second subagent re-derives item 11's coverage and re-reds any pin that moved.
- **Report.** An implementer writes the report.
- **Review.** A fresh reviewer re-measures a sample of the report.

**Tech Stack:** `gh`, `git`, `dotnet test` with `pwsh`, Gradle, and GitHub Actions. The host is Debian 13 x64. JNA and `ci.yml` evidence comes from CI only.

**Spec:** `docs/superpowers/specs/2026-10-21-phase-17.8-design.md`

## Global Constraints

- **Measure at the point of writing.** Every number has its command beside it.
  - The 17.6 audit and the 17.7 record are cited only as the place a mutation is recorded.
  - The 17.6 verdicts are a checklist, never a baseline.
- **M17 range:** `23ffc4ab..origin/main`. Release-please commits and dependency updates are excluded by name.
- **Red standard:** RS1, in 17.7 record §4 "Rulings", ratified by the owner on 2026-10-21.
- **Device lanes:**
  - Run on `main`'s HEAD, one at a time, and never with `&`.
  - Compare each run's `headSha`. Only attempt 1 counts.
  - Diagnose from the JUnit XML or log first. One rerun is allowed, for proven infrastructure only, and both attempts are recorded.
- **CI and #551:**
  - `ci.yml` cannot be dispatched. Its evidence is this phase's draft PR, shown docs-only with `git diff --stat origin/main <head> -- ':!docs'`, which must be empty.
  - A `ShutdownQuiescenceTests` positive-control failure is checked against #551's signature, quoted.
  - If it matches, rerun that one failed job, record both attempts, and grade item 2 MET NARROWLY citing #551.
- **Grading:**
  - Each item is graded on its DoD sentence, quoted.
  - Item 11 under RS1:
    - a missing red is NOT MET;
    - a named limit is MET NARROWLY;
    - an overclaiming cell is NOT MET.
  - Carried debt narrows an item only when it contradicts that item's words.
- **Changes:** no tag, no code changes, and no mutation left in place. Mutate in a detached worktree, and run `git status --short` empty before and after.
- **Commits:**
  - type and scope `docs(17.8):`;
  - no nested parentheses, no session URL, no closing keywords anywhere, PR body included;
  - end each body with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - parse-check with `node scripts/commit-parse-check/check.js`.

## Review Focus

- **Coverage copied from 17.7 §7 rather than re-derived.** The reviewer checks that Task 3's table was built from the register and the test files.
- **A narrowing lifted on the 17.7 record's word.** Each lifted narrowing quotes code at file:line on HEAD.
- **A green lane that predates HEAD.** Every lane cell carries its `headSha`.
- **A #551 hit graded as MET.** Its grade must be MET NARROWLY, citing #551.
- **A named limit graded MET.** Each of the three limits is MET NARROWLY unless the report re-measures it as deterministic.
