# Phase 17.3 — Activity recreation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A recreated Activity never shows a frame from the page it replaced. It stays on its page with its back stack, and a disposed root cannot navigate (#425).

**Architecture:** In .NET, a mount replaces any existing root, as one render-thread unit. It re-resolves the default component from the current route, and bumps a root generation that dispatch scopes record and navigation checks. In Kotlin, a retired runtime drops frames, and `MainActivity.onDestroy` retires the runtime.

**Tech Stack:** C# xUnit; Kotlin JVM tests on CI, through draft PRs for mutations; Android instrumented tests on the emulator lane.

**Spec:** `docs/superpowers/specs/2026-10-15-phase-17.3-design.md`

## Review Focus

- **A replacing mount on iOS** must not change iOS's single mount. The XCTest lane must stay green.
- **The JVM tests that read the first frame after `start()`.** A restart now first delivers a removal frame for the old root. Find every such test, `BackNoticeTest:232` among them.
- **Recreation during boot,** while `booted` is false. `retire()` cannot stop a boot thread still inside `start()`. Name this as not covered, or guard it.
- **Navigation outside any dispatch** keeps working: a deep link, and the startup route.
- **The unmount and the mount as one unit.** No dispatch may run between them.
