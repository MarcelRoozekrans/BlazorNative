# Phase 18.2 — Fault Attribution for Queued Work (#500) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fault in a re-render or a `RunAfterDispatch` action that dispatch A queued while its continuation ran inside dispatch B's window is A's: a late FaultNotice under A's handler id, with B keeping its own rc.

**Architecture:** Two halves.
- **Queued actions.** `RunAfterDispatch` records the flowing scope that queued each action.
- **Re-renders.** A change callback on `s_flowingScope` notices when A's flow runs inside B's window, then diffs `ComponentBase._hasPendingQueuedRender` across that interval to tag the components A dirtied. The renderer's own logger catches Blazor's Debug `RenderingComponent` call, so `HandleException` knows when a tagged render is running.
- **The Done trap.** A's completion waits for its tagged work to settle at B's window close.

**Tech Stack:** C# / .NET 10, Blazor `Microsoft.AspNetCore.Components` 10.0.14, xUnit, NativeAOT-compatible `[UnsafeAccessor]`.

**Spec:** `docs/superpowers/specs/2026-10-30-phase-18.2-design.md`. It was approved by the owner on 2026-10-30. Read it before any task: its "Background" and "Approach" sections are the contract this plan implements.

- `_hasPendingQueuedRender` joins `BlazorInterop.VerifyAccessors` and throws `BlazorVersionMismatchException`. Owner decision, 2026-10-30.
- An `AsyncLocal` change callback must never throw, because an exception there calls `Environment.FailFast`. Its body reads and writes fields only, runs no app code and never awaits.
- `AwaitWholeHandler` **awaits** the settle and never blocks on it. The settle `TaskCompletionSource` uses `RunContinuationsAsynchronously`.

## Review Focus

- **A tagged component disposed before it renders.** B's render removes it. A's pending Task must still complete, because the window releases every tag it holds. If it doesn't, A hangs forever. Owned by Task 5.
- **A's tagged component also re-rendered by B in the same batch.** Only the first render is A's, and a fault in the second is B's rc 2. Owned by Task 5.
- **A finished before its fire-and-forget continuation dirtied a component.** The fault is logged with `FinishedDispatchFaultLogLabel`, B keeps rc 0, and no notice is sent. Owned by Task 5.
- **Strict mode.** A tagged render's fault still goes to A, because attribution runs before the strict rethrow, and B is not rethrown into. Owned by Task 4: one fact runs with `strict: true`.
- **No tag outstanding.** Every existing `FaultNoticeTests` and `DispatchWindowScopeTests` fact stays green, unchanged. A tag rule that over-reaches shows up there first. Owned by Task 7.

### Task 2: Queued actions carry their queuer, and A's completion waits for its tagged work

**Model:** opus. This is concurrency across the render thread and A's pending Task: the Done trap, the settle, and lock ordering.

**Files:**
- Modify: `src/BlazorNative.Renderer/NativeRenderer.cs`:
  - `DispatchScope` (`~:1598`);
  - `RunAfterDispatch` (`~:305`);
  - `DrainPostDispatchActions` (`~:331`);
  - the nested move and the close in `DispatchSyncPart` (`~:1990-2005`);
  - `AwaitWholeHandler` (`~:2053`).
- Test: `tests/BlazorNative.Runtime.Tests/FaultNoticeTests.cs`: the 18.2 section, with new buttons on `InlineContinuationProbe`.

**Interfaces:**
- Produces, on `DispatchScope`:
  - `List<(Action Action, DispatchScope? Queuer)>? PostDispatchActions`, replacing `List<Action>?`;
  - `bool TryHold()`: under the scope's lock, returns false once `Done`; otherwise increments the outstanding count and returns true;
  - `void Release()`: decrements, and completes the settle when the count reaches 0;
  - `Task Settled()`: completed when the count is 0. Its `TaskCompletionSource` is created with `RunContinuationsAsynchronously`;
  - `Dictionary<DispatchScope, int>? Held`: on the WINDOW scope, the holds it must release at close.
- Produces, on `NativeRenderer`: `private void HoldFor(DispatchScope window, DispatchScope queuer)`, which calls `queuer.TryHold()` and on success records it in `window.Held`. Task 4 uses it for render tags.
- Produces: `private static void ReleaseHolds(DispatchScope window)`, called in `DispatchSyncPart`'s `finally` after the drain, on the outermost close only. A nested close moves its `Held` to the outer scope, exactly as it moves the queued actions.
- Routing rule, used by the drain here and by Task 4: `private void ChargeLate(DispatchScope queuer, Exception ex)`:
  - while not `Done`: `Interlocked.CompareExchange(ref queuer.LateFault, ex, null)` plus a log with `LateFaultLogLabel`;
  - otherwise: a log with `FinishedDispatchFaultLogLabel`.

  - `InlineContinuationProbe.Renderer` is a new static that `DispatchTwo` sets.

  - It holds the queuer through `HoldFor`, and queues `(action, queuer)`.

  - `AwaitWholeHandler`, after `await handler`, awaits `scope.Settled()` before it sets `Done`. Leave a clearly marked call site for Task 4's explicit flush, `scope.Owner.FlushSegment()`, as a no-op stub. Keep the `finally` that sets `Done` correct when the handler faults.

### Task 4: Tag A's re-renders and charge their faults to A

**Model:** opus. This is the `AsyncLocal` change callback, the segment diff and the `HandleException` ordering, on the render thread with inline continuations.

**Files:**

- Test: `FaultNoticeTests.cs`, 18.2 section: a `RenderTarget` child component rendered by `InlineContinuationProbe`, and new buttons.

**Interfaces:**
- Consumes: `HasPendingQueuedRender` (Task 1), and `HoldFor` / `ChargeLate` / `Held` (Task 2), and `NoteRenderingComponent` / `WantsRenderLog` (Task 3).
- Produces, on `NativeRenderer`:
  - `Dictionary<int, ComponentBase> _liveComponents`, filled in `CreateComponentState` for `ComponentBase` instances and removed beside `_componentTypes`;
  - `Dictionary<int, DispatchScope> _renderTags`;
  - `DispatchScope? _renderingFor`;
  - `internal void FlushSegment()`.
- **Segment rule.** `s_flowingScope = new(OnFlowingScopeChanged)`, a static callback. It acts only when the scope's `Owner` is running on its render thread, compared by `Environment.CurrentManagedThreadId == owner.RenderThreadId`, and has `_currentScope` non-null. Use whichever of the previous and current values is a scope.
  - **Switching to** a scope A that is not `_currentScope`: snapshot the ids in `_liveComponents` whose flag is set, into `_segmentFor = A` and `_segmentPending`.
  - **Switching away from** `_segmentFor`, or an explicit `FlushSegment()`: every live component whose flag is now set and was not in the snapshot is tagged in `_renderTags[id] = A`. `HoldFor(_currentScope, A)` is called when A is not `Done`, and the tag is kept even when A is `Done`, so the fault is logged as a finished dispatch's. Then `_segmentFor = null`.
  - A reentrancy flag guards the body.
- **Rendering-now rule.** `NoteRenderingComponent(id)` sets `_renderingFor = _renderTags.Remove(id, out var q) ? q : null`, which uses the tag up.
- **Attribution rule.** In `HandleException`, inside `if (_currentScope is { } scope)` and before the `anotherDispatchs` test: when `_renderingFor is { } queuer && queuer != scope`, call `ChargeLate(queuer, exception)` and return.
- **AwaitWholeHandler.** Replace the Task 2 stub. When on the owner's render thread, call `scope.Owner.FlushSegment()` before reading `Settled()`.
- **Window close.** `_renderTags` entries are cleared for the closing outermost window, before `ReleaseHolds`.
