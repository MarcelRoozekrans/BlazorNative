# Phase 19.2 Measurement Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a repeatable, interleaved comparison of HEAD against `v0.15.0` on cold boot,
dispatch-lane latency and frame-apply time, on both shells. Prove the marks silent at `Warn` and
present at `Verbose` on the emulator and the simulator.

**Architecture:**
- Seven `Verbose`-gated `BNPERF` marks: two in .NET through a new asynchronous `BnPerfMarks` writer,
  and five in the shells.
- A `PerfProbe` sample page, clicked by measurement test classes that are excluded from the PR lanes.
- A C# parser tool, `tools/BlazorNative.PerfReport`, that pairs the marks and writes `samples.csv`
  and `summary.md`. The design called for a `pwsh` parser; it became a C# tool because the repo has
  no PowerShell test framework, and this way its tests run in the required .NET lane.
- A `perf.yml` workflow that builds HEAD and the `perf/v0.15.0-marks` backport branch, then
  interleaves them in one emulator job and one simulator job.

**Tech Stack:** .NET 11 (NativeAOT), xUnit, Kotlin and Gradle (androidx instrumentation), Swift and
XCTest (XcodeGen), `pwsh`, `adb`, `simctl`/`log`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-22-phase-19.2-design.md`, approved 2026-11-22. It sits
under the M19 design, `docs/superpowers/specs/2026-11-17-milestone-19-design.md`.

## Global Constraints

- The mark line format is exactly `BNPERF <point> seq=<n> t=<ns>`. The dispatch points add
  ` id=<handlerId>`.
- The point names are exactly `boot.start`, `boot.content`, `dispatch.post`, `dispatch.enter`,
  `dispatch.handler`, `frame.recv` and `frame.applied`.
- Below `Verbose`, a mark is one `IsEnabled` check. It reads no clock and formats nothing.
- **Clocks.**
  - Android cross-boundary marks use `System.nanoTime()`. .NET uses `Stopwatch.GetTimestamp()`,
    converted to ns.
  - iOS cross-boundary marks use `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)`.
  - Boot uses `Process.getStartElapsedRealtime()` with `SystemClock.elapsedRealtimeNanos()` on
    Android, and `sysctl` `kinfo_proc.p_starttime` with the wall clock on iOS.
- Android shell marks use `BnPrivacy.SAFE`. iOS marks use the os_log subsystem `io.blazornative` and
  category `Perf`. .NET marks use category `Perf`.
- **ABI:** frozen at 80 B and 10 exports. No signature or struct changes.
- **Shipped code:** no test hook. The click driver exists only in test sources.
- **The Android shell's template copy** under `templates/BlazorNative.Templates/content/BlazorNative.App/android/`
  stays byte-identical to the shell, so the mirror guard holds.
- **The `samples.csv` columns** are exactly `side,sdk,commit,metric,part,run,value_ms`.
- **Runs:** `runs` is at least 20 per side. The parser fails the run on any violation of
  `dispatch.post ≤ dispatch.enter ≤ dispatch.handler`, and when more than 5% of samples are dropped.
- **Backport branch:** `perf/v0.15.0-marks`, cut from tag `v0.15.0` (`0184e1e7`). It is never
  merged and has no PR. Its app id gets the suffix `.v015` (Android `applicationIdSuffix`, and the
  iOS `PRODUCT_BUNDLE_IDENTIFIER` suffix).
- **Pinned lane counts are on HEAD:** .NET 2828 (`ci.yml:2422`), JVM 210 (`ci.yml:2897`),
  instrumented 273 (`android-instrumented.yml:1195`), XCTest 307 (`ios.yml:1502`). Change a count
  only by the tests a task adds to that lane, and give the reason on the count's comment line.
- **Commits:**
  - no Claude signature, no `Co-Authored-By` and no session link;
  - no closing keywords;
  - no nested parentheses in commit bodies;
  - push with `git push origin HEAD:docs/19.2-measurement-harness`, because another worktree holds
    the branch name.
- **Shell:** never `pkill -f`, and never `&` in Bash.

## Review Focus

1. **A frame that the click did not cause**, such as a safe-area or insets re-render that lands
   inside a click window. Expected: it is reported as a dropped sample, never paired as the click's
   frame. Tested by Task 4, `Pairing_ExtraFrameInWindow_IsDropped`.
2. **The marks at `Warn` on a device.** Expected: zero `BNPERF` lines and zero gated lines. Tested by
   the Q1 proof steps in Tasks 7 and 8, which fail their job.
3. **A clock mismatch between the shell and .NET.** Expected: the run fails and is not averaged.
   Tested by Task 4, `ClockOrderViolation_FailsTheRun`.
4. **The first launch after install** on Android, which includes dex optimisation. Expected: it is
   discarded. Tested by Task 7's boot loop, which records `run=0` as warm-up, and by Task 4,
   `WarmupRuns_AreExcludedFromSummary`.
5. **The measurement classes leaking into the PR lanes.** Expected: the instrumented count stays 273
   and the XCTest count stays 307 after Tasks 7 and 8. Checked by the pinned-count assertions on the
   draft PR.

**Interfaces:**
