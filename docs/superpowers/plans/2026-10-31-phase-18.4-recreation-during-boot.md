# Phase 18.4 Recreation during boot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Tick each box in this file as you finish its step, and commit the ticks with the step's work.** The complete-phase gate fails on unticked boxes.

**Goal:** An Android Activity recreated while a boot is still running shows its own page and works (#511). A same-key secure-storage request waits behind a pending prompt from any bridge in the process (#601).

**Architecture:**
- **One owner for the session.** A process-wide boot record makes each new boot thread join the previous boot thread, retire that runtime, and only then call `start()`.
- **`start()` takes a process-wide lock,** so two boots are never inside .NET at once.
- **One owner for the secure-storage hold.** Its executor, `held` and `pendingPrompts` move into `AndroidShellBridge`'s companion object, so every bridge shares them.
  - A pending prompt remembers the bridge that showed it.
  - A destroy that is not a configuration change denies the prompts it drops: its own, plus those whose bridge died in a configuration change.

**Tech Stack:** Kotlin, JNA, the NativeAOT `.so`/`.dll`, JUnit on the JVM (`testDebugUnitTest`, Windows CI only) and instrumented JUnit4 on the API 34 AVD lane.

**Spec:** `docs/superpowers/specs/2026-10-31-phase-18.4-design.md`. Read it in full before your task. Its D1–D6 are the rules this plan implements. The owner approved it on 2026-10-31.

## Review Focus

1. **The old boot fails** (`start()` throws, for example an unknown component). The new boot's join must still return, and the retire must still run. Neither may be skipped because the old boot never set `booted`. Task 2's pin 1b.
2. **A recreation while nothing is booting,** the ordinary rotation that 17.3 and 17.7 pin. The previous boot thread has already ended, so the join returns at once. The existing `RecreationAndroidTest` tests stay green with unchanged assertions. Task 2, Step 5.
3. **A rotation with a prompt up, then a finish.** The orphaned prompt is denied and its key released (D4). Task 3's pin 4b, plus a real-Activity variant.
4. **Two bridges and the same request id.** Test-made ids can collide across classes. A release from bridge B for id N must not free bridge A's hold for id N. Task 3's pin 3c.
5. **A held boot left behind by a failing pin** must not hang later tests. The latch is released in `@After`. Task 2, Step 1, and a reviewer reads the `@After` path.
