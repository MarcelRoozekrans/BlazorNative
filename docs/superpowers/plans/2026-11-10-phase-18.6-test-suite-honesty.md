# Phase 18.6 Test-suite honesty, part two Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Tick each box in this file as you finish its step, and commit the ticks with the step's work.** The complete-phase gate fails on unticked boxes.

**Goal:** A JVM test stuck on a lost host-call completion fails by name instead of using up the 45-minute job (#543), and every Android press that expects a handled back fails in its own main-thread turn if it also finishes the Activity (#544).

**Architecture:**
- **#543 has two layers.**
  - The hold-probe test runs its blocking back on a helper thread and joins it with a bound.
  - The Gradle test task sets a JUnit default per-test timeout in `SEPARATE_THREAD` mode, plus a task-level backstop timeout.
- **#544 is one helper.** `pressHandledBack(scenario)` in `Poll.kt` presses back and asserts `!isFinishing` in the same `onActivity` turn. Every handled-back press uses it.

**Tech Stack:** Kotlin, JUnit Jupiter 6.1.3 on the JVM (`testDebugUnitTest`, Windows CI only), AndroidX instrumented tests on the API 34 lane, Gradle Kotlin DSL, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-10-phase-18.6-design.md`. Read it in full before your task. Its D1–D5 are the rules this plan implements. The owner approved it on 2026-11-10.

## Global Constraints

- **No ABI change, no product change.**
  - The 80-byte bridge struct and the 10 exports stay as they are.
  - `BlazorNativeRuntime.dispatchHostEventAndWait` stays `internal`, test-only and untimed.
  - `BackHoldProbe.cs`, `MainActivity.kt` and the template mirror are untouched outside mutation commits.
- **Test counts do not change:** .NET 1412, JVM 209, Android 271, iOS 296. If a task adds a test, it moves the count at every site in `ci.yml`, `README.md` and the workflow headers in the same commit.
- **The timeouts are set from measurement** (D2):
  - per-test bound ≥ 3× the slowest passing JVM test;
  - task bound ≥ 2× the normal JVM step, and < 45 min;
  - starting values 120 s and 25 min. The measured values replace them if they disagree, with the reason in the record.
- **Commits:**
  - Conventional, with scope `18.6`.
  - No `Co-Authored-By` trailer, no "Generated with" line, no session link.
  - No closing keywords (`closes`, `fixes`, `resolves` followed by `#N`) in any commit. Only the PR body closes, and it closes #543 and #544 on purpose.
  - No nested parentheses in a body line.
- **Pins** are graded against `docs/pin-standard.md`, "Grading a pin: sites and reds". Every new site needs a fresh red from one subject mutation, and the red quotes its own message. Staleness is judged against each red's own commit: any edit to a test file makes that file's older reds stale, comments included.
- **Local host is Linux:**
  - The JVM suite needs the win-x64 dll, so it runs only in `ci.yml` on a PR.
  - Android instrumented tests run only in `android-instrumented.yml`, which runs only for PRs against `main`.
  - Run one lane run at a time per ref, never `&` in the Bash tool, and compare each run's `headSha` with the head.
  - Commit before any mutation run, and check `git status` is clean. A mutation helper's `git checkout` wipes uncommitted work.

## Review Focus

1. **A healthy but slow JVM test on a cold Windows runner.** The per-test bound must not turn it into a flake. Task 1 measures the slowest test from the JUnit XML and prints it on every run, so the margin is visible.
2. **A test that depends on running on the JUnit test thread**, through thread names or a `ThreadLocal`. `SEPARATE_THREAD` moves every test body. Task 1 Step 4 runs the full suite with the setting before anything else lands.
3. **The cascade after a wedged render thread.** Every later JNA test blocks in `start()`. Task 5's R1 records how long the step runs and what Gradle writes, and the backstop must end it inside 45 min with the first stuck test named in the log.
4. **The helper's elapsed time for the #346 pin.** The timing must cover `onBackPressed()` only, not the `isFinishing` read or the `onActivity` hop, or the pin's `< 1 000 ms` bound changes meaning. Task 3 Step 2.
5. **An exception thrown on D1's helper thread**, for example an `ExecutionException` from the lane. It must surface on the test thread with its cause, not as a misleading timeout. Task 2 Step 1.
