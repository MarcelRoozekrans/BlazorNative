# Phase 16.7 — Make the rc contract true (#455), by classifying the fault — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fault after a handler has begun a host call or a fetch reaches the shell as a
FaultNotice, and the dispatch returns rc 0. This holds whether the shell answers inside begin or
later. The rc contract is the same in its three copies, and a pin keeps it that way.

**Architecture:**
- `NativeShellBridge` calls a new hook, `NativeRenderer.NoteShellCallBegun()`, just before it
  begins a host call that is not a notice, or a fetch. The hook marks the current dispatch scope
  through a `[ThreadStatic]` view that is set only while a synchronous part runs.
- When such a marked synchronous part faults, `DispatchSyncPart` reports
  `DispatchOutcomeKind.FaultedAfterShellCall`.
- `Exports` turns that outcome into a FaultNotice and rc 0.
- Scheduling is unchanged: no yield anywhere.

**Tech Stack:** C# / .NET 10 (xUnit), Kotlin JVM tests (JUnit 5, JNA, NativeAOT dll), GitHub
Actions device lanes, release-please.
