# Phase 19.1 — Re-grade the 1.0 criteria Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-check every row of the 1.0 criteria file against one `main` commit, sweep the issues filed since 2026-07-24 for new blocker candidates, and rewrite the ledger and its scoreboard. The owner rules on each candidate before the PR is ready.

**Architecture:** This is a docs-only phase with two files. A new evidence log holds the working detail: one entry per row and one sweep table. The existing criteria file stays the ledger, at its current path. Tasks 1–4 fill the log. Task 5 writes the ledger and the public-consistency fixes from the log. Task 6 is the owner gate, run by the controller.

**Tech Stack:** Markdown, `git`, `gh`. A row's re-proof uses `dotnet build`, only when the cited code changed.

**Spec:** `docs/superpowers/specs/2026-11-17-phase-19.1-design.md` (approved 2026-11-17)

## Global Constraints

- The criteria file keeps its path: `docs/plans/2026-07-22-phase-11.3-one-point-oh-criteria.md`.
- The evidence log is `docs/plans/2026-11-17-phase-19.1-regrade.md`.
- Every check is made against the **anchor**, the `main` SHA recorded in Task 1. The anchor never moves during the phase.
- Never copy July's evidence forward unchecked. A row with neither an anchor `file:line` nor a re-proof is `unverified`, not MET.
- A closed issue counts as fixed only when its fix is located in the code at the anchor. Name the merged PR.
- **DOCUMENTED rows** (Q4, Q5, D3, R3, R4, S3, S4): while the row is still false, its caveat must be published in the README, under `website/docs/` or in shipped xmldoc. A file under `docs/plans/` or the tiers doc does not count.
- Candidate classes follow the file's own bar:
  - **BLOCKER:** falsifies something the project tells consumers in writing, and no honest caveat can describe it.
  - **DOCUMENTED:** a consumer-visible gap that a specific, named caveat can describe.
  - **not a candidate:** internal CI, test or tooling hygiene.
- No fixes to product code. No counts added to `README.md`, which is pinned by `ReadmeDriftTests`.
- Commits:
  - use the format `docs(m19): <subject>`;
  - carry no `Co-Authored-By` trailer, no Claude signature and no session link;
  - use no closing keywords: write issues as bare `#N`, never "fixes #N" or "closes #N".
- Shell: never `pkill -f`, and never `&`.
- Mutation re-proofs run only on a clean tree:
  1. commit first, and check that `git status --porcelain` is empty;
  2. mutate exactly one file;
  3. restore that one file with `git restore <file>`;
  4. confirm `git status --porcelain` is empty again.

## Review Focus

1. **Line drift.** A July `file:line` that now points somewhere else must be re-located by content and recorded with its new line, never marked missing because the number moved. This is pinned in Tasks 1–3, Step "re-locate".
2. **A closed issue whose fix is partial or reverted.** It must not read as MET. Pinned in Task 2, Step 3, which locates each fix at the anchor.
3. **New issues filed during the phase.** The sweep set is re-queried before the ledger is written, and any new issue gets a verdict. Pinned in Task 5, Step 1.
4. **A DOCUMENTED caveat that exists only in a plan file.** It must read "caveat missing". Pinned in Tasks 1–3, Step "caveat".
5. **Scoreboard counts that disagree with the rows.** They are recounted from the rows by command. Pinned in Task 5, Step 5.

## Evidence-log formats (used by Tasks 1–5)

Each row entry in `docs/plans/2026-11-17-phase-19.1-regrade.md` has exactly these fields:

```markdown
### <Row id, e.g. A1>

- **Cited (July):** <paths, lines, tests, PRs, issues the row's Evidence names>
- **At anchor:** `<path>:<line>`: <what it says now> (one bullet per citation; "not found" only after a content search)
- **Changed since 2026-07-24:** <`git log --since=2026-07-24 --format='%h %s' -- <paths>` output, or "none">
- **Re-proof:** <"not needed: cited code unchanged" | the command, then its red/green output in a fenced block>
- **Caveat published:** <DOCUMENTED rows only: `<public path>:<line>` | "caveat missing"; otherwise omit>
- **Proposed state:** <MET | OPEN | partial | caveat missing | unverified>: <one-line reason>
```

The sweep table has this header, with one row per issue:

```markdown
| # | Title | State | Verdict | Row / proposed class | Reason |
|---|---|---|---|---|---|
```

`Verdict` is one of `not a candidate`, `covered by <row>`, `candidate`. When the verdict is `candidate`, the next column is `BLOCKER` or `DOCUMENTED`.
