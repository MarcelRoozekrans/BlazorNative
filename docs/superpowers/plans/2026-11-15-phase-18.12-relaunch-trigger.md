# Phase 18.12 #407's relaunch trigger at its cause Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Tick each box in this file as you finish its step, and commit the ticks with the step's work.** Tick only your own task's boxes, line by line, and never with a broad `sed` over the file (the 18.6 lesson). The complete-phase gate fails on unticked boxes.

**Goal:** Prove what relaunched `MainActivity` right after the APK install in #407's run. Make the test runner wait out the install's own package changes before the first test, and prove the fix with a red and green pair. Then investigate #580's slow cold `LAContext` and settle it, either fixed at its cause or accepted with evidence.

**Architecture:**
- **Part 1, reproduce.** All runs are scratch, nothing is merged. A probe test fires one candidate trigger while `MainActivity` is up and reports whether the instance changed. A natural loop installs and starts at once, 10 times, and measures how long the post-install changes keep arriving. Task 3 then decides between "found", which continues the phase, and "not found", which stops it and reports to the owner.
- **Part 2, fix.**
  - `PostInstallSettle`, new in `androidTest`, waits until the proven signals hold still for a quiet window. Then it runs `am wait-for-broadcast-idle`, and it fails at a ceiling naming the last change.
  - `BlazorNativeTestRunner.onStart` calls it before any test, through `UiAutomation.executeShellCommand`.
  - Pins run it against a fake shell and a fake clock.
- **Part 3, #580.** A scratch iOS log capture around the first `LAContext` creation, on up to 10 fresh-boot runs. The outcome decides between a fix and an accepted residual.

**Tech Stack:** Kotlin, AndroidX Test on the API 34 `google_apis` x86_64 emulator (`android-instrumented.yml`); bash; Swift and XCTest on `ios.yml` (macOS). Neither the instrumented suite nor Swift runs on this Linux host: every device result comes from a lane run.

## Review Focus

1. **The wait passes on a failed read.** An empty or garbled `dumpsys` output must never count as "unchanged". `PostInstallSettle` fails at once on a read with no sequence number. Pin: `a_read_without_a_sequence_number_fails_at_once` (Task 4).
2. **The ceiling counts from the wrong start, or never fires,** while the signal keeps moving. Pin: `a_signal_that_never_holds_still_fails_at_the_ceiling_naming_the_last_change` (Task 4).
3. **The runner's failure is invisible.** A throw in `onStart` reaches Gradle as a bare "Process crashed". The message must be in logcat under the tag `BnPostInstallSettle`, and the lane must print those lines in its step log. This is checked on the Task 5 head run.
4. **The wait runs after the first test has started.** It must run before `super.onStart()`. The Task 6 red and green pair shows the camera test's relaunch disappearing, and the runner's log line must come before the first test's `TestRunner: started` line in logcat.
5. **A fake clock that never advances makes a pin hang** instead of failing. The fake `sleep` advances the fake clock, and every pin's run time is a few milliseconds.

**Interfaces:**

- Produces:

  ```kotlin
  internal class PostInstallSettle(
      private val shell: Shell,
      private val nowMs: () -> Long,
      private val sleepMs: (Long) -> Unit,
      private val log: (String) -> Unit,
      val quietMs: Long = QUIET_MS,
      val ceilingMs: Long = CEILING_MS,
      val pollMs: Long = 1_000,
  ) { fun await(): Long /* ms waited */ }
  internal class PostInstallSettleFailed(message: String) : AssertionError(message)
  internal const val POST_INSTALL_SETTLE_TAG = "BnPostInstallSettle"
  ```
  Each failure message starts with `post-install settle:`.

- superseded: **Step 1: Write the pins**, each against a scripted fake `Shell`, keyed by command, that returns the next scripted output per call, plus a fake clock whose `sleepMs` advances `nowMs`:
  - `a_changing_sequence_number_is_waited_out_until_the_quiet_window`: the sequence number reads 10, 11, 12, then holds. `await()` returns only once `quietMs` has passed since the read of 12. Assert that the fake clock's elapsed time is ≥ the time of the read of 12 plus `quietMs`, and that the number of reads is greater than 3.
  - `a_changing_overlay_list_is_waited_out`: the sequence number holds and the overlay output changes twice. The same assertions apply, measured from the last overlay change.
  - `a_signal_that_never_holds_still_fails_at_the_ceiling_naming_the_last_change`: the sequence number increments on every read. `assertThrows<PostInstallSettleFailed>`, and the message contains `never held still` and the last sequence value read.
  - `a_read_without_a_sequence_number_fails_at_once`: the first read is `""`. It throws on that read, with the message containing `no sequence number`, and the fake clock has not advanced past one poll.
  - `broadcast_idle_is_awaited_after_the_quiet_window`: the shell records every command. `am wait-for-broadcast-idle` is the last command and comes after the final signal read.
  - Only if `SIGNALS` contains `broadcast-history`: `a_new_broadcast_for_the_shell_is_waited_out`, the same shape as the overlay pin.
- superseded: **Step 2: Implement `PostInstallSettle`** to the signature above. It reads every signal in `SIGNALS` each poll and logs each change, as `+<ms> <signal> <old> -> <new>`, through `log`.
- superseded: **Step 3: Move the Android baseline** at every site, in the same commit as the pins. Compile with `cd src/BlazorNative.Jni && ./gradlew --no-daemon compileDebugAndroidTestKotlin` if this host can. If it cannot, say so and rely on the Task 5 lane run.
