# Phase 14.0 — Host-Event Vocabulary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the five host-event names a single manifest-sourced vocabulary that a hand-written string literal cannot re-enter, closing #300 and unblocking phase 14.2's inset event.

**Architecture:** `src/wire-vocabulary.json` gains a `hostEvents` section. `tools/BlazorNative.WireGen` emits a `BnHostEvent` enum into the existing Kotlin and Swift generated files, so `dispatchHostEvent` can take the enum instead of a `String` and a bare literal stops compiling. The public .NET surface `BnHostEvents` is **hand-written and pinned against the manifest**, never generated — following the `BlazorNativeNodeType` precedent that a generator must not be able to move a frozen public surface.

**Tech Stack:** C# / .NET 10, Kotlin (Android shell), Swift (Apple shell), xUnit, JUnit, XCTest.

**Spec:** [`docs/superpowers/specs/2026-09-21-phase-14.0-design.md`](../specs/2026-09-21-phase-14.0-design.md)

## Global Constraints

- **No ABI change.** The wire still carries a raw string; the enums are shell-side surfaces only. `nm -gU` must still find exactly **10** `blazornative_*` exports.
- **No wire-byte change.** This phase changes only how names are spelled in source. Every existing lifecycle/deep-link assertion must pass **unchanged in behaviour**. A changed wire-level assertion is a defect, not an expected update.
- **No new names.** 14.0 relocates the five that exist: `back`, `navigate`, `onResume`, `onPause`, `onDestroy`. `themeChanged` and the insets name belong to the phases that implement them.
- **Never hand-edit a `.g.*` file.** Always `dotnet run --project tools/BlazorNative.WireGen` and commit the regenerated output. `WireVocabularyCodegenTests` byte-compares and reds otherwise.
- **The Kotlin generated file has a byte-identical template mirror** at `templates/BlazorNative.Templates/content/BlazorNative.App/android/src/main/kotlin/io/blazornative/jni/BnWireVocabulary.g.kt`. `EmitAll` already writes both; regenerate in one run.
- **Public API is gated.** RS0016/17/37 are **errors** in `Directory.Build.targets`. Any public addition needs a `PublicAPI.Unshipped.txt` entry or the build fails.
- **Zero-warning bar.** The pack step tolerates no warnings — it *is* the release `validate` job. Verify with a clean rebuild, not an incremental one.
- **Every new pin must be mutation-proven.** Break it deliberately, watch it red, restore. A pin that has not been mutation-proven is not evidence — 13.1 shipped two that passed while checking nothing.

```csharp
public sealed class HostEvent
{
    /// <summary>The name as it crosses the wire. This exact string is what
    /// blazornative_host_event receives and what DispatchHostEventCore matches.</summary>
    [JsonPropertyName("name")] public string Name { get; init; } = "";

    /// <summary>"reserved" — .NET intercepts it in DispatchHostEventCore and routes
    /// it. "passthrough" — .NET never names it; it reaches the app multicast as an
    /// opaque string. Both misspelling failure modes are SILENT, which is why the
    /// tier is data rather than a comment.</summary>
    [JsonPropertyName("tier")] public string Tier { get; init; } = "";

    /// <summary>The PascalCase spelling the emitters use for an enum case or a
    /// constant. Derived, never authored: a second spelling in the manifest would
    /// be a second copy of the same truth, which is the defect this phase closes.</summary>
    public string EnumCase => char.ToUpperInvariant(Name[0]) + Name[1..];
}

public sealed class HostEventTable
{
    [JsonPropertyName("events")] public HostEvent[] Events { get; init; } = [];

    /// <summary>Every name, in declaration order — the order the emitters use.</summary>
    public IEnumerable<string> Names => Events.Select(e => e.Name);

    /// <summary>The names DispatchHostEventCore must have a routing arm for.</summary>
    public IEnumerable<string> Reserved =>
        Events.Where(e => e.Tier == ReservedTier).Select(e => e.Name);

    public const string ReservedTier = "reserved";
    public const string PassthroughTier = "passthrough";
}
```

Add the property to `WireVocabulary`, beside the existing ones:

        RequireNoDuplicates(HostEvents.Names, "hostEvents");

        // "does .NET intercept this?" unanswerable, and the dispatch-arm pin reads
        // this field to decide what it must assert.

        {

                    + $"'{HostEventTable.ReservedTier}' or '{HostEventTable.PassthroughTier}'. "
                    + "The tier decides whether DispatchHostEventCore must route the name or "
                    + "let it fall through to the app multicast; an unknown value makes that "
                    + "unanswerable and leaves the dispatch-arm pin with nothing to assert.");

            if (string.IsNullOrWhiteSpace(e.Name))
                throw new InvalidDataException("a hostEvent has an empty name");
        }

namespace BlazorNative.Core;

/// <summary>
/// The host-event names an app can subscribe to, so app code names an event
/// rather than spelling it.
/// </summary>
/// <remarks>
/// <para>HAND-WRITTEN AND PINNED, NOT GENERATED. This is public API with a
/// PublicAPI baseline; a generator able to rewrite it is a generator able to move
/// a frozen surface. <c>TheHostEventConstants_MatchTheManifest_BothWays</c> asserts
/// it against <c>src/wire-vocabulary.json</c> in both directions instead — the same
/// trade <see cref="BlazorNativeNodeType"/> makes.</para>
/// <para>Adding a name here alone does nothing: the shells send what the manifest
/// says. Add it to the manifest, regenerate, then add the constant.</para>
/// </remarks>
public static class BnHostEvents
{
    /// <summary>The user pressed system back. RESERVED — the runtime intercepts this
    /// and routes it to the navigation manager; it does not reach subscribers.</summary>
    public const string Back = "back";

    /// <summary>A deep link or notification tap asks for a route, carried as the
    /// payload. RESERVED — the runtime intercepts this and navigates.</summary>

> **Pin through the real function.** The precedent pins `BlazorNativeNodeType` "through the REAL mapping function rather than by reading the enum". - [x] **Step 1: Write the failing test**

```csharp
    [Fact]
    public void EveryReservedHostEvent_IsRoutedRatherThanFallingThrough()
    {
        // A reserved name with no arm in DispatchHostEventCore does not throw — it
        // falls through to the app multicast and is SILENTLY IGNORED. That is the
        // failure this pin exists for: the direct analogue of a style name the
        // routing table accepts that no shell applies.
        WireVocabulary v = LoadManifest();

        int checkedNames = 0;
        foreach (string reserved in v.HostEvents.Reserved)
        {
            checkedNames++;

            // With no session mounted, a ROUTED name reports "nothing to route to"
            // (rc 1) because the nav manager is null. An UNROUTED name reaches the
            // multicast, which has no subscribers, and reports success (rc 0).
            // The two are distinguishable precisely because routing happens first.
            int rc = Exports.DispatchHostEventCore(reserved, payload: null);

            Assert.True(rc == 1,
                $"reserved host event '{reserved}' returned rc {rc} with no session mounted — "
                + "expected 1 (routed, but nothing to route to). rc 0 means it fell through "
                + "to the app multicast, i.e. DispatchHostEventCore has no arm for it and the "
                + "name is silently ignored on every device.");
        }

        Assert.True(checkedNames >= 2,
            $"only {checkedNames} reserved names checked — the manifest lost entries, or this "
            + "loop stopped seeing them");
    }
```

- [x] **Step 2: Run it**

```bash
dotnet test tests/BlazorNative.Runtime.Tests --filter "FullyQualifiedName~EveryReservedHostEvent_"
```

Expected: PASS immediately — both reserved names already have arms. **This is correct and is not a wasted test.** It pins the property so the *next* reserved name cannot be added without one.

**If it fails, diagnose before adjusting — there are two very different causes.**

*Cause A — the rc contract differs from the assumption.* Read `DispatchHostBack` and
`DispatchHostNavigate`; both return 1 when `HostSession.CurrentNavigationManager` is null. Adjust
the expected rc and keep the assertion message's explanation accurate.

*Cause B — a sibling test mounted a session.* The assertion depends on **no session being
mounted**, and `HostSession.CurrentNavigationManager` is process-wide static state. If another
test in the same collection mounts one, a routed name may return 0 instead of 1 and this pin
becomes **flaky rather than wrong** — the worst failure mode for a guard, because it teaches its
readers to re-run rather than investigate.

If you observe order-dependence, do **not** paper over it with a retry or a relaxed assertion.
Put the test in its own xUnit collection so it cannot run beside a mounting test, or assert on a
signal that does not depend on ambient session state. A pin that is green depending on test order
is not evidence.
