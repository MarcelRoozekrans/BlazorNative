# Phase 14.4 — Device Observability, Docs, and the Device Lane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the framework's diagnostics observable on real hardware, build the device slice in CI and prove it is the slice we think it is, and make M14's central pin true **unconditionally** rather than for the shapes we happened to test.

**Architecture:** Four independent workstreams sharing one property — each is a place where something claims to be checked and is not. Two change test code, one changes Swift, one changes CI, one changes prose.

**Tech Stack:** C# / xUnit, Swift, GitHub Actions YAML, Markdown.

**Spec:** [`docs/superpowers/specs/2026-09-22-phase-14.4-design.md`](../specs/2026-09-22-phase-14.4-design.md)

## Global Constraints

- **No new public API, no new status value, no wire change, no ABI change.** If a task appears to need one, stop and escalate.
- **Conventional commits, scope `14.4`.** The body must contain **no nested parentheses** — release-please silently drops the entire commit when a `(` appears inside a parenthesised group, and the workflow still reports success. Never write a `claude.ai/code/session_*` URL in a commit message or PR body.
- **Zero new build warnings.** Doc warnings are errors here; a failed pack is the release `validate` job.
- **Never hand-edit a `.g.*` file.**
- **A pin that passes under its own mutation is worthless.** Every assertion added or changed must be mutation-proven. This phase exists partly because three rounds of mutations each missed the next round's shape.
- **Run every command in the FOREGROUND.** Backgrounding a `dotnet test` and waiting for a notification hangs a subagent indefinitely — it cost 30 minutes twice on the previous phase.

- [ ] **Step 3: Teach `StripComments` about string literals**

The `//` branch currently swallows to end of line unconditionally, so a `//` inside a string hides everything after it. Add string tracking to the main loop.

Add a `bool inString = false;` beside `int i = 0;`, and insert this branch **before** the `/*` branch:

```csharp
            // STRING LITERALS (F2). A `//` inside a string is not a comment — the
            // shells already contain `://` in literals, at BnDeepLink.swift:113 and
            // BnCamera.swift:415, so this is a live shape and not a hypothetical.
            // Tracking is deliberately simple: toggle on an unescaped `"`, and RESET
            // AT EVERY NEWLINE. Neither Swift nor Kotlin lets an ordinary string span
            // lines, and the reset is what BOUNDS a mis-parse to one line rather than
            // letting one stray quote blind the rest of the file. A `"""` multiline or
            // raw string toggles three times and lands `true`, which the newline reset
            // then clears — imperfect, and bounded, which is the trade being made.
            if (source[i] == '"')
            {
                bool escaped = i > 0 && source[i - 1] == '\\'
                               && !(i > 1 && source[i - 2] == '\\');
                if (!escaped) inString = !inString;
                sb.Append(source[i]);
                i++;
                continue;
            }

            if (source[i] == '\n')
            {
                inString = false;
                sb.Append(source[i]);
                i++;
                continue;
            }

            if (inString)
            {
                sb.Append(source[i]);
                i++;
                continue;
            }
```

- [ ] **Step 4: Make `ScanOccurrences` match across line breaks**

Replace the per-line loop with a whole-text match that tolerates whitespace around the `.`, deriving the line from the match offset.

Replace the body's scanning section with:

```csharp
                string stripped = StripComments(File.ReadAllText(path));

                // WHOLE-TEXT MATCHING (F1). The old scan split on '\n' first, so a
                // token wrapped across lines was invisible — and every dotted KOTLIN
                // token can wrap, because the dot leads the continuation. Swift is
                // immune only by accident: its tokens BEGIN with the dot, so a wrap
                // carries it intact. Matching whole-text with `\s*` around each dot
                // closes the Kotlin half without special-casing a language.
                var matches = new List<(string Token, int Start)>();
                foreach (string token in AuthenticatorVocabulary)
                {
                    string pattern = string.Join(@"\s*\.\s*",
                        token.Split('.').Select(Regex.Escape));
                    foreach (Match m in Regex.Matches(stripped, pattern))
                        matches.Add((token, m.Index));
                }

                foreach ((string token, int start) in matches)
                {
                    // Suppress only a TRUE span overlap with a longer token — the
                    // span rule from 14.3's fix, unchanged, now over offsets in the
                    // whole file rather than within a line.
                    bool shadowed = matches.Any(o =>
                        o.Token.Length > token.Length
                        && o.Start <= start
                        && start + token.Length <= o.Start + o.Token.Length);
                    if (shadowed) continue;

                    int line = 1;
                    for (int k = 0; k < start; k++) if (stripped[k] == '\n') line++;

                    found.Add(new Occurrence(
                        token,
                        Path.GetRelativePath(root, path).Replace('\\', '/'),
                        line));
                }
```

Note the span test now compares **regex match lengths against token lengths**. A wrapped match is longer than its token, so use `o.Start + o.Token.Length` only where the match is unwrapped; if a wrapped long token must shadow a short one, prefer comparing against the matched text length. **If you find the span rule mis-suppresses under wrapping, fix it and say so in your report** — this is the one place the plan's code may need judgement.

Add `using System.Text.RegularExpressions;` if absent.

- [ ] **Step 1: Read the pump and its call site**

Read `src/BlazorNative.Apple/BnHost/BnStderrPump.swift` — particularly the header at `:23-40` and `install()` at `:91`. Then read `HostViewController.swift:112-120`, the call site.

Note the existing design: the **XCTest** skip lives at the *call site*, with a comment explaining it is there on purpose. Your skip goes **inside `install()`** instead, and the difference is the point — the XCTest guard is about what kind of process is hosting, which the view controller knows; this one is about **fd 2 semantics**, which is the pump's own subject. It is also the only placement that is unit-testable.

- [ ] **Step 2: Add the skip**

**Placement is load-bearing — put the check at the VERY TOP of `install()`, before `lock.lock()` and before the idempotence guard.**

The tempting placement is after `installedFlag = true`, so the idempotence semantics look untouched. That is wrong, and it would introduce exactly the class of bug this phase is about: `installedFlag` would be `true` with no pipe and no `dup2`, so `BnStderrPump.isInstalled` at `:73` — a public accessor — would report an installed pump that does not exist. A flag asserting a state nothing established is the same fault as a comment asserting an unenforced property.

Checking first keeps `isInstalled` honest, keeps the flag meaning what it says, and is what makes step 4's test able to tell this return apart from idempotence.

```swift
        // OS_ACTIVITY_DT_MODE (#17). A developer who sets this is asking the OS to
        // MIRROR os_log to fd 2 so a device console can show it. Installing the pump
        // then points fd 2 at ourselves and the mirror lands in our own pipe -- so the
        // one documented route to seeing Debug and Verbose on a device is closed BY
        // US. Measured on an iPhone 17 Pro Max: exactly one UIKit line arrives before
        // install, then nothing, even at Verbose.
        //
        // Every other route is already shut: BnLog maps both levels onto
        // OSLogType.debug, which the unified log drops unless the subsystem is
        // enabled, and `log config` has no --device flag. On macOS 26 `log stream`
        // lost device support and `devicectl --console` carries only fd 1 and fd 2.
        //
        // So when the mirror is on, standing aside IS the transport. It also avoids a
        // cycle nobody should have to reason about: mirror writes fd 2, pump reads
        // fd 2, BnLog writes os_log, mirror writes fd 2.
        if ProcessInfo.processInfo.environment["OS_ACTIVITY_DT_MODE"] != nil {
            BnLog.info("native", "stderr pump: standing aside — OS_ACTIVITY_DT_MODE is "
                + "set, so os_log is mirrored to fd 2 and the pump would capture it",
                privacy: .safe)
            return false
        }
```

Confirm `BnLog.info`'s exact signature against a neighbouring call in the same file before using it — match the file, do not invent an overload.

- [ ] **Step 3: Update the header comment**

`BnStderrPump.swift:23-40` describes when the pump installs. Add the new condition, and say what the developer should do — the comment is where someone debugging this will look first.

- [ ] **Step 4: Add a test**

The pump's tests live in **`src/BlazorNative.Apple/BnHostTests/BnLogTests.swift`**, not a file of their own — `testThePumpSplitsLinesAndBuffersPartialOnes` at `:162` and its neighbour save and restore `BnStderrPump.sink` through a `defer`. Follow that idiom.

**Those tests drive `drain()` directly and never call `install()`, which is what makes this test possible at all** — `installedFlag` at `:69` is private with no reset, and the app's own `install()` call sits inside the XCTest guard, so the flag should still be `false` in the test process.

**The vacuous-pass risk is the thing to guard against.** `install()` now returns `false` for three different reasons — already installed, the new environment check, and a failed install. A test asserting only `install() == false` cannot tell them apart, and would pass for the wrong reason if anything ever installs the pump first. So assert the *state*, not just the return:

```swift
    func testThePumpStandsAsideWhenTheOsLogMirrorIsOn() {
        XCTAssertFalse(BnStderrPump.isInstalled,
                       "precondition: nothing has installed the pump in this process — "
                       + "without this the assertion below passes for the wrong reason")
        setenv("OS_ACTIVITY_DT_MODE", "YES", 1)
        defer { unsetenv("OS_ACTIVITY_DT_MODE") }

        XCTAssertFalse(BnStderrPump.install(), "the mirror is on, so the pump must stand aside")
        XCTAssertFalse(BnStderrPump.isInstalled,
                       "standing aside must not mark the pump installed — isInstalled would "
                       + "then report a pump that does not exist")
    }
```

The precondition assertion is the important line: it is what stops this becoming a test that passes while checking nothing. The second assertion is what step 2's placement rule buys you — it only holds because the check runs *before* the flag is set.

`setenv` is process-global, so the `defer` matters. **If the test proves unreachable or flaky in practice, say so in your report and ship without it** — an honest gap beats a test that poisons its neighbours.
