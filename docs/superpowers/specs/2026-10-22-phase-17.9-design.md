**Date:** 2026-10-22

**Surface:** `Mixed`
**Stage:** phase (one phase, implementation-ready)

- **Milestone:** [M17](../../planning/MILESTONE.md)
- **Scope:** #557, by owner decision on 2026-10-22. The findings come from [the 17.8 re-audit](../../plans/2026-10-21-milestone-17-reaudit.md), §11.
- **Red standard:** RS1, ratified on 2026-10-21. It is stated in [the 17.7 record §4 "Rulings"](../../plans/2026-10-17-phase-17.7-record.md).

## Goal

Every one of #557's 13 assertion sites gets a recorded red that RS1 accepts. The two overclaiming register cells come to say exactly what their rows show. After that, the 17.10 re-audit can grade item 11 MET, or MET NARROWLY on the three named limits.

## Non-goals

- New behaviour, new pins, or work on any finding outside #557.
- Reworking a pin to make it easier to red. A rework must make the pin stronger or more honest.
- Fixing the three named limits. They stay MET NARROWLY. Their register cells (`:563`, `:564`) are updated to the re-measured rates while this phase is in the file.

## Approach

1. **The red standard is unchanged.** A red is:
   - a mutation of subject code;
   - a mutation of a planted input, for drift, scan and stub pins;
   - a fixture or seam mutation, but only with RS1's clause-3 argument written in the row. The argument covers three things: no subject-side red exists, how one was looked for, and that the anchor reds with its own message.

   Every red row records:
   - the pin;
   - the exact diff;
   - the anchor entered;
   - the command or run id, with `headSha` and attempt;
   - the quoted red.
2. **F1, `FaultNoticeTests.cs:811`, the order anchor.** Record a mutation that keeps the child's begin but lets the fault come first, so the test reds at `:811` with its own message. A subject-side order swap is preferred.
3. **F2, five anchors resting on fixture or seam reds.** For each one, in this order:
   1. Look for a subject-side red and run it.
   2. If none exists, write the clause-3 argument, naming what was tried.

   These are the five anchors: `FaultNoticeTests.cs` `:809`, `:998` and `:1016`; `RecreationTests.cs:134`; and `AndroidHostCallContractTest.kt:105`, which is a device run.
4. **F3, `SlowHandlerWarningTests.cs:700`.** Record a red. For example, a dispatch that also runs the other checkbox's handler.
5. **F4, six main assertions.**
   - **The scan pins, `LogPrivacyDriftTests` `:138`, `:139` and `:174`.** Weaken each detector so it misses the planted text. This is the shape 17.7's L1 and S1 used.
   - **The planted call, `GeneratorRunTests.cs:335`.** Weaken the node-reuse detector so it misses the planted call.
   - **`SlowHandlerWarningTests.cs:701`–`:702`.** Make the wrapper fallback key by another owner, for example the tree owner, instead of the call site, so the single line no longer names `BnCheckbox`'s call site.
6. **F5 and F6, the register cells.**
   - **`docs/pin-standard.md` `:499` and `:501`–`:502`.** Correct them to what the rows show once F1 and F2 are recorded.
   - **`:552`, the renamed-executor claim.** Run it on the device lane: rename the secure-storage and biometrics executors' thread literal in the subject, and record the reds at `AndroidHostCallContractTest.kt:115` and pin 5's `:167`.

     *Builder's call:* if the rename reds an earlier line first, reword the cell to what is recorded. Do not chase the line.
7. **Coverage from git.** The record gets a coverage section, rebuilt from git. Do not build it from #557's list. It re-derives each of the 10 pins' sites with the method the 17.8 re-audit used, and shows a red row for every site. The 17.10 re-audit re-derives coverage independently again.
8. **Mutation hygiene,** as in 17.7:
   - Use detached worktrees, and check `git status --short` before and after.
   - Run device lanes one at a time, from `scratch/17.9-<id>` refs, never with `&`.
   - Kill stub processes with a `ps | grep '[x]'` pattern, never with `pkill -f`.
   - Leave no scratch refs or worktrees behind.

## Risks

| Risk | Mitigation |
|---|---|
| A red fails a different line than the one it claims | Quote the failing line and message; the reviewer checks each against the anchor |
| A missing subject-side red is assumed, not looked for | A clause-3 argument names what was tried |
| The coverage section is copied from #557 | Approach 7: re-derive it from git |
| A third pass finds more gaps | The coverage section uses the 17.8 re-audit's own method, and the reviewer re-derives a sample from git |
