# Phase 15.1 Design — `Close the nine gaps`

**Date:** 2026-09-23
**Phase:** `15.1`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [M15 — A Standard for Pins](../../planning/MILESTONE.md)
**Standard:** [`docs/pin-standard.md`](../../pin-standard.md)
**Census:** [`docs/plans/2026-09-22-phase-15.0-census.md`](../../plans/2026-09-22-phase-15.0-census.md)

## Goal

Close the nine gap facts the census found, so that every pin in the population can demonstrate its
detector still detects — not merely that its walk still walks.

## Why this phase is smaller than it was planned to be

15.1 was originally *"make the standard mechanical — a new pin that can pass while checking nothing
reds."* **15.0's enforcement verdict withdrew that goal**, and the census re-sized what remains.

Both changes came from measurement rather than opinion:

- **The mechanical check is not viable at acceptable cost.** A convention test asserting every pin
  carries a count-style assertion scores **0 of 4** against the known defects, because all four
  *already execute* one — they floor the **manifest** or the **subtracted set** while the scanned
  set stays bare. It would hand out a green over the only demonstrated false-green channel in the
  repo, under a name claiming coverage.
- **The population is in better shape than the milestone assumed.** 93 of 102 pin facts conform.
  Rule 3 predicted most pins would fail the positive-control rule; **8 of 27** do.

So this is not a sweep. It is **nine applications of one lesson**.

## The mechanism — one sentence, nine applications

> **Every uncontrolled detector in this repo is an absence assertion** — *no X survives anywhere in
> this tree*. **The fix for an absence assertion is a fixed point it must still hit**, so rewording
> the pattern past its subject reds instead of going quietly green.

A count floor proves the **walk** works — it found files. A positive control proves the
**detector** works. The census found the population has the first and lacks the second, and that
the two are routinely confused.

**Four worked examples already exist in the tree**, which is why six of the nine are borrowable
rather than invented:

- `NSLogDriftTests.TheTestBundleExemption_IsRealAndStillHoldsNSLog` — the exempt test bundle is the
  fixed point; it **must** still contain live `NSLog` calls
- the same shape in `ConsoleErrorDriftTests` and `AndroidLogDriftTests`
- and two **negative** controls — `RouteTableDriftTests.TheDuplicateRouteFixture_IsOtherwiseValid`
  and `WireVocabularyCodegenTests`' malformed-manifest pair — which sit in *non-pin* facts, so the
  model for the hardest fix is already in the tree, just outside the population

## Approach

Work in the census's §7 order, which is value per unit of work and front-loads the only real defect.

**1 — `ShellStyleTableDriftTests`, the live false green.** This is a **defect**, not a missing
assertion, and it covers **3 of the 9 gap facts**.

`ShellStyleTableDriftTests.cs:216` collects **every quoted string** in the dispatch body:

```csharp
foreach (Match name in Regex.Matches(match.Groups["body"].Value, "\"([^\"]+)\""))
    names.Add(name.Groups[1].Value);
Assert.NotEmpty(names);
```

Today that bag holds `"center"`, `"row"`, `"column"`, `"nowrap"`, `"absolute"` and two log
messages — **none of which are arms**. Yoga's *value* vocabulary overlaps its *property*
vocabulary, so a manifest style whose arm was never written **reads as dispatched** if any unrelated
quoted string matches its name.

The `Assert.NotEmpty(names)` is the shape the census named: a floor on the **subtracted** set, while
the **iterated** set — the manifest's styles — has none.

Two changes, and neither is sufficient alone: **narrow the extractor to actual arm labels** rather
than any quoted string, and **add a negative control** — a style present in the manifest with no arm
written must be reported missing. Without the second, a future widening of the extractor silently
restores the hole.

**2 — `DispatchSurfaceDriftTests.EveryDispatchNamedDeclaration_IsDeclaredOrIgnored`.** One
assertion: floor the **scanned** set. `Surface()` already asserts `methods.Count >= 4`, but that
guards the manifest-derived list, not `DispatchNamedDeclarations(source)`. This is 14.1's residual,
still open, and is **#357**.

**3 — the seven uncontrolled detectors in pin facts.** One fixed-point assertion each, six
borrowable from the worked examples. These are the phase's bulk and its easiest work.

**4 — `PinPopulationTests` itself.** It has **no positive control anywhere**, and it is the
enforcement mechanism this milestone built. A guard that cannot demonstrate its own detector works
is precisely what the standard objects to; that it is *our* guard makes it worse, not exempt. Its
Rule 5 disclosure should move from the report into the pin.

**5 — `ReleaseWorkflowPinTests`' mislabelled comment.** It calls a **subject-moved** guard *"THE
POSITIVE CONTROL"*. Correct it while fixing its detector: **any sweep grepping that phrase scores it
done**, so leaving it is a trap for exactly the work this phase is doing.

**6 — `BnSafeAreaCoverageTests`' Razor-comment false green.** Needs Razor comment handling, so this
is real work rather than reuse. Take it last of the code items.

**7 — the two uncontrolled detectors in non-pin facts.** Worth closing, scoped as doc-coverage and
purity work. They left the pin population during the census's per-fact split and **must not be
treated as having become safe** — the census says so explicitly.

**8 and 9 — decisions to record, not code.** Whether `BnRepo.cs`' by-name exemption needs its own
guard, and the `PackagePurityTests` stale-dll question, which is resolvable **by experiment** rather
than by argument.

## Tests

- **Every fixed point must be mutation-proven against its own subject.** Reword the pattern past
  what it matches and confirm the fixed point reds. A positive control that is never observed
  failing is the thing this phase exists to remove, one level up.
- **Item 1 needs both halves proven separately:** a style with no arm must be reported missing
  *with* the narrowed extractor, and the negative control must red if the extractor is widened back.
- **Every existing suite must keep its count.** These are added assertions, not changed subjects; a
  pin whose own suite changes shape has been altered rather than controlled, and that is a finding.
- **Run the mutations one at a time.** `Assert` stops at the first failure, so a batched run proves
  one mutation while still going red — indistinguishable from success. That cost a previous phase a
  review round.

## Out of scope

- **#375 — `RouteMenuDriftTests`.** Vacuous-capable and outside every mechanism the milestone built.
  Filed. Its cheap half is a floor; its hard half is **a population-key decision that must not be
  rushed inside a fix phase**, because the wrong second key reintroduces the name-based enumeration
  M15 spent a phase removing. Suggested home 15.4.
- **A mechanical enforcement of Rule 2.** Settled by 15.0's verdict; revisiting it is a new
  decision, not this phase's work.
- **The auth pin's coverage** — 15.2. **The deep-link divergence** — 15.3.

## Open Questions

None blocking. The census sized and ordered the work, and 15.0's verdict settled the one design
question this phase would otherwise have had to answer.

One item is **deliberately deferred rather than open**: whether `BnRepo.cs`' by-name exemption needs
a guard is listed as a decision to record, and recording *"no, and here is why"* is an acceptable
outcome.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **Item 1's narrowed extractor over-corrects**, missing arms that are really there | The pin reds on a correct tree, and the pressure is to widen it back — restoring the hole | The negative control is the guard against exactly that, which is why both halves ship together. Measure the arm count before and after; it must not move on an unchanged tree |
| **Seven near-identical fixes invite copy-paste**, and copies are this milestone's subject | A ninth stripper by another name | Borrow the *shape* from the worked examples, not the code. If a helper genuinely wants extracting, extract it once — Rule 8 |
| A fixed point is written but never observed failing | A positive control that proves nothing, which is worse than none because it reads as coverage | Mutation-prove each one. Non-negotiable, and it is Rule 3's own requirement |
| **The census's verdicts go stale as gaps close** | 15.6 audits against a document describing a tree that no longer exists | Update the census as each gap closes, in the same commit. It is the phase's own record |
| Counts drift between `ci.yml` and `README.md` | `ReadmeDriftTests` reds for a bookkeeping reason | They move together, always — and the step *name* moves too, which a 14.4 review caught being missed |
