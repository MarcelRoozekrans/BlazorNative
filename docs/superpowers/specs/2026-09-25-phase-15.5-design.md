## Goal

Audit every hand-written documentation page against the code as it is now, fix what has expired,
and leave behind guards that make the next expired sample or renamed identifier fail CI instead of
waiting for someone to walk past it. Land the three small corrections the milestone owes.

## Approach

### A. The audit (#291)

Each of the 20 pages is read against HEAD. Each is checked in four ways:

- every claim naming a type, a member or a count is **verified**, not skimmed;
- every version reference is removed, except under `migrating/*`, where a release is the subject;
- every code sample is classified per §B;
- **coverage the other way**: the shipped features no page mentions. #291 names
  `BlazorNative.Testing`, `BnScroll` programmatic scroll, typed lengths and the item surface. The
  audit confirms each and adds a pointer, or a short section, where a consumer would look.

**The audit record** is `docs/plans/2026-09-25-phase-15.5-docs-audit.md`. It has one row per
page, listing:

- the claims checked, with the code they were checked against;
- what was wrong;
- what changed.

"Audited" has to be inspectable. A page with nothing wrong still gets its row.

### B. The guards

**B1. Sample compilation.** This is a CI step in `ci.yml`'s `build-test` job, in the shape of
`scripts/template-smoke.ps1`.

Every fence on a hand-written page declares its kind in the info string, for example
`` ```razor bn-sample=markup ``. The kinds are:

| Kind | Compiled as |
|---|---|
| `markup` | the body of a generated Razor component |
| `code` | an `@code` block of a generated component |
| `types` | a top-level `.cs` file |
| `statements` | the body of a method in a generated static class |
| `skip:<reason>` | not compiled: signature listings, shell-language code, and the `✗` counterexamples, which compile and then throw, so compiling them proves nothing |

A script extracts the samples into a generated, gitignored project that references the in-repo
packages by project reference, and builds it. It uses the zero-warning bar the rest of the repo
uses. A sample that fails to build names its page and fence number. Samples may need shared
`using`s or a small host type; those live in one hand-written prelude file beside the generator,
never in the pages.

**B2. `DocsSamplesDriftTests`.** This is a tree-reading pin through `BnRepo.Root()`.

- **Classification is complete.** Every fence on a hand-written page carries a `bn-sample`
  value from the table, and every `skip` has a non-empty reason. An unclassified fence reds, so a
  new sample cannot avoid compilation by omission.
- **Floor:** the number of compiled samples is at least the measured count.
- **No version string on a narrative page.** A `\d+\.\d+\.\d+` version on any hand-written page
  outside `migrating/*` reds. `migrating/*` is excluded by name, never by pattern. The version
  literal inside a generated file is out of scope.

**B3. `DocsNameDriftTests`.** This is a tree-reading pin that uses reflection.

- Every inline code span on a hand-written page naming an identifier that starts `Bn` or
  `BlazorNative` must resolve, by reflection over the shipped assemblies, to a public type or a
  public member of a named type. This covers `` `BnView` ``, `` `BnScroll.ScrollTo` `` and
  `` `BlazorNativeApp.ConfigureServices` ``.
- A name that does not resolve reds, naming the page.
- **Positive control:** a planted `` `BnDoesNotExist` `` goes red through the same detector.
- **Floor:** at least the measured number of spans resolved.

Both pins carry a Rule 5 list. Its central entry: **the meaning of a sentence is not checked.**
"BnView carries the flex surface" names two real types and expires anyway. Only an audit catches
that, and the phase says so rather than implying the guards replace reading.

**Counts in prose get a rule, not a pin.** The rule goes in `CONTRIBUTING.md`: narrative pages
state no hand-maintained count and no version. Detecting "N things" in English is a regex over
prose, false in both directions. The phase record states this reasoning, which is what the DoD's
"not worth its cost" clause asks for.

## Tests

- **Unit (.NET):** `DocsSamplesDriftTests` and `DocsNameDriftTests`, each with floors and a
  positive control; the extended `IosSliceMatrixDriftTests`. The .NET count moves by measurement.
- **CI:** the sample-compilation step compiles every non-`skip` sample under the zero-warning bar.
- **Mutation (Rule 7), tables for each new pin:**
  - an unclassified fence;
  - an empty `skip` reason;
  - a version string on a narrative page;
  - a renamed identifier in a page;
  - the planted-name control;
  - the scan emptied with its floor deleted, as the vacuity contrast;
  - for F5, each new roster column changed on one leg only.
- **Live proof that compilation fails:** on the phase branch, one throwaway commit breaks a sample,
  for example a typed-length sample reverted to `Width="12px"`. Observe the new CI step go red on
  that commit's exact `headSha`, then revert with a follow-up commit. It is not dropped, so the
  branch is never rewritten.
- **Rendering check:** build the Docusaurus site locally or observe `docs.yml`, and confirm that a
  fence carrying `bn-sample=` renders with its language highlighting unchanged.
- **Regression:** the full .NET suite; JVM, Android instrumented and iOS unchanged. No shell
  behaviour moves, so any change in those counts is a finding.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Docusaurus renders a `bn-sample=` meta word visibly, or breaks highlighting | Every page with a sample looks wrong | Measure first, in the plan's first code task. Fallback: an HTML comment `<!-- bn-sample: markup -->` on the line before the fence, which Markdown never renders. The pin reads whichever form is chosen. |
| Many samples need scaffolding to compile | A large prelude that hides what a sample depends on | A prelude of `using`s and a tiny host only. A sample needing more is a sample a consumer cannot copy either, so fix the sample, not the prelude. |
| The name check over-matches: a `Bn…` span that is a *parameter value* or a CSS-like token | False reds | Scope it to identifiers shaped like `Bn` + PascalCase, optionally dotted to one member. A deliberate non-type span is written without the prefix. Recorded in Rule 5. |
| The audit turns into rewriting | The phase grows without bound | The audit fixes what is **false or missing**, never tone. The coverage additions are pointers or short sections, and each is justified by a shipped feature no page mentions. |
| #356's legend text is read as a behaviour promise | Consumers rely on "not established" as meaning something | The public XML doc says the iOS value is unestablished and points at the tracking issue. It promises nothing new. |
| Sample compilation adds CI time to a required job | Slower PRs | One small project and one build. Measure the added seconds in the plan. If material, run it as its own job inside the same required aggregator, never as a new required context. |
