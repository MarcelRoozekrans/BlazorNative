# Phase 17.6 Design — `Audit and close`

**Date:** 2026-10-17
**Phase:** `17.6`
**Surface:** `Docs`
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [M17 — Close the Dispatch Lane's Debt](../../planning/MILESTONE.md)

## Goal

Audit Milestone 17 against all eleven of its DoD items on evidence measured now on `origin/main`. Close M17 if every item is MET, or MET NARROWLY with its reason.

## Approach

16.8's method holds. What follows is what M17 adds or changes.

1. **Measured at the point of writing.** Every number is re-measured against `origin/main` when the report is written, with the command that reproduces it beside it. A phase record is cited only as the place a mutation is recorded, never as evidence that something is true now. That rule is the lesson of 17.5, where an inference from a file timestamp was written down as a measurement.
2. **Range.** M17 opened at `23ffc4ab` (#499). The ABI diff for item 10 runs over `23ffc4ab..origin/main`, on 16.8's three subjects:
   - the 80-byte bridge struct, in the C header and its C# mirror;
   - the 10 `UnmanagedCallersOnly` exports;
   - `src/wire-vocabulary.json`.

   Release-please version-string commits are excluded by name.
   **17.1's BREAKING 0.20.0 is not an ABI change.** It changed which dispatch a fault is attributed to, which is behaviour. The report records it under item 10 and grades the item on its wording.
3. **Items 3–9, the fixed issues.** For each one:
   - **The issue is closed by its phase's PR.** Shown with `gh issue view`.
   - **The DoD sentence is true of the code on `origin/main`.** Read at file:line, and quoted.
   - **The pins exist on `origin/main` and pass**, by the test run of item 2.
   - **Mutations are recorded with their anchors** in the phase record, and the pin's register row exists in `docs/pin-standard.md`. That is item 11's check, done per issue.
   - **Wording mismatches are graded as found.** One is already visible. Item 9 asks that `ReferenceFixtureBase` "fails naming the stalled command". 17.5's failure names the script, the package and the last output lines, and says which case it hit, but does not name which native command inside the script stalled. If the wording is not met, the item is **MET NARROWLY**, citing #530. *Builder's call: a DoD item is graded on its words, as 16.8 did.*
4. **Item 2, all tests passing.**
   - **.NET:** five local runs of the full suite, with `--blame-hang --blame-hang-timeout 10m`. Each run's environment records whether `MSBUILDDISABLENODEREUSE` was set; read it from the run's own process, not from a config file.
   - **JVM:** CI's `build-test` on HEAD, cited by run id and its `testDebugUnitTest` count.
   - **Device lanes:** `android-instrumented`, then `ios`, dispatched on `origin/main`'s HEAD, one run at a time.
     - Each run's `headSha` is compared with HEAD, and only attempt 1 counts.
     - A failure is diagnosed from its JUnit XML or log first. One rerun is allowed, and only for a proven infrastructure failure, such as 17.5's artifact-upload ENOTFOUND. Both attempts are recorded.
5. **Item 11, the pin standard.**
   - **Every pin M17 added** has its mutations recorded, anchors included, in its phase record (17.1–17.5), and a register row or census cell in `docs/pin-standard.md` written in that phase. The register's line range is re-measured from the file.
   - **A pin whose phase recorded it as vacuous at first** must have a later red recorded. 17.3 and 17.4 each had cases.
   - **Grading follows the 16.8 precedent:**
     - a pin with no recorded red makes item 11 **NOT MET**;
     - a partial its record names, with a reason, is **MET NARROWLY**;
     - an unnamed partial is NOT MET.
   - **Reds after a later phase changed the pin's file.** If the pin's test file or its subject file changed after the red was taken, one recorded mutation is re-run on HEAD, restored, and `git status` is checked clean. Nothing is committed.
6. **Debt.** These are open and are judged and carried with their numbers: #500, #506, #511, #522, #530, and #491, which is adjacent. Each is tested against the items it touches. If one contradicts an item's wording, that item is MET NARROWLY.
7. **Verdict.**
   - **PASS** or **PASS WITH FINDINGS** → `complete-milestone`, as its own PR. **No tag**: `CONVENTIONS.md` records `Milestone completion tags a release: no`.
   - **FAIL** → `plan-milestone-gaps`, and M17 stays open.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The report repeats a phase record's claim | The audit certifies something stale | Approach 1 |
| A device flake or runner infrastructure failure | A false NOT MET | Approach 4: diagnose first, one bounded rerun |
| A green lane predates HEAD | A false green | Compare `headSha` |
| A phase record's mutation was vacuous and never re-proven | Item 11 is passed falsely | Approach 5: check every phase's vacuity notes for a later red |
| An item graded on intent rather than its words | A soft MET | Approach 3: grade on the DoD sentence, quoted |
