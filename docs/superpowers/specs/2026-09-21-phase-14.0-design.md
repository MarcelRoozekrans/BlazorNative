# Phase 14.0 Design — Pin the Host-Event Vocabulary

**Date:** 2026-09-21
**Phase:** 14.0
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [14 — Twin Divergence, Closed Mechanically](2026-09-21-milestone-14-design.md)
**Closes:** [#300](https://github.com/MarcelRoozekrans/BlazorNative/issues/300)
**Unblocks:** phase 14.2 — the safe-area inset event needs a generated name

## Goal

Make the host-event vocabulary a generated surface that a hand-written string literal cannot
re-enter, closing #300 and removing the prerequisite that has now blocked two features in a row —
theming in 13.5 and insets in 14.2.

## Why this is not already done

#262 built the apparatus — `src/wire-vocabulary.json` as the source, `tools/BlazorNative.WireGen`
as the emitter, and `WireVocabularyCodegenTests` re-running the emitters and **byte-comparing**
against committed output, so a hand-edit of a generated file fails the required `build-test` lane.
The manifest's own `$doc` states the standard it was built to:

> Divergence stops being REPRESENTABLE rather than merely detected.

Host-event names never joined it. They live in **five** homes across three languages, under three
different naming conventions, and three of them are bare inline literals:

| name | .NET | Kotlin | Swift |
|---|---|---|---|
| `navigate` | `Exports.cs:667` `NavigateEventName` | `MainActivity.kt:82` `NAVIGATE_EVENT` | `BnNotifications.swift:76` `navigateEventName` |
| `back` | `Exports.cs:652` `BackEventName` | **inline literal** `MainActivity.kt:522` | *(iOS has no system back)* |
| `onResume` | — | **inline literal** `MainActivity.kt:360` | `BnAppLifecycle.swift:46` |
| `onPause` | — | **inline literal** `MainActivity.kt:365` | `BnAppLifecycle.swift:47` |
| `onDestroy` | — | **inline literal** `MainActivity.kt:375` | `BnAppLifecycle.swift:48` |

### The vocabulary has two tiers, and .NET only knows one

`Exports.cs:704` `DispatchHostEventCore` intercepts exactly two **reserved** names — `back` and
`navigate` — and routes them to the nav manager. Every other name falls through to
`NativeShellBridge.RaiseNativeEvent` as an opaque string the **app** matches on.

| tier | names | who names it | failure when a shell misspells it |
|---|---|---|---|
| **Reserved** | `back`, `navigate` | .NET, in `Exports.cs` | silent fall-through to the app multicast — no error, navigation simply never happens |
| **Pass-through** | `onResume`, `onPause`, `onDestroy` | nobody; the **app** string-matches | the app's handler silently never fires |

Both failure modes are silent. That is why the drift was never caught.

### The existing pins are vacuous

`BnDeepLinkTests.swift:162-164` asserts `XCTAssertEqual(BnAppLifecycle.onResume, "onResume")` — a
constant compared against its own spelling, in one language. It passes by construction and would
still pass if Kotlin said `"onResumed"`. This is the **vacuous-pin** shape phase 13.1 hit twice —
two tests that passed while checking nothing, found only by mutation-proving. These asserts are
**deleted**, not updated: updating them would preserve the appearance of coverage without the
substance.

## Decisions

1. **Both tiers are generated.** Reserved *and* lifecycle pass-through names. The lifecycle names
   carry the highest drift risk — they are the three bare literals — and they are exactly what
   13.5's `themeChanged` and 14.2's insets event will join.
2. **Enforcement is a generated enum, not a lint.** `dispatchHostEvent` takes a generated
   `BnHostEvent` in Kotlin and Swift instead of a `String`, so a bare literal **stops compiling**.
   Generation alone would be a regression against the manifest's own standard: a constant nobody is
   forced to use is detection, not prevention. The ABI still crosses as a raw string — the enum is
   a shell-side surface only, so **there is no ABI change**.
3. **The .NET constants are PUBLIC — but hand-written and *asserted*, not generated.** There is a
   fourth copy of this vocabulary nobody had counted: the **app**. Lifecycle names exist so app
   code can subscribe to them, and app code matches raw strings. Generating into three framework
   languages and stopping leaves the consumer holding the literal — the same defect one layer out.
   Pre-1.0 is the cheap window and the surface freezes at 1.0.

   **The mechanism follows the repo's existing precedent rather than inventing one.**
   `BlazorNativeNodeType` is the identical situation — a public, PublicAPI-baselined .NET surface
   mirroring a manifest vocabulary — and `WireVocabularyCodegenTests` records the ruling:

   > generating it would mean **a generator that can move a frozen surface**. It is pinned
   > instead — and pinned through the **REAL mapping function** rather than by reading the enum,
   > so this fails if either the enum or FrameEncoder's switch drifts from the manifest.

   `BnHostEvents` is therefore **hand-written with hand-written `///` docs**, and pinned against
   the manifest by a test. Two consequences: no generator can silently alter a frozen public
   surface, and **the CS1591 hazard disappears** — nothing is emitted, so there is nothing to
   emit docs for. The Kotlin and Swift enums remain generated; they are shell internals, not the
   .NET package's public API.
4. **One `hostEvents` section with `tier` as a field**, not two sections. Two sections would force
   every future name to pick its tier before its semantics are known, and 14.2's insets event is
   genuinely ambiguous — pass-through today, plausibly reserved later.

## Approach

**The manifest gains a `hostEvents` section.** Each entry is `{ "name", "tier" }` where `tier` is
`reserved` or `passthrough`. No `doc` field: its only justification was emitting `///` onto
generated public members, and decision 3 means nothing public is generated. The prose lives with
the hand-written constants, where a human writes it once.

**Three generated outputs**, joining the existing style/scroll-ignore/node-type emitters:

- a Kotlin `BnHostEvent` enum carrying a `wireName`, into the existing `BnWireVocabulary.g.kt`;
- a Swift `BnHostEvent` enum likewise, into the existing `BnWireVocabulary.g.swift`;
- the byte-identical **template mirror** at
  `templates/BlazorNative.Templates/content/BlazorNative.App/android/.../BnWireVocabulary.g.kt`,
  which the existing mirror guard already enforces.

**And one hand-written output:** a public `BnHostEvents` static class of `///`-documented
`const string` in `BlazorNative.Core`, so apps write `BnHostEvents.OnPause` instead of
`"onPause"`. Hand-written per decision 3, and pinned against the manifest by a test.

**Three guards, layered — each closing a different hole:**

| guard | catches | status |
|---|---|---|
| `WireVocabularyCodegenTests` byte-compare | a hand-edit of a **generated file**, or a manifest edited without regenerating | already exists; extends for free |
| the enum signature | a hand-written **literal at a call site** | new — this is what makes divergence unrepresentable |
| a `BnHostEvents` assertion pin | the **hand-written public surface** drifting from the manifest | new — the direct analogue of `TheNodeTypeEnum_MatchesTheManifest_IdForId` |
| a dispatch-arm pin | a **reserved name with no routing arm** in `DispatchHostEventCore` | new — the direct analogue of `AndroidSetStyleDispatch_HasAnArmForEveryYogaStyle`, which the manifest's `$doc` already cites as the pin that makes the other half fail loudly |

Both new pins follow the precedent's second rule as well as its first: **pin through the real
function, not by reading the declaration.** The dispatch-arm pin drives `DispatchHostEventCore`
and asserts on its routing behaviour rather than grepping for a `switch` arm — otherwise it is a
pin that reads the thing it is meant to check, which is how the vacuous asserts in
`BnDeepLinkTests` came to exist.

That third guard closes the reserved tier's silent fall-through. It is the same defect the styles
apparatus already solved — *a name the table accepts that nothing applies* — and it is worth
solving the same way rather than discovering it later on a device.

**Call sites migrate.** `Exports.cs`'s two `internal const`s give way to the generated public ones;
`MainActivity.kt`'s three inline literals and its `NAVIGATE_EVENT` become enum cases;
`BnAppLifecycle.swift`'s three constants and `BnNotifications.navigateEventName` fold in. The
vacuous asserts are deleted.

**One wrinkle, deliberately kept.** iOS has no system back, so the Swift enum carries a `.back`
case the Apple shell never sends. That is correct — the vocabulary is the union of what the wire
admits, not what one shell happens to use. Recorded so nobody "cleans it up" and reintroduces a
per-shell subset, which is a divergence by another name.

## Tests

- **Unit (.NET):** `WireVocabularyCodegenTests` extends to the new emitters — re-run and
  byte-compare. New: the **`BnHostEvents` assertion pin**, asserting the hand-written public
  constants match the manifest name-for-name in both directions — no constant without a manifest
  entry, no manifest entry without a constant. New: the **dispatch-arm pin**, driving
  `DispatchHostEventCore` and asserting every `tier: reserved` name routes rather than falling
  through to the app multicast.
- **Unit (JVM):** the Kotlin enum's `wireName` values byte-match the manifest.
- **Integration (Swift/XCTest):** lifecycle dispatch still produces the same wire names end to end
  — `BnAppLifecycle` → `dispatchHostEvent` → the recorded name.
- **Regression:** the existing deep-link and lifecycle suites must pass **unchanged in
  behaviour**. This phase is a pure refactor of *how names are spelled in source*; not one wire
  byte moves. If any wire-level assertion changes, that is a defect, not an expected update.
- **Mutation-proof each new pin.** Deliberately misspell one name in one language and confirm the
  relevant guard reds. A pin that has not been mutation-proven is not evidence — 13.1 shipped two
  that passed while checking nothing.

## Open Questions

None blocking. Two judgement calls are recorded above rather than deferred: the `.back` case being
present-but-unused on Swift (decision: keep), and `tier` as a field rather than two sections
(decision 4).

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **The hand-written public surface drifts from the manifest** — decision 3 trades a generator for a human, and humans forget | A name exists for apps that no shell sends, or a shell sends one apps cannot name | The `BnHostEvents` assertion pin, mutation-proven. This is the cost the precedent accepts deliberately: a drifting mirror caught by a test beats a generator able to move a frozen public surface |
| **~~CS1591 on a generated public file~~** — *retired by decision 3.* Had `BnHostEvents` been generated, public members demanding XML docs would have met the repo's finding that **no per-file lever works**, and the zero-warning pack bar **is** the release `validate` job — how 0.9.0 orphaned | — | Nothing public is generated, so nothing needs emitted docs. Recorded rather than deleted so the next person to propose generating a public surface finds the reason it was not |
| **PublicAPI baseline churn hides something** | A public surface lands without review | Read the `PublicAPI.Unshipped.txt` diff as an API review, the way 13.0 read its baseline diff. The addition should be exactly one type and N constants — anything else is a mistake |
| **The enum signature change is wide** | Every `dispatchHostEvent` call site in both shells changes at once | It is compiler-enforced: this is the one refactor where the compiler finds every site for you. A missed site cannot compile |
| **Generated sources are not written to disk by default** | The generator appears to work while the build silently skips compilation | Verifying a source generator needs `-p:EmitCompilerGeneratedFiles=true` **and** `--no-incremental`. WireGen is a `dotnet run` tool rather than a source generator, so this applies only if the shape changes — noted because the trap has bitten here before |
| **The template mirror drifts** | CI reds on the byte-identical mirror guard | Regenerate both copies in one `dotnet run`; the guard exists precisely to catch a half-done regeneration |
| **Scope creep into 14.2** | The phase grows an insets event it was not scoped for | 14.0 adds **no new names**. It relocates the five that exist. `themeChanged` and the insets name are added by the phases that implement them |
