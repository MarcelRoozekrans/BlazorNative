## Goal

Every pin M18 added has a fresh, quoted red at each graded site, #568's last three register cells are fixed, and M18 is audited against its DoD on that head, then closed if it passes.

## Decisions

| Question | Decision | By |
|---|---|---|
| Which stale reds are re-run | **M18 pins only.** Every stale red on a pin added by an M18 phase (18.1 to 18.10) is re-run. Pre-M18 pins keep their cells that name stale reds; the DoD grades new pins only. | Owner, 2026-11-14 |
| How the work is split | **One PR, two stages.** Stage 1 takes the fresh reds and fixes the cells; stage 2 audits on the same head. | Owner, 2026-11-14 |
| Population source | Derived from git, not from the phase records (see Approach 1). | Coordinator call: a record is a snapshot, so the population is re-measured |

## Why

- **#568.** Three register cells in `docs/pin-standard.md` still cite a stale red without naming it stale: the 17.2 M5 cell, the 17.7 `!= main` contrast cell and the 17.7 §3 M1 cell. The fourth was fixed in 18.8. Each of the three sites already has a fresh red on record (17.9 §3 D2; the 17.8 re-audit §11d D1 and D4), so the fix only cites them. Their line numbers have moved since the issue was written.
- **DoD "Every new pin conforms".** Rule 7 part 4: a red is stale once its test or subject file changed after the red's own commit. Later M18 phases edited shared subjects, so reds that M18 pins cite went stale within the milestone. Known examples: 18.3's contract mutations and 18.4's H1 to H5 (`AndroidShellBridge.kt`, changed in 18.4 and 18.7), 18.1's W1 and W5 (`BnBiometrics.swift`, 18.7), every `FaultNoticeTests` red taken before 18.9, and 18.1's #444 diagnostics plus the old "show never completed Granted" message quoted in the 18.5 and 18.8 records (18.10). Non-M18 commits in the range count too: `#690` added net11.0, `#627` changed coverage collection, and dependency bumps touched build files.
- **DoD flake bullet.** The box stays open until the re-audit's own CI runs show attempt 1 green on every lane with none of the #551, #564, #453, #444 or #407 signatures.

## Approach

### Stage 1 — fresh reds (the re-run record)

1. **Freeze a head.** Stage 1 starts from `origin/main` at the cut (`da6f8c1d`, or a later main if it moves before the plan executes). Any later code change on the branch restarts the staleness check for the files it touches; the branch is docs-only past this point except for scratch mutation commits that are never pushed to it.
2. **Population, from git.** Every test (fact, `@Test`, XCTest method) added or materially changed by an M18 squash: `5a7ab54a` (18.1, #584), `d246778f` (18.2), `2eb3f22d` (18.3), `0b430432` (18.4), `2cc6801d` (18.5), `d7fdf937` (18.6), `ff39e209` (18.7), `d9bf0711` (18.8), `a1bacd6b` (18.9), `da6f8c1d` (18.10). Derive the list from each squash's diff of test files, then compare it against the phase records' pin lists. A pin in one list and not the other is a finding to resolve, not a silent skip. "Materially changed" means a new or changed assertion; a moved line alone is not.
3. **Sites.** The written unit, `docs/pin-standard.md` "Grading a pin: sites and reds" part 1: every labelled anchor and every assertion carrying a claim in the test's name. Nothing broader (#562).
4. **Staleness check.** For each site's cited red, run `git diff --stat <red-commit> HEAD -- <test-file> <subject-file>`. Empty means fresh: cite it as is. Any output means stale: re-run it.
5. **Re-runs.** One mutation per red, RS1 (part 2), the site's own assertion failing at its own line with its own message (part 3). Where the original mutation no longer applies, write the nearest subject-side mutation and say so. Where to run:
   - **.NET:** locally on Linux, both TFMs (net10.0 and net11.0); the Linux host needs `pwsh` as a dotnet tool.
   - **JVM:** locally.
   - **Android instrumented and iOS:** scratch refs on CI. ios.yml and the Android lane run one ref at a time, so batch mutations per lane run where they do not mask each other (a mutation that crashes the process masks every later site; those run alone). Swift cannot compile on this host.
   - Every mutation is applied on a clean tree with its own commit, then reverted, on a clean tree only.
6. **Record.** `docs/plans/YYYY-MM-DD-phase-18.11-record.md`, in the 17.11 record's shape: per pin, each site with its red id, commit, run id or local command, and the quoted failure message. Reds found fresh are listed with the diff that proved them fresh.
7. **Register cells.** Each M18 cell in `docs/pin-standard.md` cites the fresh reds. A stale red the cell still mentions is named stale, with its re-run beside it. #568's three cells get the same treatment, citing the existing re-runs, at their current lines.

### Stage 2 — the M18 audit

The report is `docs/plans/YYYY-MM-DD-milestone-18-audit.md`, mirroring the 17.12 re-audit: a scorecard first, then one section per DoD item, every number measured on the audited head with its command shown.

| DoD item | How it is graded |
|---|---|
| All planned phases complete | ROADMAP and MILESTONE states, plus each closing issue's state from `gh` |
| All tests passing, both device lanes, `headSha` | The PR's own lanes on its final head, `headSha` compared against the PR head; one local .NET run, both TFMs. Expected counts .NET 2828, JVM 210, Android 273, iOS 307, re-measured |
| CI flakes fixed at cause | Each of #551, #564, #453, #444, #407: cause, fix commit, pin, and that no bound was raised to hide it. The last bullet: the PR's own runs at attempt 1 on every lane, each log searched for the five signatures |
| #500, #506, #511, #522, #543/#544, #401/#396, #530 | Re-read the fix's code and its pins on HEAD, as 17.12 did, and re-check each closing issue's state |
| #568 fixed | No register cell cites a stale red without naming it stale; checked by running the staleness diff on every red each cell cites, not only the three |
| No ABI change | The 80-byte struct and the 10 exports diffed across `5af84d3d..HEAD`; any wire addition traced to `src/wire-vocabulary.json` |
| Every new pin conforms | Graded on the stage 1 record: every site has a fresh RS1 red with its quoted message; its register cell was written in the phase that added it; staleness checked against each red's own commit. A sample of the stage 1 reds is re-run by a different subagent than the one that took them |

**Verdict.** PASS or PASS WITH FINDINGS: run `complete-milestone` (no tag, per `CONVENTIONS.md`; release-please owns releases) in this same PR's tail or as its own follow-up, as the owner chooses at the time. FAIL: stop and ask the owner; no gap phase is opened by the process.

**Findings.** A defect found in code is filed with file and line, not fixed in this docs phase, unless it is a doc or cell fix that belongs to this phase's own surface. Findings the review loop can fix are fixed here.

### Calls made for the builder

These were settled by the coordinator after the builder check; the owner can overturn any of them.

- **CI on a docs-only PR.** No workflow has a path filter: `ci.yml` runs on every `pull_request`, and `ios.yml` and `android-instrumented.yml` run on PRs against `main`. So the PR's own lanes run all four suites.
- **Which head is graded.** The audit grades the lanes of the head it names. The report is committed after those runs, so the head that carries it is a docs-only commit after the graded head. Its own lanes must also pass at attempt 1 before merge. The PR body and STATE.md record that, but the report does not, because it cannot cite runs on the commit that contains it. Every push starts a new attempt 1, and a flake on any graded head is reported, not re-run away.
- **Scratch-ref device runs.** Both device lanes take `workflow_dispatch`, so a mutation batch is pushed to a scratch branch and dispatched with `gh workflow run --ref`. `ios.yml` cancels in-progress runs per ref, so the plan uses one ref per batch and one run per ref at a time. Scratch branches are deleted after the record cites their run ids.
- **A pre-M18 test changed by an M18 squash.** Only the sites the M18 change added or altered are graded: a new or changed assertion, or a name clause it added. The rest of the test stays under its pre-M18 cell.
- **A red whose commit cannot be resolved** (a squashed or deleted ref). On an M18 pin it counts as stale and is re-run. On a pre-M18 pin, its cell names it stale.
- **The #568 sweep finds a pre-M18 cell that cites a stale red without saying so.** The cell is fixed in this PR to name the red stale. It is not re-run, because the M18 DoD grades only new pins. The #568 item is graded on the result.
- **A re-run that uses a different mutation from the original.** The cell keeps the old red, names it stale, and cites the re-run beside it, as `:537` and `:555` already do.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| main moves under the branch and stales a fresh red | Reds cited as fresh that are not | Re-run the staleness diff for every cited red on the final head, as the last stage 1 task and again in the audit |
| A mutation masks later sites in a batched device run | A site counted red that never failed at its own line | Check each site's own message in the log; run crashing mutations alone |
| Device lane flakes during re-runs | Misread reds, or a lost run | A scratch-ref run is evidence only for the site whose message it shows; a flake hit is noted against its issue and re-run once |
| The population from git disagrees with the records | A pin missing from grading | Treat each disagreement as a finding and resolve it in the record |
| The PR's own lanes hit a flake signature | The flake bullet cannot be graded MET | Diagnose against the signature; it is graded honestly (MET NARROWLY or NOT MET), never re-run into green silently |
| Swift-only reds can't be checked locally | Slow iOS loop | Batch iOS mutations; open the draft PR early so device lanes run per PR against main; device lanes run only for PRs against main |
