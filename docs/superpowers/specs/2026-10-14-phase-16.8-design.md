# Phase 16.8 Design — `Re-audit and close`

**Date:** 2026-10-14
**Phase:** `16.8`
**Surface:** `Docs`
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [M16 — Unblock the Dispatch Lane](../../planning/MILESTONE.md)
**Precedent:** [the 16.5 design](2026-10-01-phase-16.5-design.md) and
[the 16.5 audit](../../plans/2026-10-01-milestone-16-audit.md), verdict **FAIL**: 7 MET, 2 MET
NARROWLY, 1 NOT MET.

## Goal

Re-audit Milestone 16 against all ten DoD items on evidence measured now on `origin/main`, after the
gap phases 16.6 (the pin standard) and 16.7 (the rc contract, #455). Close M16 if every item is MET,
or MET NARROWLY with its reason.

## Why a full re-audit (owner decision, 2026-10-14)

Seven items were MET on 2026-10-01 evidence. Since then, 16.6 changed about 25 pins and 16.7 changed
dispatch code, so a MET from that date is a snapshot. Every item is re-measured. None is carried
forward by citation. The 16.5 audit is cited for its method and its earlier findings, never as
evidence.

## Approach

16.5's approach holds, items 1–8 of its design. Only what differs is recorded here.

1. **Measured at the point of writing.** Every number is re-measured against `origin/main` when the
   report is written, with the command that reproduces it beside it. Nothing is copied from a phase
   record, ROADMAP, STATE.md or the 16.5 audit.
2. **Range.** M16 opened at `3757d0e` (#421). The ABI diff (item 9) runs over
   `3757d0e..origin/main`, over the same three subjects as 16.5: the 80-byte bridge struct in the C
   header and its C# mirror, the 10 `UnmanagedCallersOnly` exports, and `src/wire-vocabulary.json`.
   Release-please version-string commits are excluded by name.
   **16.7's rc change is not an ABI change.** 0.18.0 is BREAKING because the meaning of rc changed
   for a fault after a begun call. That is the behaviour item 7 asks for, and the owner chose it on
   2026-10-01. Item 9's wording is the struct, the exports and the vocabulary, verified by diffing.
   The report records the rc change under item 9 with this reason, so it is visible, and grades
   item 9 on its wording. *(Builder's call.)*
3. **Item 7, #8 and #455.**
   - #455 was fixed by #465: a fault after a handler began a host call or a fetch is a FaultNotice
     with rc 0. The audit checks the contract wording in all three copies against the code, and
     cites `RcContractCopiesTests`.
   - **#464 (owner decision: grade it, do not block).** #464 is a defect 16.1 introduced. A fault
     from a continuation that runs inline inside another dispatch is reported under that dispatch,
     and that dispatch's own fault is lost. The audit grades it against item 7's "a fault after
     the first await reaches `onError`". If it contradicts the wording, item 7 is **MET NARROWLY**
     citing #464. It does not block closing M16.
4. **Item 2, all tests passing, and #454 (owner decision: re-measure, grade as found).**
   - **Local .NET:** five runs of the full suite, as in 16.5. **This host is Linux**, and #454 was
     only ever observed on Windows, so the report says the local runs are weaker evidence for #454's
     absence. If any run hangs, item 2 stays **MET NARROWLY** citing #454.
   - **JVM:** the JVM lane cannot run on this host (#491), so the JVM evidence is CI's `build-test`
     job on HEAD, cited by run id and its `testDebugUnitTest` count.
   - **CI and the device lanes are the binding evidence.**
   - **If all five local runs pass, item 2 is MET** on CI and the lanes, and the report states the
     host caveat. Linux runs that pass do not make the item narrow. *(Builder's call, from the
     DoD's wording: it names .NET, JVM and the device lanes, not a host.)*
   - #491, the JVM lane being Windows-only, predates M16 and is not a DoD item. The report lists it
     as adjacent, not as carried debt.
5. **Item 10, the pin standard.**
   - The 16.6 population of 38 distinct pins, 39 list entries: the
     [16.6 record](../../plans/2026-10-01-phase-16.6-record.md) must hold a red on current code for
     each one, partials named.
   - The pins 16.7 added: the [16.7 record](../../plans/2026-10-02-phase-16.7-record.md) must hold
     each one's mutations.
   - The register in [`docs/pin-standard.md`](../../pin-standard.md) must cite both. Its line range
     is **re-measured**: the 16.5 audit's `awk 'NR>=396 && NR<=498'` is stale, since the register
     now ends at about line 514.
   - **Reds after 16.7.** A 16.6 red stands if neither the pin's test file nor its subject file
     changed between the commit the red was taken on and HEAD, shown by `git diff --stat` per pin.
     For a pin where either changed, one of its recorded mutations is re-run on HEAD and its red
     recorded in the report. The mutation is restored, and `git status` is clean before the next
     one. No mutation is committed, so the phase stays docs-only. *(Builder's call: it applies
     Approach 1 to item 10 without redoing 16.6.)*
   - **Grading, the 16.5 precedent.** A pin with no recorded red on current code makes item 10
     **NOT MET**. A partial that its record names, with a reason, is **MET NARROWLY**. A partial
     that is not named is NOT MET. *(Builder's call: this is how 16.5 graded item 10, and the owner
     accepted that verdict.)*
6. **Device lanes.**
   - `android-instrumented`, then `ios`, are dispatched on `main`'s HEAD, one run at a time.
   - Each run's `headSha` is compared with HEAD. Only attempt 1 counts, unless a rerun is allowed.
   - A failure is diagnosed from its JUnit XML or log before any rerun. Exactly one rerun is allowed,
     only for a proven infrastructure failure or #444's or #453's known signature, and both attempts
     are recorded.
7. **Carried debt.** These are open, judged and carried with their numbers: #424, #425, #426, #427,
   #435, #440, #444, #453, #454, #458 and #464.
   - #425 is tested against item 5, one thread owns the renderer.
   - #440 is tested against item 4, no main-thread caller blocks.
   - #464 is tested against item 7.
   - Where one contradicts an item's wording, that item is MET NARROWLY with the issue cited.
8. **Verdict.**
   - **PASS** or **PASS WITH FINDINGS** → `complete-milestone`. **No tag**: `CONVENTIONS.md`
     records `Milestone completion tags a release: no`.
   - **FAIL** → `plan-milestone-gaps`, and M16 stays open.
