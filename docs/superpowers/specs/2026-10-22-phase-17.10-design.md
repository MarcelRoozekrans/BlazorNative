## Approach

1. **Items 1 and 3–10.** Re-measure on HEAD as 17.8 did:
   - item 10 by its three diffs over `23ffc4ab..origin/main`;
   - the narrowings on items 4, 6, 8 and 9 by quoting code and checking each issue's state.

   This is short, because the code is unchanged.
2. **Item 2, tests on HEAD.** The device lanes run on this phase's PR, which is docs-only against HEAD. Both lanes run there automatically.
   - **What counts:** compare `headSha`; only attempt 1 counts.
   - **#551:** a hit is handled by the #551 rule. It is diagnosed against the signature, its job is re-run once, and item 2 becomes MET NARROWLY citing #551.
   - **Local runs:** one local .NET run, not five. The five-run soak existed for #454, which is closed.
3. **Item 11, re-derived across the whole M17 population, per assertion statement.**
   - **The risk.** 17.9 found unredded sites in a pin that 17.8's unit had not counted. The owner's ruling, applied per assertion statement, can therefore reach pins outside #557's 10.
   - **The population.** Every test method the M17 phase PRs added: #503, #507, #510, #514, #523, #528, #545 and #560. #560 adds none.
   - **The unit.** For each pin, every labelled anchor and every assertion statement that its name or summary claims.
   - **The check.** Each site maps to a red that RS1 accepts, in some phase record. The cells must not claim more than their rows.
   - **Independence.** The re-auditor builds this from git and the test files, then compares it with the 17.8 map and 17.9 §4. Every disagreement is listed.
   - **Moved pins.** A pin whose test or subject file changed after its red is re-redded on HEAD. Since 17.8, that is the 0.20.2 bump only, so expect none.
   - **Named limits.** The three named limits stay MET NARROWLY at 11 of 15, 11 of 15 and 6 of 6. Cite the 17.8 measurement; do not re-run.
4. **Debt.** Carry #500, #506, #511, #522, #530, #543, #544 and #551, plus #491 as adjacent, each with the M18 phase planned for it. #551 has now hit 3 times. The report notes the owner's option to move it first in M18.
5. **Verdict.**
   - **PASS or PASS WITH FINDINGS:** run `complete-milestone` as its own PR, with no tag, then plan M18.
   - **FAIL:** run `plan-milestone-gaps` again.
