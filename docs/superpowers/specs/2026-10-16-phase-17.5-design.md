# Phase 17.5 Design — `Test-infrastructure honesty`

**Date:** 2026-10-16
**Phase:** `17.5`
**Surface:** `Infra`
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [M17 — Close the Dispatch Lane's Debt](../../planning/MILESTONE.md)
**Issues:** #454, #424 and #458.

## Goal

No local test run can hang silently, test a stale native library, or fail with a bare message. When one of them breaks, the person running it learns what broke and where.

## What was measured, 2026-10-16

### #454

The 2026-10-15 Linux hang left two dumps in `~/bn-454-dumps/`.

- `dotnet_921920` is **`pwsh`**, not the publish. On Linux, `pwsh` is a dotnet global tool, so its process is named `dotnet`. The issue's 2026-10-15 comment called this dump the publish; it was wrong, and that comment gets corrected.
- Its pipeline thread is in `NativeCommandProcessor.Complete` → `ConsumeAvailableNativeProcessOutput` → `DequeueProcessOutput` → `BlockingCollection.Take`. It is waiting for EOF on the output pipe of a native command it launched.
- **The native command, `dotnet publish`, is in no dump**, so it had already exited.

That is the same picture as the 2026-10-01 Windows dumps. On both OSes the publish exits, and something it started still holds the write end of its output pipe. pwsh never sees EOF and never exits. The test fixture waits on pwsh with no bound, so the run hangs silently.

**The suspect is an MSBuild worker node.** With node reuse on, a node the publish launches outlives it for minutes, holding whatever handles it inherited. Persistent `MSBuild.dll` nodes were running during the Linux hang. One prior standalone run with a fresh node did not hang, so the mechanism is **not proven**. It is the one candidate that explains an exited publish plus an open pipe, and an intermittent hang: a new node is launched only when no idle node can be reused.

### #424

`src/BlazorNative.Jni/build.gradle.kts` points the JVM `Test` tasks at the win-x64 publish through `jna.library.path`, and declares no task input for the DLL. A changed DLL leaves `testDebugUnitTest` UP-TO-DATE.

### #458

There are now **10** private `pollUntil` copies under `src/BlazorNative.Jni/src/androidTest/.../shell/`: the 8 the issue lists, plus `RecreationAndroidTest` and `FaultNoticeLogAndroidTest`, which 17.3 and 17.4 added.
- Only `BackAndroidTest`'s copy names a destroyed Activity.
- `BootWait.kt`, from #514, shows the shared-helper shape that already works in this source set.
- `BnGeolocationTests.swift:219` still asserts a bare status pair.

## Approach

### #454 — the reference fixture can never hang silently, and the publish cannot leave a pipe holder behind

1. **Root fix, in `scripts/generate-reference.ps1`.**
   - Every MSBuild invocation the script runs is passed `-nodeReuse:false`, and the script sets `MSBUILDDISABLENODEREUSE=1` for itself. Its `dotnet publish` is the one today.
   - No MSBuild node can then outlive the publish, so when the publish exits, nothing it started still holds its pipe.
   - The cost is a few seconds per reference generation. Node reuse buys nothing in a one-shot publish.
2. **Bound, in `ReferenceFixtureBase`.**
   - Both streams are read asynchronously, and `WaitForExit` gets a bound.
   - On expiry the fixture kills the process tree and fails with a message that names the script, the package, the bound, and the last lines of captured output.
   - The bound is **5 minutes per generation**. The generator takes 6–8 s standalone. The soak also records the slowest generation, and the bound is re-checked against that number in the record.
   - This holds whatever the cause. A stalled child becomes a named failure, never a one-hour silence.
3. **Diagnosis evidence, not a pin.** The controller runs it locally.
   - After the fix, run the full local suite **20 times** on Linux. Before the fix: 1 hang in the Linux runs counted on 2026-10-15, and 3 in 6 on Windows.
   - Record the result in the record, together with a corrected comment on #454 that states what was and was not proven.
   - If a hang still occurs, the bound turns it into a failure naming the stalled step, and the issue stays open with that evidence.

### #424 — a changed native library always reruns the JVM tests

1. The JVM `Test` tasks declare the win-x64 publish output as an input, with `inputs.files(...)` and relative path sensitivity. Changing the DLL invalidates `testDebugUnitTest`.
2. The same input goes on the `JavaExec` tasks that set the same `jna.library.path`: `runPreviewHost` and `runInspectorHost`. *Builder's call.*
3. **No missing-DLL check.** The issue lists it as optional. Nothing in the source set marks which JVM test classes load the DLL, so a check would either break the pure-Kotlin runs on Linux or never fire. A missing DLL already fails loudly, with JNA's `UnsatisfiedLinkError`. The trap #424 names is a **stale** DLL, and the input declaration closes that. *Builder's call.*

### #458 — one `pollUntil`, and messages a human can act on

1. **One shared helper** in a new `src/BlazorNative.Jni/src/androidTest/.../shell/Poll.kt`, beside `BootWait.kt`. It is measured to fit every caller: all 10 copies take `(ActivityScenario<MainActivity>, deadline, predicate)` and return `Boolean`, false on timeout, and only `BackAndroidTest` adds `sleepMs`. Each caller keeps its own deadline and its own sleep, which the plan reads off each copy. `BnModalDemoAndroidTest.pollUntilBackNavigatedAway` stays as it is, because it answers a different question; if it has a loop of its own, it calls the helper.
   - `pollUntil(scenario, deadlineMs, sleepMs = 250, predicate)`;
   - before each `onActivity`, it checks the scenario's state. If the Activity was destroyed, it fails with "the activity was DESTROYED while the test still expected it on screen", F19's message;
   - any other exception is rethrown.

   All 10 copies are deleted and their callers use the helper. `BackAndroidTest`'s `sleepMs` overload is kept as the parameter. Pin-standard Rule 8: consolidate, do not port.
2. **`BnGeolocationTests.swift:219`** gets F18's message shape: status 0 is OK, status 5 is Error, and it names the call that must produce Error.

## Tests

- **#454, the bound, red first.** The fixture's process logic is extracted into one internal method that takes the script, its arguments and a bound. A fact runs it against a stub `.ps1`, launched through `pwsh` as the real one is.
  - The stub starts a grandchild with `Start-Process`, a long `Start-Sleep` that inherits stdout, and then exits. That is the real failure's shape: the script is done, and a descendant holds its pipe.
  - The fact asserts that the run fails within the test's short bound, with the named message, and that no process from the tree is still alive afterwards.
  - **Anchor, in the same fact:** before the bound expires, the stub has exited and the grandchild is alive. That proves the pipe really is held, so the named failure is the bound's work.
  - `finally` kills any survivor, so nothing leaks into CI.
  - Red today: the current logic never returns. The red run is driven with the test's own timeout and recorded.
  - *Builder's call: the stub is `.ps1`, to match the fixture.*
- **#454, the script.** A drift fact asserts that every `dotnet publish`, `build` or `msbuild` call in `scripts/generate-reference.ps1` carries `-nodeReuse:false`, and that the script sets `MSBUILDDISABLENODEREUSE`. Its non-vacuity is a planted line.
- **#424.** A drift fact asserts that `build.gradle.kts` declares the publish output as a `Test` input, and that the missing-DLL check exists. Behaviour is checked once locally and recorded: touching the DLL makes the next `testDebugUnitTest` run, not UP-TO-DATE.
- **#458.**
  - The helper's DESTROYED message is pinned by an instrumented test that finishes the Activity and polls. It must fail with the DESTROYED message, which the test catches and asserts.
  - A drift fact asserts that no `fun pollUntil` remains under `androidTest` outside `Poll.kt`.
  - The Swift message is checked by its mutation reproducing the A7 red, now with the named message.
- **Mutations:**
  - the bound removed;
  - `-nodeReuse:false` removed;
  - the Gradle input removed;
  - a `pollUntil` copy reintroduced;
  - the DESTROYED check removed.
- **Lanes:** .NET, JVM, Android and iOS on the PR head, with `headSha` compared.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Node reuse is not the cause | Hangs continue | The bound makes each one a named failure, the 20-run soak measures it, and #454 stays open with the evidence if it recurs |
| `-nodeReuse:false` slows reference generation | A few seconds per run | Measured in the soak and recorded |
| Killing the process tree misses a re-parented MSBuild node | A stray node lingers after a failed run | With node reuse off none should exist. The failure message says so, and `dotnet build-server shutdown` clears one |
| The DLL check breaks pure-Kotlin JVM runs on Linux | The local dev loop breaks | The check skips when no JNA-loading test is selected, and is verified locally on Linux |
| Consolidating `pollUntil` changes a test's timing | A flaky device test | The helper keeps each caller's deadline and sleep. A full Android lane run on the PR head checks it |
