## Approach

### 1. The amendment to item 3

This goes into `docs/planning/MILESTONE.md`, as a sub-bullet below item 3's first bullet, in the re-audit PR:

> *Owner decision 2026-11-16:* a flake whose cause stays unproven after a phase spent hunting it (#407: 18.12, with #718 left open for a recurrence) meets this bullet with a fix that makes the failure name itself, plus a lane capture that would record the cause if it recurs. A residual the owner accepted after measuring it (#580, 18.12) counts as decided.

Item 3's paragraph about 18.11's grade stays, as history. A line is added after it that points to the amendment and to this re-audit.

### 2. Items 1 and 4–12

These are re-measured as 18.11 measured them.

- **Code changes.** `git diff --stat 09332c5e HEAD -- ':!docs' ':!*.md'` shows what changed outside the docs since 18.11 merged. On 2026-11-16 that was:
  - 18.12's capture scripts, `scripts/android-gradle-captured.sh` and `scripts/android-emulator-settle.sh`;
  - workflow edits;
  - the 0.22.1 release bump. In `Exports.cs` this changes only the `VersionNumber` string.

  The report shows the diff, then re-reads each of 18.11's code quotes on HEAD.
- **Item 1** must now show 18.1 to 18.12 complete, with 18.13 being this re-audit.
- **Every issue M18 closes** is checked for its state. #718 is open by design, and so is the amendment.
- **Item 12.** Re-check the 10 exports, the 80-byte struct, the C header and `wire-vocabulary.json`. The version string is not ABI.

### 3. Item 2

- **Evidence.** The re-audit PR's own lanes: `ci`, `android-instrumented`, `ios` and `baseline-checks`.
  - Each run's `headSha` is compared against the PR head, and each run must be attempt 1.
  - One local .NET run on both TFMs is added to that.
- **Baselines.** Expected counts are .NET 2828, JVM 210, Android 273 and iOS 307. 18.12 changed no test.

### 4. Item 3

1. Apply the amendment of §1 first, then grade each flake against the amended text.
2. Copy 18.11 §3a forward, with a row update for #407 (the 18.12 outcome and the capture) and #453 (#580 accepted).
3. Re-check §3b, that no bound was raised, over `09332c5e..HEAD`.
4. Grep the PR's own runs for every signature, as in §3c, including the #407 signature in the `android-instrumented` log. Confirm that the capture's artifact was uploaded.

**The best possible grade is MET NARROWLY.** The narrowings to name are:
- #407's cause is unproven, and #718 is open;
- #453 holds only through the accepted #580;
- the evidence is one sample per lane.

### 5. Item 13

1. **Population.** The 108 pins and 339 sites of the 18.11 record. The population is re-derived from git, and the re-check confirms that no M18 squash after `09332c5e` adds a test.
2. **Freshness.** Run `git diff --stat <red-commit> HEAD -- <test> <subject>` for every site. If it is empty, the red is still fresh. If it is not empty, the site is re-run to its own assertion, and the message is quoted.
3. **Sample.** Re-run a small independent sample of reds, one per lane that can run here. The JVM sample needs a draft PR (#491). The device lanes need scratch refs.
4. **The 18.11 narrowing.** Three register rows were written in 18.11, not in the phase that added them. The owner accepted this on intent on 2026-11-15, so the item stays MET NARROWLY, citing that decision.

### 6. Carried debt

Each of these is listed, not graded: #718, #716, #717, #711, #575, #603, #621, #600, #593 and #582. #562 is deferred to a later testing milestone.

### 7. Verdict

- **PASS or PASS WITH FINDINGS:** record the Audit History row, then run `complete-milestone` as its own PR, with no tag.
- **FAIL:** stop and ask the owner.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The amendment reads as a loosening that hides an unfixed flake | A future reader takes item 3 as fully met | Grade it no higher than MET NARROWLY, name #718 and #580 in the grade, and keep 18.11's NOT MET text as history |
| A "fresh" claim is wrong because a subject file moved | A stale red is graded as fresh | Diff each site's own test and subject, never a directory, and re-run a sample of reds |
| A lane hits a known flake (#602, #551, #564) | Item 2 or 3 is graded on a re-run | Diagnose the hit against its signature and re-run the job once. The item then becomes MET NARROWLY, citing the issue, as 17.12 did |
| The capture's sampler shifts install timing on the main lane, per the 18.12 record §4 | #407 could become rarer or more frequent with no sign of the change | This is noted in the report as a known limit of the capture. It does not affect the grade |
