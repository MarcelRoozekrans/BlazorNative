# Phase 15.0 Design — `The pin standard`

**Date:** 2026-09-22
**Phase:** `15.0`
**Surface:** `Mixed`
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [M15 — A Standard for Pins](../../planning/MILESTONE.md)

## Goal

Make the pin population **exactly enumerable**, write down what a pin must do to be trusted, and
measure every pin against that standard — replacing the milestone's opening guess with a per-pin
verdict.

## What changed before this phase started

M15 opened claiming **sixteen** pins. That counted one test project. Correcting it surfaced the
real problem, which is not the number:

- **19** `*DriftTests` across three projects
- plus `LayoutSurfacePinTests`, `PackageVersionPinTests`, `ReleaseWorkflowPinTests`,
  `DefaultStructTrapSweepTests`, `AnalyzerDiagnosticRosterTests` — same job, four different suffixes

**The population is not enumerable by name.** A convention test reflecting over `*DriftTests` —
the obvious implementation of the milestone's enforcement criterion — would **silently miss a
quarter of the pins**. That is this milestone's own bug class, inside the mechanism meant to close
it.

## The finding this phase is built on

A pin is not defined by its name but by what it **does**: it reads the repo tree at runtime and
asserts on its contents, coupling to the tree rather than to behaviour.

That definition is mechanically detectable, and measuring it found something better than a
definition:

> **`RepoRoot()` is defined 23 times.** Copy-pasted into 23 separate test files, called by 25.

Two consequences:

1. **The behavioural population is ~25**, and it includes three tests nobody named like pins —
   `WireVocabularyCodegenTests`, `PackagePurityTests`, `GeneratedSymbolShadowTests`. They byte-compare
   generated copies and inspect package contents; they are pins by every property that matters.
2. **`RepoRoot()` is itself a twin divergence** — 23 copies of one truth, unpinned, in the repo
   whose previous milestone was about exactly that.

**Stated precisely, because overclaiming here would be this milestone's own failure:** all 23 copies
currently use the same sentinel, `BlazorNative.sln`, and the same shape. **They have not drifted.**
What exists is a **latent** divergence — the precondition for the class, not an instance of it.
#339 was copies-agreeing right up until one was not.

## Approach

**1 — Consolidate `RepoRoot()` into one shared helper.** This single change does three jobs, which
is why it leads:

- **removes the latent divergence** — 23 copies become one
- **makes the population exactly enumerable** — reflection over callers of the shared helper
  enumerates pins with no suffix guessing
- **gives enforcement a hook** — the helper is where the standard can attach

**The fix for the divergence is the mechanism for enforcement.** That is a strictly better shape
than a convention test keyed on `*DriftTests`, which is already known to miss a quarter of the
population.

**Fallback, pre-agreed:** if consolidation proves risky across three test projects, pin the 23
copies against each other instead. Cheaper, preserves the enumeration key, and is honest about what
it does not fix.

**2 — Write the standard, in the repo.** Not in a milestone doc — those get archived. At minimum a
pin must:

- **fail when it scans nothing.** Vacuity is about the *assertion shape*, not the input: *for every
  X, assert Y* passes trivially when there are no X, whether X came from a regex, a directory walk,
  or a collection. `RouteMenuDriftTests` scans no files and has the shape.
- **fail when its subject moves** — a renamed file, a restructured manifest, a regex whose anchor
  disappears.
- **state what it does not cover**, as a written limit rather than leaving a reader to infer
  completeness.

**3 — Census every pin against it**, recording *conforms*, *fixed*, or *exempt with a written
reason*. **An unassessed pin is a gap; "exempt" is a fine outcome, silence is not.**

**4 — Answer whether enforcement can be mechanical.** A Roslyn analyzer over test methods, a
reflection-based convention test over the helper's callers, or nothing cheap enough. **A negative
answer reshapes 15.1 rather than failing it**, and must be recorded with its evidence.

## Files / Modules Touched

- `tests/**/` — 23 files lose their local `RepoRoot()`; one gains the shared one. Exact list from
  the census.
- A new shared test helper — location to be decided by where the three test projects can all
  reference it without a new package dependency.
- `docs/` — the written standard.
- `.github/workflows/ci.yml`, `README.md` — counts, if the census adds a test.

## Tests

- **The consolidation is proven by the suite passing unchanged** — 1111 before and after, with no
  test skipped. A pin that silently stopped finding the repo root would still pass if it were
  vacuous, which is precisely why the census must be measured rather than inferred from green.
- **The enumeration is proven by mutation:** add a new test that reads the repo tree without going
  through the shared helper, and confirm the enumeration notices. If it cannot, the enumeration key
  is weaker than claimed and that is a finding for 15.1.
- **Any new assertion is mutation-proven against its own branches**, not just its subject — the
  M14 lesson that cost five review rounds.

## Open Questions

- **Where does a shared test helper live** so all three test projects can use it without a new
  package? A linked source file, a shared test-utility project, or `Directory.Build.props`
  trickery. Cheapest option that does not add a dependency wins.
- **Is `BnSafeAreaCoverageTests` a pin?** It reads the tree, but its subject is coverage rather
  than agreement between copies. The census must draw this line explicitly rather than leave it to
  each reader.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Consolidating across three test projects needs a shared assembly that does not exist | The phase stalls on packaging rather than on pins | The pre-agreed fallback: pin the 23 copies against each other instead. Take it early rather than fighting |
| The census concludes every pin conforms | The milestone documents the status quo and the sixth review finds a seventh shape | The census is **measured per pin**, and the heuristic already says otherwise. A clean result is a finding to challenge, not to celebrate |
| The definition of "pin" over-captures | Ordinary tests get held to a standard written for guards | The census draws the line case by case and records the reasoning, so the boundary is reviewable rather than asserted |
| `RepoRoot()` consolidation changes behaviour subtly — a different sentinel, a different walk | Pins silently stop finding their subject and pass vacuously | All 23 copies were verified identical before consolidation, so there is one behaviour to preserve, not 23 to reconcile |
