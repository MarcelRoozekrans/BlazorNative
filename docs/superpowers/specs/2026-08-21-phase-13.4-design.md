## 1. One bug class, and the honest caveat

Four of the six issues are **the same defect wearing four costumes**: *two copies of one truth, one
of them unpinned.* That is the shape of the visual-style hole (#263/#266) and of the wire-vocabulary
drift (#262), and the repo already has a doctrine for it, stated in `ShellStyleTableDriftTests`:

> *"#255 made the divergence unrepresentable instead."*

The doctrine ranks the answers: **generate** beats **pin**, and pinning "could only ever catch
divergence AFTER somebody wrote it".

**The honest caveat, stated once so nothing downstream pretends otherwise: one class does not mean
one fix.** The copies live in three different places, and each admits a different mechanism.
A single universal guard would be the tidy lie:

| Instance | Where the twin lives | Mechanism | Doctrine rank |
|---|---|---|---|
| **#279** | A Swift literal shadowing a generated symbol | Consume the generated value; pin that no generated symbol is shadowed | generate |
| **#278 / #282** | Kotlin ↔ Swift parser **logic** | Generated shared test vectors — specify once, three suites assert | generate (the table, not the parser) |
| **#280** | .NET harness ↔ .NET encoder | Reference rather than copy — run the real `FrameEncoder` as a gate | unrepresentable |

## 2. #279 — the generated symbol that lost to a hand-written twin

### Measured, not summarised

`BnWidgetMapper.swift:534` declares `private static let measuredNodeTypes: Set<String>` as a
literal, and `:2196` uses it to decide which node types get a Yoga measure func. The **generated**
`BnWireVocabulary.measuredNodeTypes` (`BnWireVocabulary.g.swift:27`) has **zero qualified
references** in the Apple tree. All four occurrences of the name resolve to the hand-written copy.

The Kotlin shell does it correctly: `YogaLayout.kt:1328` consumes
`BnWireVocabulary.MEASURED_NODE_TYPES`.

`WireVocabularyCodegenTests` cannot catch this: it re-emits and byte-compares the *generated* files
against the manifest, and never looks at a hand-written literal. The literal is `private static`, so
no Swift test can reach it either.

### The refined diagnosis — dead is common, dead-**and-shadowed** is the defect

Surveying every generated shell symbol:

| Symbol | Consumed? | Hand-written twin? |
|---|---|---|
| `nodeTypes` (Swift) | ✅ `BnFrameAdapter.swift:115` | — |
| **`measuredNodeTypes` (Swift)** | ❌ | ⚠️ **yes**, and it wins every use |
| `visualStyles`, `scrollIgnoredContainerStyles` (Swift), `kNodeTypes` (ObjC++) | ❌ | no |

Three generated symbols are dead and **harmless** — nothing competes with them. One is dead and
**shadowed**, and that is the whole defect. #279 said it in a sentence worth keeping: *"a dead
generated symbol next to a live hand twin is the shape to watch."*

A blunt guard ("every generated symbol must be referenced") would red on four symbols and force
three pointless consumptions. The precise guard is narrower and stronger.

### Fix and guard

1. `BnWidgetMapper.swift` consumes the generated set:
   `private static let measuredNodeTypes = Set(BnWireVocabulary.measuredNodeTypes)`.
2. **New pin: no generated symbol may be shadowed by a hand-written definition of the same name**,
   in either shell tree. This is a source scan from the .NET suite — the one lane that sees both
   shells — in the established `ShellStyleTableDriftTests` style.
3. **Second pin, weaker and advisory: every generated symbol is referenced, or is on an allowlist
   carrying a written reason.** The three harmless dead symbols go on it with their reasons. An
   allowlist that must be *edited* to add a dead symbol is the point: it makes the next one a
   decision rather than an accident.

Pin 2 is the one that closes the class. Pin 3 catches the precursor state.

## 3. #278 / #282 — deep links: generate the table, not the parser

### The divergence, and which side is right

| | Parser | `blazornative://settings` | `blazornative://settings/audio` |
|---|---|---|---|
| **iOS** | `BnDeepLink.route(from:)` — host + path, trailing slash trimmed | `/settings` | `/settings/audio` |
| **Android** | `MainActivity.parseDeepLinkRoute` — `return "/$host"` | `/settings` | **`/settings`** ← drops `/audio` |

**iOS is correct.** Android's parser is three lines and discards `data.path` entirely.

**The bug is latent.** Every route declared today is single-segment (`/settings`, `/layout`,
`/scroll`, `/image`), so the two agree. It surfaces on the first nested route — which is exactly the
condition #279 has too, and exactly why neither was caught.

### #282 is a distinct code path

Cold launch: Android constructs the bridge with `initialRoute = deepLinkRoute ?: "/"`, so .NET's
router reflects the link **regardless** of any component map. iOS (`HostViewController.swift:84`)
resolves through the stashed component map and **drops routes it cannot map**. Same feature, second
divergence, opposite shell in the wrong.

### The mechanism

**You cannot generate a parser from a manifest. You can generate the table it must satisfy.**

New `src/deeplink-vectors.json`, beside `src/wire-vocabulary.json`. `tools/BlazorNative.WireGen`
emits three test tables from it — Kotlin, Swift, .NET. A case is written **once**; all three suites
assert it.

Vectors must include, at minimum:

| Input | Expected route | Why it is in the table |
|---|---|---|
| `blazornative://settings` | `/settings` | the common case; both agree today |
| `blazornative://settings/audio` | `/settings/audio` | **the live divergence** (#278) |
| `blazornative://settings/audio/input` | `/settings/audio/input` | more than one extra segment |
| `blazornative://about/` | `/about` | trailing-slash trim — iOS documents it, Android never did |
| `blazornative://` | `/` | degenerate host |
| `https://example.com/settings` | *(no route)* | wrong scheme is rejected, not coerced |
| an unmapped route, cold launch | route still seeds .NET | **#282** — the map must not gate the seed |

The last row is the cold-launch seed and belongs in the same table: it is the same question ("what
route does this URL produce") asked at a different moment.

## 4. #280 / #281 — the harness

### #280 — run the real encoder as a gate

`FrameEncoder.MapNodeType` (`FrameEncoder.cs:158`) **throws** `Unknown node type '…'` on anything
outside its map. That throw is the C-ABI gate every on-device frame passes.
`BnTestTree.Apply` (`BnTestTree.cs:204`) does `new BnTestNode(p.NodeId, p.NodeType)` and accepts
**any string**.

So a component emitting an unmapped node type gives a **green harness test** and a frame that
**aborts rc 2 on device**. `StrictErrors = true` cannot catch it — the throw lives in the
`FrameSink` the harness never installs.

**Fix:** `BnTestHost` runs every frame it receives through the real `FrameEncoder` and **discards
the bytes**. The encode exists solely so it throws where the device throws. This closes the entire
encode gate rather than the reported node-type case, and it is a *reference* to the production
encoder, not a copy of its rules — divergence becomes unrepresentable in-language.

### #280 sub-case — `TextBearing` is a third twin

`BnTestTree.TextBearing = {text, button, input}` (`:114`) matches **iOS's** collapse predicate. It
does **not** match Android's, which is broader — `TextView && !ViewGroup`, so `CheckBox` and
`Switch` are text-bearing there.

**The harness currently encodes one shell's rule as the contract**, which is the same defect this
phase exists to close, one layer up.

**Fix:** `TextBearing` stops being a constant. The harness models both predicates and **names which
shell it is projecting**. A consumer asserting `node.Text` gets an answer that is true of a stated
platform rather than true of iOS and silently wrong on Android.

This is a **public API change** to `BlazorNative.Testing` (0.10.0). It is pre-1.0 and the package is
a dev-time-only dependency taken from a test project, so the break is cheap — but it is a break, and
it needs a migration note like 13.1's.

### #281 — the leak

`BnTestHost.cs:79–103` builds a `ServiceProvider`, resolves the renderer, subscribes
`renderer.Frames += host.OnFrame`, then calls `renderer.Mount<TComponent>(view)` with **nothing
guarded**. If the mount throws — the path the harness sets `StrictErrors = true` specifically to
produce — the provider and renderer leak.

**Fix:** `try`/`catch` around the construction, disposing what was built before rethrowing. Pinned by
a test that mounts a throwing component and asserts the provider is disposed.

## 5. Scope boundary

**13.4 closes the class. It is not "fix everything the 0.10.0 review found."**

#283's grouped low-severity items ride along **only where they touch a file this phase already
opens**. Anything else splits out into its own issue rather than widening the phase. The precedent
is 13.1, where a late in-scope addition (`BnModal`) was taken because the DoD would otherwise have
been false, and unrelated items were not.

## 6. Definition of done

- [ ] `BnWidgetMapper.swift` consumes `BnWireVocabulary.measuredNodeTypes`.
- [ ] **A generated symbol shadowed by a hand-written definition of the same name reds** — pinned,
      and **mutation-proven** by re-introducing the literal.
- [ ] Every generated symbol is referenced or allowlisted with a written reason.
- [ ] `src/deeplink-vectors.json` exists; WireGen emits Kotlin, Swift and .NET test tables from it;
      the three emitted copies are **byte-compared**, as `WireVocabularyCodegenTests` does.
- [ ] Android's parser keeps path segments; both shells satisfy every vector.
- [ ] iOS cold launch seeds .NET's route for an **unmapped** route (#282).
- [ ] `BnTestHost` runs the real `FrameEncoder` over every frame; an unmapped node type **fails the
      harness**, pinned by a test that would have passed before.
- [ ] `BnTestTree`'s text-collapse names the shell it projects; both predicates are modelled.
- [ ] `BnTestHost.Mount` disposes on a throwing mount, pinned.
- [ ] Migration note for the `BlazorNative.Testing` break.
- [ ] Both device lanes dispatched and green, with no frame-table file in the diff.

## 7. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| **"One class" is read as "one fix"** and a universal guard is attempted | Either a guard so blunt it needs constant allowlisting, or three real mechanisms collapsed into one that closes none properly | §1 states the caveat and the table assigns a mechanism per instance |
| **The shadowing pin is written to pass rather than to bite** | The class stays open behind a green tick — the exact failure 13.1 found twice | Mutation-proof it by re-introducing the `BnWidgetMapper` literal and observing the red |
| **Vector table grows into a route-grammar spec** | Phase slips on a design nobody asked for | The table holds URL→route pairs and nothing else. Parameterised routes are explicitly out — no route uses them |
| **The `BlazorNative.Testing` break lands unannounced** | A consumer's test project breaks on upgrade with no explanation | Migration note, and the package is dev-time-only and pre-1.0 |
| **Fixing Android's parser changes an app's live behaviour** | A deep link that resolved to `/settings` now resolves to `/settings/audio` and misses the table | True and intended — it was a silent miss before. Called out in the migration note; no shipped route is multi-segment, so no shipped app is affected |

## 8. Out of scope

- **Parameterised routes** (`/product/{id}`). Not supported today; RouteGen parses
  `BlazorNativePage.Routed<T>()` calls into an exact-string table. Adding them is a separate feature.
- **Making the harness drive the shells.** #280's stronger reading — run the actual Kotlin/Swift
  mappers — is a device-lane concern, not a unit-test one. The encoder gate is the boundary that
  admits a cheap, exact answer.
- **#284, #285, #291.** Capabilities and an open-ended audit; unscheduled M14 candidates.
