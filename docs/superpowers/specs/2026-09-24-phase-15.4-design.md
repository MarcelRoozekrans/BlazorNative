# Phase 15.4 Design — `The missing guards`

**Date:** 2026-09-24
**Phase:** `15.4`
**Surface:** `Mixed`
**Stage:** phase (one phase, implementation-ready)

**Milestone:** [M15 — A Standard for Pins](../../planning/MILESTONE.md)
**Standard:** [`docs/pin-standard.md`](../../pin-standard.md)
**Issues:** **#375** (population key + a vacuous-capable pin) · **#297** (RenderPatch ↔ patch-kind
switch unpinned) · **#302** (release-please silently dropped a breaking commit)

## Goal

Decide the pin population key and give the one pin it cannot see a floor, then build the two guards
that do not exist: a pin from every `RenderPatch` subclass to the encoder, the enum and both shells'
patch-kind arms; and a pre-merge check that every commit message survives release-please's own
parser.

## What scoping measured (2026-09-24, on `origin/main` at `2b59541`)

1. **#302's cause is reproduced, and it is not the `!` marker.** Parsing `cf8e956`'s real message
   with release-please's own `parseConventionalCommits` at **17.6.0**, the version
   `release-please-action@45996ed` (v5.0.0) bundles, per its `package-lock.json`, yields **0
   commits**. The underlying `@conventional-commits/parser` 0.4.1 throws `unexpected token '(' at
   352:28, valid tokens [)]`. The line is `` `Width="@(Width is { } w ? (BnAutoLength?)w :
   null)"` ``. The three comparison commits in #302's table all parse. The breaking marker only
   made the loss visible.
2. **The loss is per chunk, which is why it looked random.** release-please's `splitMessages` splits
   a body wherever a blank line is followed by a paragraph beginning `feat|fix|…(scope)?: `. It then
   parses each chunk separately and **silently drops a chunk that throws**. The logger reports it at
   `debug` level only. `cf8e956`'s bad line sat in the **first** chunk, so the headline vanished.
3. **Across all 210 commits on `main` since `bootstrap-sha`, the parser rejects exactly two.**
   - `cf8e956` lost its headline. It was restored by hand in `CHANGELOG.md` on 2026-08-22.
   - `6ec3894` lost a **later chunk**, so its headline `fix` rendered in 0.6.0, but something
     after it did not. What was lost is not yet known.
4. **The trigger is narrower than "a nested parenthesis".** `e345bca` (`InvokeAsync(() =>
   Dispose())`) and `f7aa1b7` (`Tests (new file, [Collection("host-session")]`) both contain nested
   parentheses and parse. The throwing shape is a `(` attached to a preceding token, read as a
   `type(scope)` group, with a second `(` inside it before it closes. A guard that restates the
   grammar as a regex would get this wrong in both directions, so **the guard runs the real
   parser.**
5. **Patch kinds are bare integers in three languages, and nothing relates them.** There are nine
   non-abstract `RenderPatch` records in `src/BlazorNative.Renderer/PatchProtocol.cs`.
   `FrameEncoder.Encode` has nine `case` arms and a throwing `default:`. `BlazorNativePatchKind`
   declares ten values, one of them `AppendChild = 2 /* reserved-dormant */`. Kotlin
   `NativeFrameAdapter.kt`'s `when (kind)` has arms `1, 3–10`, and Swift `BnFrameAdapter.swift` has
   `case 1, 3–10`. `wire-vocabulary.json` does not carry patch kinds. The plan re-measures the
   record count, because a record that is not live, like `AppendChildPatch`'s deleted
   predecessor, must be accounted for rather than assumed.
6. **`RouteMenuDriftTests` is vacuous-capable per fact, but not per file.** Each of its two
   comparison facts passes over an empty collection. The file as a whole is not vacuous:
   `TheTwoExemptions_AreStillWhatTheyClaimToBe` reds on an empty page list, and an empty menu
   against a non-empty page list reds the coverage fact. The floor is still a real fix, because
   Rule 2 is per fact. #375's framing overstates the exposure, and the record says so.
7. **The existing required `footer-check` job already reads PR commit bodies** and carries a
   self-test in `commitlint.yml`. The repo squash-merges with `PR_TITLE` + `COMMIT_MESSAGES`.

## Decisions (owner, 2026-09-24)

1. **Population key: a hand-kept register.** Rule 6's mechanical population stays *tree-readers*.
   Pins that compare in-memory collections are listed by hand in a register beside Rule 6, and
   Rule 6 says so. A `[Pin]` marker attribute was rejected: it is declared rather than derived, the
   pattern M15 has rejected four times. The cost is accepted and written into the rule: the
   register grows only when someone remembers to add to it.
2. **#297 includes both shells, through a differential pin.** This is not codegen.
   Generating the constants would still leave hand-written arms, it touches a frozen NOT-API enum,
   and it is phase-sized on its own.
3. **#302's guard is a pre-merge PR check.** It is not a release-PR check and not a checklist step.

## Approach

### A. The population key and #375 (Docs + one test)

`docs/pin-standard.md` Rule 6 gains one paragraph. Its population is **tree-readers, by
construction**. Pins over in-memory collections exist, cannot be enumerated by the key, and are
listed in a **register** directly under Rule 6. The register has one row per pin:

- the file;
- what it compares;
- its verdict against Rules 2–5 and 7.

The first row is `RouteMenuDriftTests`. The census §9 decision block records the decision, dated
and attributed, together with the stated cost. The rule text moves in this phase, not in 15.5:
leaving Rule 6 contradicted by a decision just taken would be an unpinned claim.

`RouteMenuDriftTests` gains a per-fact floor. Each comparison fact asserts that its input
collections are non-empty **before** comparing, with a message naming the collection. This is
proven by mutation: empty `BnDemo.Destinations` and `EveryMenuRow_PointsAtARoutedPage` reds on its
own floor. Today only a sibling fact catches that.

### B. #297 — `PatchKindDriftTests` (Backend)

This is a new tree-reading pin through `BnRepo.Root()`. It has four facts. Every one is derived from
a real gate; none restates a list.

1. **Every `RenderPatch` subclass encodes.**
   - Reflection enumerates every non-abstract `RenderPatch` subclass in `BlazorNative.Renderer`.
   - Each is instantiated through its primary constructor, with default arguments.
   - Each instance is passed through the real `FrameEncoder.Encode`.
   - A throw names the subclass and the obligation.
   - **Floor:** the enumeration yields at least the measured count, so a scan that finds nothing reds.
2. **Kinds are exactly the enum, both ways.**
   - Each encoded `Kind` is a declared `BlazorNativePatchKind` value.
   - No two subclasses share a kind.
   - Every enum value is produced by some subclass, except `AppendChild`. It is asserted to be
     **produced by none**, so if it is revived, the exemption reds.
3. **Kotlin arms equal the live kinds.** The pin extracts the integer arms of the anchored
   `when (kind)` block in `NativeFrameAdapter.kt`, not every `when` in the file. The set must equal
   the live-kind set exactly: no missing arm, no stale arm.
4. **Swift arms equal the live kinds.** The same check runs on `BnFrameAdapter.swift`'s patch
   `switch`, anchored the same way.

The pin meets the standard:

- **floors** on every extracted set;
- a **positive control** that plants a removed arm into the real Kotlin text and drives it through
  the pin's own detector;
- a **Rule 5 "does not cover" list**:
  - arm *bodies* are not checked, only that arms exist;
  - the reserved id's semantics are out of scope;
  - the template's copy of `NativeFrameAdapter.kt` is not read, and the plan must establish
    whether an existing template pin byte-compares it;
- a **Rule 7 mutation table**. It must at least remove a Kotlin arm, add a stale Swift arm, add a
  subclass with no `case`, map two subclasses to one kind, delete the floor for the vacuity
  contrast, and add a commented-out arm as a negative.

### C. #302 — the parse guard (Infra)

`tools/commit-parse-check/` is a small Node script. It depends on **`release-please` at exactly
17.6.0**, and a committed lockfile pins it. The script:

1. parses each of the PR's commits individually;
2. parses the squash message a merge would produce: the PR title, followed by the commit
   messages, per the repo's `COMMIT_MESSAGES` setting;
3. calls release-please's own `parseConventionalCommits` with a logger that records every
   `commit could not be parsed` event;
4. **fails on any recorded event**, naming the commit SHA, the line and the column.

This catches lost headlines (`cf8e956`) and lost later chunks (`6ec3894`) for every commit type,
not only `!`.

The script runs as a **new step in the existing required `footer-check` job**, so branch protection
does not change. It carries a self-test in `footer-check`'s style, run before the real check:

| Input | Expected |
|---|---|
| `cf8e956`'s real message | **red** — lost headline |
| `6ec3894`'s real message | **red** — lost chunk |
| `e345bca`'s real message | **green** — nested parentheses that parse, the over-match guard |
| one clean message | **green** |

A self-test that cannot red proves nothing, so the first two rows are required.

**The version claim is pinned.** "The same parser the action runs" would otherwise be a comment.
`tools/commit-parse-check/action-version.json` records one entry, `{ "actionSha": "45996ed…",
"releasePlease": "17.6.0" }`, measured from the action's lockfile. A .NET test enforces it:

- it reads the action SHA from `release-please.yml` and asserts that it equals `actionSha`;
- it asserts that the script's locked `release-please` version equals `releasePlease`.

When Renovate bumps the action, the test reds until someone re-measures. Writing a new `actionSha`
without re-measuring is still possible, and the Rule 5 list says so.

**History.** The plan determines what `6ec3894`'s dropped chunk was. If it was a user-facing
`feat` or `fix`, it is restored in `CHANGELOG.md` under 0.6.0 with an "added by hand" note like the
0.12.0 one. If not, the finding is recorded on #302 and nothing is added.

**Closing #302.**

- *Cause established:* point 1 above, reproduced and recorded on the issue.
- *Mechanical check:* the guard.
- *0.12.0 restored:* already done.

## Tests

- **Unit (.NET):**
  - `PatchKindDriftTests`: 4 facts plus a positive control;
  - `RouteMenuDriftTests`: per-fact floors, no new facts;
  - the action-version pin.
  - The .NET count moves by the measured delta.
- **Self-test (CI):** the four-row table in §C, run inside `footer-check` before the real check.
- **Mutation (Rule 7):** tables for `PatchKindDriftTests`, for the `RouteMenuDriftTests` floors,
  and for the action-version pin. They are run one at a time, reverted, and recorded for the PR.
- **Live proof that the guard reds:** on the phase branch, one throwaway commit whose body carries
  `cf8e956`'s bad line. Observe `footer-check` red on that commit's exact `headSha`, then drop the
  commit before review. It is the same red-before-green discipline 15.3 used.
- **Regression:** the full .NET suite, JVM 162, and iOS and Android instrumented unchanged, because
  no shell code moves.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A `RenderPatch` subclass cannot encode from default arguments, for example a null string rejected | Fact 1 fails for a reason unrelated to the switch | Per-type argument overrides are allowed. The reflection enumeration and the floor stay the source of truth, so an override cannot hide a new subclass; a subclass without one still gets default arguments. |
| The Kotlin or Swift arm extractor over-matches another `when`/`switch` | The pin passes while reading the wrong block | Anchor to the block that switches on the patch-kind read, plus a positive control through the same detector and a stale-arm mutation |
| The squash message the script reconstructs differs from GitHub's | The guard passes a message GitHub would render differently | It parses each commit individually as well, and a parse failure is line-local, so a bad line in any commit fails in either form. Measured by the throwaway-commit live proof. |
| `npm ci` in `footer-check` adds network, time and a supply-chain surface | A slower, flakier required job | An exact lockfile, one dependency tree, no install scripts, and a cache keyed on the lockfile only, never with a `restore-keys` fallback (see the M14 lesson on cache fallbacks masking a gate) |
| A Renovate bump updates `actionSha` without re-measuring | The version pin passes while the parser drifts | Stated in the pin's Rule 5 list. The pin guarantees that a bump is *noticed*, not that it is re-measured correctly. |
| The register is forgotten | A new in-memory pin is invisible again | Accepted by decision 1 and stated in Rule 6 itself. It is disclosed, not hidden. |
